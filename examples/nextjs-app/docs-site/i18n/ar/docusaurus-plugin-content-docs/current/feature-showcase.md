توجد هذه الصفحة لتوضيح كيفية تعامل `ai-i18n-tools` مع كل بنية شائعة في Markdown. قم بتشغيل `sync` ضدها وقارن المخرجات في كل مجلد لغة لمعرفة بدقة ما يتم ترجمته وما يظل دون تغيير.

---

## نص عادي {#plain-text}

التجنيس الدولي أكثر من مجرد استبدال الكلمات. يجب أن تحافظ خطوة الترجمة الجيدة على هيكل المستند، وتُبقي المعرفات التقنية كما هي، وترسل فقط النصوص القابلة للقراءة من قبل البشر إلى نموذج اللغة.

يقوم `ai-i18n-tools` بتقسيم كل مستند إلى **مُقطعات** قبل إرسالها إلى نموذج اللغة الكبير (LLM). يتم ترجمة كل مقطع بشكل مستقل ثم إعادة تجميعه، لذلك لا يؤدي تغيير فقرة واحدة إلى إبطال الترجمات المخزنة مؤقتًا لبقية الملف.

---

## تنسيق النصوص {#text-formatting}

يجب أن يقوم المترجم بنقل كل التنسيقات المضمنة دون تغيير التنسيق:

- **النص الغامق** يشير إلى الأهمية ويجب أن يظل غامقًا بعد الترجمة.
- _النص المائل_ يستخدم للتأكيد أو العناوين؛ ويجب الحفاظ على المعنى.
- ~~النص المشطوب~~ يُشير إلى المحتوى المُهمل أو المحذوف.
- `inline code` لا يُترجم **أبدًا** — يجب أن تظل المعرفات وأسماء الدوال ومسارات الملفات كما هي.
- يحتفظ [رابط تشعبي](https://github.com/wsj-br/ai-i18n-tools) بعنوان URL الأصلي؛ فقط تُرجم تسمية الرابط.

## الجداول {#tables}

تُعد الجداول مصدرًا شائعًا لأخطاء الترجمة. يتم ترجمة كل خلية بشكل منفصل؛ ويتم الحفاظ على فواصل الأعمدة وبناء الجملة الخاص بالمحاذاة.

| الميزة                  | الحالة         | الملاحظات                                                      |
|------------------------|----------------|------------------------------------------------------------------|
| ترجمة Markdown        | ✅ مستقرة       | يتم تخزين المقاطع مؤقتًا في SQLite                              |
| استخراج سلاسل الواجهة | ✅ مستقر | يقرأ استدعاءات `t("…")` |
| سلاسل واجهة المستخدم بصيغة الجمع | ✅ مستقرة       | `t("…", { plurals: true, count })`; بادئات المجلّة + صيغ JSON المسطحة |
| ترجمة تسمية JSON | ✅ مستقر | شريط جانبي/شريط تنقّل Docusaurus بتنسيق JSON |
| ترجمة نص SVG | ✅ مستقر | يحافظ على هيكل SVG |
| تطبيق المفردات | ✅ مستقر | ملف مفردات CSV لكل مشروع |
| التزامن الدفعي | ✅ قابل للتكوين | المفتاح `batchConcurrency` |

### دعم الكتابة من اليسار إلى اليمين ومن اليمين إلى اليسار {#left-to-right-and-right-to-left-support}

يجب أن تدعم الترجمة الحديثة اللغات المكتوبة من اليسار إلى اليمين (LTR) ومن اليمين إلى اليسار (RTL). ويضمن `ai-i18n-tools` التعامل الصحيح مع اتجاه النص طوال عملية الترجمة:

- يحافظ الخط الإنتاجي تلقائيًا على اتجاه كل لغة محلية. على سبيل المثال، يتم عرض اللغة العربية (`ar`) من اليمين إلى اليسار، بينما تبقى الإنجليزية (`en-GB`)، والبرتغالية (`pt`)، وغيرها من اليسار إلى اليمين.
- عند ترجمة جداول Markdown، أو عينات الأكواد، أو سلاسل واجهة المستخدم، تحافظ الأدوات على المحاذاة وهيكل المحتوى، بحيث تُعرض الجداول والكتل المنسقة بشكل طبيعي في السياقات المكتوبة من اليسار إلى اليمين ومن اليمين إلى اليسار.
- كلا من Docusaurus وتطبيق Next.js النموذجي يحترمان اتجاه اللغة في المتصفح، ويقومان بتبديل التخطيط ومحاذاة النص حسب الحاجة.

| اتجاه النص | مثال على اللغة         | العرض                  |
|:--------------:|:-----------------------|:-----------------------|
|      LTR       | `en-GB`, `es`, `pt-BR` | اتجاه قياسي من اليسار إلى اليمين |
|      RTL       | `ar`, `fa`, `he`       | تخطيط من اليمين إلى اليسار   |

وهذا يضمن أن تظهر المستندات والواجهات بشكل صحيح، بغض النظر عن لغة المستخدم أو اتجاه القراءة.

## القوائم {#lists}

### غير مرتبة {#unordered}

- يقوم ذاكرة الترجمة بتخزين تجزئة (hash) لكل جزء مصدر.
- فقط الأجزاء التي تغير تجزئتها منذ التشغيل السابق تُرسل إلى نموذج اللغة الكبير (LLM).
- هذا يجعل التشغيل التدريجي سريعًا جدًا — عادةً تتطلب التعديلات الصغيرة بضع استدعاءات واجهة برمجة تطبيقات فقط.

### مرتبة {#ordered}

1. أضف `ai-i18n-tools` كاعتماد تطوير (dev dependency).
2. أنشئ `ai-i18n-tools.config.json` في الجذر الرئيسي لمشروعك.
3. شغّل `npx ai-i18n-tools sync` لإجراء الترجمة الكاملة الأولى.
4. أرسل ملفات اللغة المُنشأة مع ملفات المصدر الأصلية.
5. في التشغيلات اللاحقة، تُعاد ترجمة الأجزاء التي تغيرت فقط.

### متداخلة {#nested}

- **خط أنابيب المستندات**
  - المصدر: أي ملف `.md` أو `.mdx`
  - المخرجات: هيكل `i18n/` لـ Docusaurus أو نسخ مترجمة مسطحة
  - ذاكرة التخزين المؤقت: SQLite، مفتاحها مسار الملف + تجزئة الجزء
- **خط إنتاج سلاسل واجهة المستخدم**
  - المصدر: ملفات JS/TS تحتوي على استدعاءات `t("…")` (بما في ذلك صيغ الجمع عبر `{ plurals: true, count }`)
  - المخرجات: ملفات JSON مسطحة لكل لغة محلية (`de.json`، `fr.json`، …) مع مفاتيح مرفقة ببادئات حسب فئة الجمع عند الحاجة
  - التخزين المؤقت: المجلّة الأساسية `strings.json` نفسها

## سلاسل واجهة المستخدم بصيغة الجمع {#plural-ui-strings}

تُظهر مستندات Markdown في هذا الموقع ترجمة **المستند**. وأسهل طريقة لملاحظة سلوك **الجمع** في نصوص واجهة المستخدم هي من خلال مثال **Next.js المجمّع** الموجود بجانب `docs-site/` ضمن `examples/nextjs-app/`.

تشمل صفحة البداية في هذا التطبيق (`src/app/page.tsx`) قسمًا لعرض **الجمع العددي**، ويتم تكرار رسالة واحدة بعدد من الأمثلة حتى تتمكن من مقارنة القواعد النحوية بين اللغات المختلفة (مثل العربية مقابل الإنجليزية). تستدعي كل سطر:

```typescript
t("This page has {{count}} sections", { plurals: true, count })
```

استخدم `plurals: true` بحيث يقوم `extract` بتسجيل مجموعة جمعية في `locales/strings.json` ويقوم `translate-ui` بتعبئة الملفات المسطحة لكل لغة محلية ضمن `public/locales/`. أثناء التشغيل، يقوم i18next بحل المفتاح المُسند باللاحقة الصحيحة للغة النشطة `count`؛ ويُظهر مثال Next كيفية توصيل المساعدات في `src/lib/i18n.ts`.

لعرض لقطات الشاشة وعناوين URLs الخاصة باللغات المحلية وتخطيط الملفات، انظر إلى **مثال الجمع** في [ملف README الخاص بمثال Next.js](https://github.com/wsj-br/ai-i18n-tools/blob/main/examples/nextjs-app/README.md).

## كتل التعليمات البرمجية {#code-blocks}

لا تُترجم كتل الشيفرة **أبدًا**. يتم ترجمة النص المحيط بها، ولكن يتم نسخ كل حرف داخل كتلة الشيفرة حرفيًا دون تغيير.

### Shell {#shell}

```bash
# Install the package
npm install --save-dev ai-i18n-tools

# Run a full sync
npx ai-i18n-tools sync

# Translate only documentation
npx ai-i18n-tools sync --no-ui --no-svg
```

### تهيئة JSON {#json-configuration}

```json
{
  "sourceLocale": "en-GB",
  "targetLocales": ["de", "es", "fr", "pt-BR"],
  "features": {
    "translateMarkdown": true,
    "translateJSON": true
  },
  "documentations": [
    {
      "contentPaths": ["docs-site/docs/"],
      "outputDir": "docs-site/i18n",
      "markdownOutput": { "style": "docusaurus", "docsRoot": "docs-site/docs" }
    }
  ]
}
```

### TypeScript {#typescript}

```typescript
import { createI18nConfig } from 'ai-i18n-tools/runtime';

const config = createI18nConfig({
  defaultLocale: 'en-GB',
  supportedLocales: ['de', 'es', 'fr', 'pt-BR'],
  fallback: 'en-GB',
});

export default config;
```

## التنبيهات (Docusaurus) {#admonitions-docusaurus}

تُترجم عناوين التنويهات في Docusaurus؛ بينما تُحفظ حدود `:::` والكلمات المفتاحية للنوع دون تغيير.

:::note
تم إعداد هذا المستند بشكل متعمد غنيًا بسمات Markdown. الغرض الأساسي منه هو أن يكون كائن اختبار للترجمة — قم بتشغيل `sync` وتفقد الناتج للتحقق من معالجة كل عنصر بشكل صحيح.
:::

:::tip
يمكنك تجاوز النص المترجم لأي جزء عن طريق تعديل ملف الإخراج ثم إعادة تشغيل `sync`. سيكتشف الأداة تعديلاتك ويضيف الصيغة المصححة تلقائيًا إلى مسرد المصطلحات الخاص بالمشروع.
:::

:::warning
لا تُرسل دليل `.translation-cache/` إلى نظام التحكم بالإصدار. إن ذاكرة التخزين المؤقت خاصة بالجهاز وتُعاد إنشاؤها تلقائيًا عند كل استرجاع جديد.
:::

:::danger
حذف دليل التخزين المؤقت يُجبر النظام على إعادة ترجمة كل جزء من البداية. قد يكون ذلك مكلفًا إذا كانت وثائقك كبيرة. استخدم `sync --no-cache-write` لإجراء تشغيل تجريبي دون حفظ النتائج.
:::

## الصور وإعادة كتابة المسارات حسب اللغة المحلية {#images-and-locale-aware-path-rewriting}

يتم ترجمة نصوص وصف الصور (alt text) إلى كل لغة محلية. وبما يتجاوز ذلك، يمكن لـ `ai-i18n-tools` أيضًا **إعادة كتابة مسارات الصور** في المخرجات المترجمة عبر `postProcessing.regexAdjustments` — بحيث يمكن لكل لغة محلية أن تشير إلى لقطة شاشة خاصة بها بدلًا من عرض النسخة الإنجليزية دائمًا.

يُشير المستند المصدر (الإنجليزية) إلى:

```markdown
![The example Next.js app running in English](/img/screenshots/ar/screenshot.png)
```

يحتوي إدخال التهيئة لهذا الموقع على:

```json
"regexAdjustments": [
  {
    "description": "Per-locale screenshot folders in docs-site static assets",
    "search": "screenshots/ar/",
    "replace": "screenshots/${translatedLocale}/"
  }
]
```

بعد الترجمة، يصبح الإخراج الألماني:

```markdown
![Die Beispiel-Next.js-App auf Deutsch](/img/screenshots/de/screenshot.png)
```

ها هي لقطة الشاشة الفعلية لتطبيق Next.js — وهي باللغة الإنجليزية افتراضيًا، ولكن إذا كنت تقرأ هذا المحتوى في موقع مترجم، فيجب أن تعرض الصورة أدناه التطبيق بلغتك:

![The example Next.js app — UI strings and this page translated by ai-i18n-tools](/img/screenshots/ar/screenshot.png)

## القواعد الأفقية وفواصل الأسطر {#horizontal-rules-and-line-breaks}

القاعدة الأفقية (`---`) هي عنصر هيكلي ولا تُترجم.

يتم التعامل مع المحتوى فوقها وتحتها كمقاطع منفصلة، مما يمنح نموذج اللغة السياق بشكل أنظف.
