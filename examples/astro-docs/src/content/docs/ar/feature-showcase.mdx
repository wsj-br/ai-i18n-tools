توجد هذه الصفحة لتوضيح كيفية تعامل `ai-i18n-tools` مع كل بنية شائعة في Markdown. قم بتشغيل `sync` ضدها وقارن المخرجات في كل مجلد لغوي لترى بدقة ما يتم ترجمته وما يظل دون تغيير.

---

<a id="plain-text"></a>

## نص عادي
الترجمة الدولية تتجاوز مجرد تبديل الكلمات. خط أنابيب الترجمة الجيد يحافظ على هيكل المستند، ويحافظ على المعرفات التقنية كما هي، ويرسل فقط النصوص القابلة للقراءة من قبل الإنسان إلى نموذج اللغة.

يقوم `ai-i18n-tools` بتقسيم كل مستند إلى **مقطع** قبل إرساله إلى نموذج اللغة الكبير (LLM). يتم ترجمة كل مقطع بشكل مستقل ثم إعادة تجميعه، وبالتالي فإن تغيير فقرة واحدة لا يجعل الترجمات المخزنة مؤقتًا لبقية الملف غير صالحة.

---

<a id="text-formatting"></a>

## تنسيق النص
يجب على المترجم نقل كل التنسيقات داخل السطر دون تغيير العلامات:

- يشير **النص الغامق** إلى الأهمية ويجب أن يظل غامقًا بعد الترجمة.
- يستخدم _النص المائل_ للتأكيد أو العناوين؛ ويجب الحفاظ على المعنى.
- يُستخدم ~~النص المشطوب~~ للإشارة إلى المحتوى المُعدَم أو المُزال.
- لا يتم ترجمة `inline code` **أبدًا** — يجب أن تظل المعرفات وأسماء الدوال ومسارات الملفات كما هي.
- تحتفظ [رابط تشعبي](https://github.com/wsj-br/ai-i18n-tools) بعنوان URL الأصلي؛ ويتم ترجمة تسمية الرابط فقط.

<a id="tables"></a>

## الجداول
تُعد الجداول مصدرًا شائعًا للأخطاء في الترجمة. يتم ترجمة كل خلية بشكل منفصل؛ مع الحفاظ على فواصل الأعمدة وبناء الجملة الخاص بالمحاذاة.

| الميزة                   | الحالة           | الملاحظات                                                            |
|------------------------|----------------|------------------------------------------------------------------|
| ترجمة Markdown         | ✅ مستقر         | يتم تخزين المقاطع مؤقتًا في SQLite                                        |
| استخراج سلاسل الواجهة    | ✅ مستقر         | يقرأ استدعاءات `t("…")`                                             |
| السلاسل المفردة والجمعية في الواجهة | ✅ مستقر         | `t("…", { plurals: true, count })`؛ كتالوج + لواحق JSON مسطحة |
| ترجمة تسميات JSON       | ✅ مستقر         | JSON شريط التصفح/شريط التنقل في Docusaurus                                   |
| ترجمة نصوص SVG | ✅ مستقر | يحافظ على هيكل SVG |
| تطبيق القاموس | ✅ مستقر | قاموس CSV حسب المشروع |
| التزامن الدُفعي | ✅ قابل للتكوين | المفتاح `batchConcurrency` |

<a id="left-to-right-and-right-to-left-support"></a>

### دعم الكتابة من اليسار إلى اليمين ومن اليمين إلى اليسار
يجب أن تدعم الترجمة الحديثة اللغات المكتوبة من اليسار إلى اليمين (LTR) ومن اليمين إلى اليسار (RTL). ويضمن `ai-i18n-tools` التعامل الصحيح مع اتجاه النص طوال عملية الترجمة:

- يقوم الخط التصنيعي تلقائيًا بالحفاظ على اتجاه كل لغة محلية. على سبيل المثال، يتم عرض اللغة العربية (`ar`) من اليمين إلى اليسار، بينما تبقى الإنجليزية (`en-GB`)، والبرتغالية (`pt`)، وغيرها من اليسار إلى اليمين.
- عند ترجمة جداول Markdown أو أمثلة الأكواد أو سلاسل واجهة المستخدم، تحافظ الأدوات على المحاذاة وهيكل المحتوى، بحيث تُعرض الجداول والكتل المنسّقة بشكل طبيعي في كلا السياقين (LTR وRTL).
- كل من Starlight وتطبيق Next.js النموذجي يحترمان اتجاه اللغة في المتصفح، ويغيّران تخطيط العرض ومحاذاة النصوص وفقًا لذلك.

| الاتجاه | مثال على اللغة | العرض |
|:--------------:|:-----------------------|:-----------------------|
| LTR | `en-GB`, `es`, `pt-BR` | اتجاه قياسي من اليسار إلى اليمين |
| RTL | `ar`, `fa`, `he` | تخطيط من اليمين إلى اليسار |

وهذا يضمن أن تظهر المستندات والواجهات بشكل صحيح، بغض النظر عن لغة المستخدم أو اتجاه القراءة.

<a id="lists"></a>

## القوائم
<a id="unordered"></a>

### غير مرتبة
- يقوم ذاكرة التخزين المؤقت للترجمة بتخزين تجزئة كل مقطع مصدر.
- فقط المقاطع التي تغيرت تجزئتها منذ التشغيل السابق تُرسل إلى نموذج اللغة الكبيرة (LLM).
- وهذا يجعل التشغيل التدريجي سريعًا جدًا — عادةً تتطلب التعديلات الصغيرة بضع استدعاءات واجهة برمجة تطبيقات فقط.

<a id="ordered"></a>

### مرتبة
1. أضف `ai-i18n-tools` كاعتماد تطوير.
2. أنشئ `ai-i18n-tools.config.json` في جذر مشروعك.
3. شغّل `npx ai-i18n-tools sync` لإجراء الترجمة الكاملة الأولى.
4. قم بتأكيد ملفات اللغة المُنشأة مع ملفات المصدر.
5. في التشغيلات اللاحقة، تُعاد ترجمة المقاطع التي تغيرت فقط.

<a id="nested"></a>

### متداخلة
- **خط أنابيب المستندات**
  - المصدر: أي ملف `.md` أو `.mdx`
  - المخرجات: شجرة لغوية `doc-system` (أو أسماء مستعارة `docusaurus` / `astro-starlight`) أو نسخ مترجمة مسطحة
  - ذاكرة التخزين المؤقت: SQLite، مفتاحها هو مسار الملف + تجزئة المقطع
- **خط أنابيب سلاسل واجهة المستخدم**
  - المصدر: ملفات JS/TS تحتوي على استدعاءات `t("…")` (بما في ذلك الأعداد الجمعية عبر `{ plurals: true, count }`)
  - المخرجات: ملفات JSON مسطحة لكل لغة (`de.json`, `fr.json`، ...) بمفاتيح مرفقة بلاحقة لفئات الجمع عند الحاجة
  - ذاكرة التخزين المؤقت: كتالوج `strings.json` الرئيسي نفسه

<a id="plural-ui-strings"></a>

## سلاسل واجهة المستخدم للجمع
تُظهر مستندات Markdown على هذا الموقع ترجمة **document**. يمكن ملاحظة سلوك **Plural** بسهولة في **bundled Next.js example** ضمن `examples/nextjs-app/`.

تشمل الصفحة الرئيسية للتطبيق (`src/app/page.tsx`) قسمًا لعرض **plurals demo**، وتكرر رسالة واحدة بعدد من الأمثلة حتى تتمكن من مقارنة القواعد النحوية عبر اللغات المحلية (مثل العربية مقابل الإنجليزية). تستدعي كل سطر:

```typescript
t("This page has {{count}} sections", { plurals: true, count })
```

استخدم `plurals: true` بحيث يقوم `extract` بتسجيل مجموعة جمعية في `locales/strings.json` ويقوم `translate-ui` بتعبئة الملفات المسطحة الخاصة بكل لغة محلية ضمن `public/locales/`. أثناء التشغيل، يقوم i18next بحل المفتاح المُسبوق المناسب للغة النشطة `count`؛ ويُربط المثال Next بمساعدات في `src/lib/i18n.ts`.

لعرض لقطات الشاشة وعناوين URL الخاصة باللغات المحلية وتخطيط الملفات، راجع **Plurals example** في [Next.js example README](https://github.com/wsj-br/ai-i18n-tools/blob/main/examples/nextjs-app/README.md).

<a id="code-blocks"></a>

## كتل التعليمات البرمجية
لا تُترجم كتل التعليمات البرمجية **أبدًا**. يتم ترجمة النص المحيط بها، ولكن يتم نقل كل حرف داخل كتلة الشفرة كما هو دون تغيير.

<a id="shell"></a>

### Shell

```bash
# Install the package
npm install --save-dev ai-i18n-tools

# Run a full sync
npx ai-i18n-tools sync

# Translate only documentation
npx ai-i18n-tools sync --no-ui --no-svg
```

<a id="json-configuration"></a>

### إعدادات JSON

```json
{
  "sourceLocale": "en-GB",
  "targetLocales": ["de", "es", "fr", "pt-BR"],
  "features": {
    "translateMarkdown": true,
    "translateJSON": true
  },
  "documentations": [
    {
      "contentPaths": ["src/content/docs/"],
      "outputDir": "src/content/docs",
      "markdownOutput": {
        "style": "astro-starlight",
        "docsRoot": "src/content/docs"
      }
    }
  ]
}
```

<a id="typescript"></a>

### TypeScript

```typescript
import { createI18nConfig } from 'ai-i18n-tools/runtime';

const config = createI18nConfig({
  defaultLocale: 'en-GB',
  supportedLocales: ['de', 'es', 'fr', 'pt-BR'],
  fallback: 'en-GB',
});

export default config;
```

<a id="admonitions-starlight"></a>

## التنويهات (Starlight)
عناوين العناصر الجانبية في Starlight تُترجم؛ بينما يُحافظ على تنسيق المكونات دون تغيير.

<Aside type="note">
تم تصميم هذا المستند بشكل متعمد غنيًا بسمات Markdown. الغرض الأساسي منه هو أن يكون أداة اختبار للترجمة — قم بتشغيل `sync` وتفقد المخرجات للتحقق من معالجة كل عنصر بشكل صحيح.
</Aside>

<Aside type="tip">
يمكنك تجاوز الصيغة المترجمة لأي مقطع عن طريق تعديل ملف المخرجات ثم تشغيل `sync` مرة أخرى. سيكتشف الأداة تعديلاتك ويضيف الصيغة المصححة تلقائيًا إلى مسرد مصطلحات المشروع.
</Aside>

<Aside type="caution">
لا تُدرج دليل `.translation-cache/` في التحكم بالإصدار. يتم إنشاء ذاكرة التخزين المؤقت خصيصًا لكل جهاز وتُعاد إنشاءها في كل مرة يتم فيها استرداد النسخة. 
</Aside>

<Aside type="danger">
حذف دليل الذاكرة المؤقتة يجبر النظام على إعادة ترجمة كل مقطع من الصفر. قد يكون ذلك مكلفًا إذا كانت مستنداتك كبيرة الحجم. استخدم `sync --no-cache-write` لإجراء تشغيل تجريبي دون حفظ النتائج.
</Aside>

## الصور وإعادة كتابة المسارات حسب اللغة
يتم ترجمة نصوص وصف الصور إلى كل لغة محلية. وبالإضافة إلى ذلك، يمكن لـ `ai-i18n-tools` أيضًا **إعادة كتابة مسارات الصور** في المخرجات المترجمة عبر `postProcessing.regexAdjustments` — بحيث يمكن لكل لغة محلية أن تشير إلى لقطة شاشة خاصة بها بدلاً من عرض النسخة الإنجليزية دائمًا.

يُشير المستند المصدر (الإنجليزية) إلى:

```markdown
![The example Next.js app running in English](/img/screenshots/ar/screenshot.png)
```

يحتوي إدخال التهيئة لهذا الموقع على:

```json
"regexAdjustments": [
  {
    "description": "Per-locale screenshot folders in public assets",
    "search": "screenshots/ar/",
    "replace": "screenshots/ar/"
  }
]
```

بعد الترجمة، تصبح المخرجات الألمانية كالتالي:

```markdown
![Die Beispiel-Next.js-App auf Deutsch](/img/screenshots/ar/screenshot.png)
```

فيما يلي لقطة الشاشة الفعلية لتطبيق Next.js — تكون باللغة الإنجليزية افتراضيًا، ولكن إذا كنت تقرأ هذا النص بلغة مترجمة، فيجب أن تعرض الصورة أدناه التطبيق بلغتك:

![The example Next.js app — UI strings and this page translated by ai-i18n-tools](/img/screenshots/ar/screenshot.png)

<a id="horizontal-rules-and-line-breaks"></a>

## الخطوط الأفقية وفواصل الأسطر
الخط الأفقي (`---`) هو عنصر هيكلي ولا يتم ترجمته.

يتم التعامل مع المحتوى فوقه وتحته كمقاطع منفصلة، مما يمنح نموذج اللغة سياقًا أكثر وضوحًا.
