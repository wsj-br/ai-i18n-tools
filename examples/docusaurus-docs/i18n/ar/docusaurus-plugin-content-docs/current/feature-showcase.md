توجد هذه الصفحة لتوضيح كيفية تعامل `ai-i18n-tools` مع كل بنية Markdown شائعة. قم بتشغيل `sync` عليها وقارن المخرجات في كل مجلد محلي لترى بالضبط ما يتم ترجمته وما يبقى دون تغيير.

---

## نص عادي {#plain-text}

العولمة هي أكثر من مجرد تبديل الكلمات. يحافظ مسار الترجمة الجيد على بنية المستند، ويحافظ على المعرفات التقنية سليمة، ويرسل فقط النص المقروء بشريًا إلى نموذج اللغة.

يقوم `ai-i18n-tools` بتقسيم كل مستند إلى **أجزاء** قبل إرسالها إلى LLM. يتم ترجمة كل جزء بشكل مستقل ثم إعادة تجميعه، لذا فإن التغيير في فقرة واحدة لا يبطل الترجمات المخزنة مؤقتًا لبقية الملف.

---

## تنسيق النص {#text-formatting}

يجب أن ينقل المترجم جميع التنسيقات المضمنة دون تغيير الترميز:

- **النص الغامق** يشير إلى الأهمية ويجب أن يبقى غامقًا بعد الترجمة.
- يُستخدم _النص المائل_ للتركيز أو العناوين؛ يجب الحفاظ على المعنى.
- ~~يتوسطه خط~~ يشير إلى محتوى مهمل أو محذوف.
- `inline code` **لا** يُترجم أبدًا — يجب أن تظل المعرفات وأسماء الوظائف ومسارات الملفات كما هي.
- [الارتباط التشعبي](https://github.com/wsj-br/ai-i18n-tools) يحتفظ بعنوان URL الأصلي؛ يتم ترجمة تسمية الرابط فقط.

## الجداول {#tables}

الجداول هي مصدر شائع لأخطاء الترجمة. يتم ترجمة كل خلية على حدة؛ ويتم الحفاظ على فواصل الأعمدة وبنية المحاذاة.

| الميزة                | الحالة         | الملاحظات                                                            |
|------------------------|----------------|------------------------------------------------------------------|
| ترجمة Markdown   | ✅ مستقرة       | الأجزاء المخزنة مؤقتًا في SQLite                                        |
| استخراج سلسلة واجهة المستخدم   | ✅ مستقرة       | يقرأ استدعاءات `t("…")`                                             |
| سلاسل واجهة المستخدم بصيغة الجمع | ✅ مستقر | `t("…", { plurals: true, count })`؛ فهرس + لاحقات JSON مسطحة |
| ترجمة تسمية JSON | ✅ مستقر | Docusaurus sidebar/navbar JSON |
| ترجمة نص SVG | ✅ مستقر | يحافظ على بنية SVG |
| تطبيق المسرد | ✅ مستقر | مسرد CSV لكل مشروع |
| التزامن الدفعي | ✅ قابل للتكوين | مفتاح `batchConcurrency` |

### دعم من اليسار إلى اليمين ومن اليمين إلى اليسار {#left-to-right-and-right-to-left-support}

يجب أن تستوعب العولمة الحديثة اللغات التي تُكتب من اليسار إلى اليمين (LTR) واللغات التي تُكتب من اليمين إلى اليسار (RTL). يضمن `ai-i18n-tools` المعالجة الصحيحة لاتجاه النص خلال سير عمل الترجمة:

- يحافظ المسار تلقائيًا على اتجاه كل لغة. على سبيل المثال، تُعرض اللغة العربية (`ar`) من اليمين إلى اليسار، بينما تظل الإنجليزية (`en-GB`) والبرتغالية (`pt`) وغيرها من اليسار إلى اليمين.
- عند ترجمة جداول Markdown أو عينات التعليمات البرمجية أو سلاسل واجهة المستخدم، تحافظ الأدوات على المحاذاة وهيكل المحتوى، بحيث تُعرض الجداول والكتل المنسقة بشكل طبيعي في سياقات LTR وRTL.
- يحترم كل من Docusaurus وتطبيق Next.js المثال اتجاه اللغة في المتصفح، ويغيران التخطيط ومحاذاة النص حسب الاقتضاء.

| الاتجاهية | مثال اللغة | العرض |
|:--------------:|:-----------------------|:-----------------------|
| LTR | `en-GB`، `es`، `pt-BR` | من اليسار إلى اليمين بشكل قياسي |
| RTL | `ar`، `fa`، `he` | تخطيط من اليمين إلى اليسار |

يضمن هذا أن تبدو المستندات والواجهات صحيحة، بغض النظر عن لغة المستخدم أو اتجاه القراءة.

## القوائم {#lists}

### غير مرتبة {#unordered}

- يخزن ذاكرة التخزين المؤقت للترجمة تجزئة لكل جزء من المصدر.
- يتم إرسال الأجزاء التي تغيرت تجزئتها فقط منذ التشغيل الأخير إلى LLM.
- هذا يجعل التشغيلات التزايدية سريعة جدًا — عادةً ما تكون بضع استدعاءات API فقط للتعديلات الصغيرة.

### مرتبة {#ordered}

1. أضف `ai-i18n-tools` كاعتماد تطوير.
2. أنشئ `ai-i18n-tools.config.json` في جذر مشروعك.
3. قم بتشغيل `npx ai-i18n-tools sync` لإجراء الترجمة الكاملة الأولى.
4. قم بتثبيت ملفات اللغة التي تم إنشاؤها جنبًا إلى جنب مع المصدر الخاص بك.
5. في التشغيلات اللاحقة، يتم إعادة ترجمة الأجزاء التي تم تغييرها فقط.

### متداخلة {#nested}

- **مسار المستندات**
  - المصدر: أي ملف `.md` أو `.mdx`
  - الإخراج: شجرة Docusaurus `i18n/` أو نسخ مترجمة مسطحة
  - ذاكرة التخزين المؤقت: SQLite، مفتاحها مسار الملف + تجزئة الجزء
- **مسار سلاسل واجهة المستخدم**
  - المصدر: ملفات JS/TS مع استدعاءات `t("…")` (بما في ذلك صيغ الجمع عبر `{ plurals: true, count }`)
  - الإخراج: JSON مسطح لكل لغة (`de.json`، `fr.json`، ...) مع مفاتيح لاحقة لفئات الجمع عند الاقتضاء
  - ذاكرة التخزين المؤقت: فهرس `strings.json` الرئيسي نفسه

## سلاسل واجهة المستخدم للجمع {#plural-ui-strings}

تُظهر مستندات Markdown في هذا الموقع ترجمة **المستند**. يمكن رؤية سلوك **الجمع** لنسخ واجهة المستخدم بسهولة أكبر في [مثال Next.js](https://github.com/wsj-br/ai-i18n-tools/tree/main/examples/nextjs-app) (`examples/nextjs-app/`)، الذي يجمع بين تطبيق React ونموذج محتوى Docusaurus هذا نفسه.

تتضمن الصفحة الرئيسية لهذا التطبيق (`src/app/page.tsx`) قسمًا لـ **عرض الجمع** وتكرر رسالة واحدة بعدة أعداد عينة حتى تتمكن من مقارنة القواعد النحوية عبر اللغات (على سبيل المثال العربية مقابل الإنجليزية). كل سطر يستدعي:

```typescript
t("This page has {{count}} sections", { plurals: true, count })
```

استخدم `plurals: true` بحيث يسجل `extract` مجموعة جمع في `locales/strings.json` ويملأ `translate-ui` الملفات المسطحة لكل لغة تحت `public/locales/`. في وقت التشغيل، يحل i18next المفتاح الملحق الصحيح لـ `count` النشط؛ يربط مثال Next المساعدين في `src/lib/i18n.ts`.

للحصول على لقطات الشاشة وعناوين URL للغات وتخطيط الملفات، راجع **مثال الجمع** في [ملف README لمثال Next.js](https://github.com/wsj-br/ai-i18n-tools/blob/main/examples/nextjs-app/README.md).

## كتل التعليمات البرمجية {#code-blocks}

كتل التعليمات البرمجية **لا تُترجم أبدًا**. تتم ترجمة النثر المحيط بها، ولكن يتم تمرير كل حرف داخل الكتلة المسورة حرفيًا.

### Shell {#shell}

```bash
# Install the package
npm install --save-dev ai-i18n-tools

# Run a full sync
npx ai-i18n-tools sync

# Translate only documentation
npx ai-i18n-tools sync --no-ui --no-svg
```

### تهيئة JSON {#json-configuration}

```json
{
  "sourceLocale": "en-GB",
  "targetLocales": ["de", "es", "fr", "pt-BR"],
  "features": {
    "translateMarkdown": true,
    "translateJSON": true
  },
  "documentations": [
    {
      "contentPaths": ["docs-site/docs/"],
      "outputDir": "docs-site/i18n",
      "markdownOutput": { "style": "docusaurus", "docsRoot": "docs-site/docs" }
    }
  ]
}
```

### TypeScript {#typescript}

```typescript
import { createI18nConfig } from 'ai-i18n-tools/runtime';

const config = createI18nConfig({
  defaultLocale: 'en-GB',
  supportedLocales: ['de', 'es', 'fr', 'pt-BR'],
  fallback: 'en-GB',
});

export default config;
```

## التنبيهات (Docusaurus) {#admonitions-docusaurus}

تُترجم عناوين تنبيهات Docusaurus؛ ويتم الاحتفاظ بحدود `:::` والكلمات المفتاحية للنوع.

:::note
هذا المستند غني عن قصد بميزات Markdown. والغرض الأساسي منه هو أن يكون بمثابة أداة اختبار للترجمة — قم بتشغيل `sync` وافحص المخرجات للتحقق من معالجة كل عنصر بشكل صحيح.
:::

:::tip
يمكنك تجاوز الصياغة المترجمة لأي جزء عن طريق تحرير ملف الإخراج وتشغيل `sync` مرة أخرى. ستكتشف الأداة تعديلاتك وتضيف الصياغة المصححة إلى مسرد المشروع تلقائيًا.
:::

:::warning
لا تقم بتثبيت دليل `.translation-cache/` في نظام التحكم في الإصدار. ذاكرة التخزين المؤقت خاصة بالجهاز ويتم إعادة إنشائها عند كل سحب جديد.
:::

:::danger
يؤدي حذف دليل ذاكرة التخزين المؤقت إلى إعادة ترجمة كل جزء من البداية. قد يكون هذا مكلفًا إذا كانت مستنداتك كبيرة. استخدم `sync --no-cache-write` لإجراء تشغيل تجريبي دون الاحتفاظ بالنتائج.
:::

## الصور وإعادة كتابة المسار المدرك للموقع {#images-and-locale-aware-path-rewriting}

تتم ترجمة النص البديل للصورة إلى كل لغة. بالإضافة إلى ذلك، يمكن لـ `ai-i18n-tools` أيضًا **إعادة كتابة مسارات الصور** في المخرجات المترجمة عبر `postProcessing.regexAdjustments` — بحيث يمكن لكل لغة الإشارة إلى لقطة الشاشة الخاصة بها بدلاً من عرض النسخة الإنجليزية دائمًا.

يشير المستند المصدر (الإنجليزية) إلى:

```markdown
![The example Next.js app running in English](/img/screenshots/ar/screenshot.png)
```

يتضمن إدخال التكوين لموقع المستندات هذا ما يلي:

```json
"regexAdjustments": [
  {
    "description": "Per-locale screenshot folders in docs-site static assets",
    "search": "screenshots/ar/]+/",
    "replace": "screenshots/ar/"
  }
]
```

بعد الترجمة، يصبح الإخراج الألماني:

```markdown
![Die Beispiel-Next.js-App auf Deutsch](/img/screenshots/ar/screenshot.png)
```

هذه هي لقطة الشاشة الفعلية لتطبيق Next.js — وهي باللغة الإنجليزية افتراضيًا، ولكن إذا كنت تقرأ هذا بلغة مترجمة، فيجب أن تعرض الصورة أدناه التطبيق بلغتك:

![تطبيق Next.js المثال — سلاسل واجهة المستخدم وهذه الصفحة مترجمة بواسطة ai-i18n-tools](/img/screenshots/ar/screenshot.png)

## الخطوط الأفقية وفواصل الأسطر {#horizontal-rules-and-line-breaks}

الخط الأفقي (`---`) هو عنصر هيكلي ولا تتم ترجمته.

يتم التعامل مع المحتوى أعلاه وأسفله كأجزاء منفصلة، مما يمنح LLM نوافذ سياق أنظف.
