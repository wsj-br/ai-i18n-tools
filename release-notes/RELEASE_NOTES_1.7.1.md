# ai-i18n-tools 1.7.1 Release Notes

## Highlights

- **Multi-provider LLM support:** Configure several LLM providers under a top-level `providers` map and pick the active one with a `provider` key. Built-in OpenAI-compatible presets ship for `openrouter`, `openai`, `anthropic`, `gemini`, `deepseek`, `cerebras`, `groq`, `mistral`, `xai`, `nvidia`, `alibaba`, `apifun`, and `ollama` (each needs only a `translationModels` list); any other key defines a custom endpoint. A new global `-P, --provider <name>` flag switches provider for a single run without editing the config, and the legacy `openrouter` config block is auto-migrated. The provider-agnostic client is now `LlmClient` (the old `OpenRouterClient` name is kept as a deprecated alias).
- **Script-aware translation and validation:** Locales carrying an ISO 15924 script subtag (e.g. `hi-Latn`, `sr-Cyrl`, `zh-Hans`) now get a `SCRIPT REQUIREMENT` directive in the prompt, and completions written in the wrong script are rejected with automatic model fallback (`ScriptValidationError`). Wrong-script validation covers every supported script (Latin, Cyrillic, Arabic, Devanagari, Han, …). Chinese entries pivoted from region variants to script subtags (`zh-Hans` / `zh-Hant`), and several new script-variant languages were added.
- **New `list-languages` and `list-models` commands:** `list-languages` prints the bundled UI languages catalog (with optional search), and `list-models` lists every model advertised by the active provider's `GET /models` endpoint (with pricing where available). Config now fatally validates `sourceLocale` / `targetLocales` against the catalog and points you at `list-languages` when a code is unknown.
- **Interrupt and cache reliability:** `Ctrl-C` (`SIGINT`) now reliably interrupts even fully-cached document-translation runs, and interrupted runs no longer leave SQLite `-wal` / `-shm` sidecar files behind (idempotent `TranslationCache.close()` plus a `process.on("exit")` safety net). The `dashboard` command also shuts down cleanly on signals.
- **Dashboard improvements:** The "By model and locale" statistics matrices now render full-width, and a new header "Close" button stops the local server and closes the window.
- **`cleanup` backup change:** `cleanup` no longer writes a SQLite backup by default — pass `--backup <path>` to snapshot before modifications (the `--no-backup` flag was removed). `cleanup` also fully refreshes the `markdown_source_issues` table so renamed/deleted docs no longer linger in the dashboard.
- **Cleaner dependencies and tooling:** Pruned stale `pnpm-workspace.yaml` overrides, silenced benign peer warnings, and added a non-fatal peer-dependency phase to the upgrade script.

## Why this release matters

Version 1.7.1 makes ai-i18n-tools provider-agnostic — you can now translate through OpenAI, Anthropic, Gemini, DeepSeek, Ollama, and many more (or a custom endpoint) and switch per run — and adds first-class support for script-variant locales with automatic wrong-script rejection and fallback. It also makes interrupts and cache shutdown reliable so cancelled runs no longer leave stray SQLite sidecar files.

## Detailed Changes

- **Changed**: cli/cache — `cleanup` no longer writes a SQLite backup by default. A backup is now made only when `--backup <path>` is passed, which writes the snapshot to that path before modifications. The `--no-backup` flag (previously needed to opt out of the automatic timestamped backup) has been removed, and `--backup` no longer has a default timestamped path.

- **Fixed**: core/cache — `TranslationCache` now closes cleanly on any process exit via a `process.on("exit")` safety net that closes every still-open on-disk cache (registry of open instances; synchronous WAL checkpoint + `db.close()`). This covers hard exits that bypass a command's `finally { cache.close() }` — a second-`Ctrl-C` force-quit (`createRunInterruptScope`), `exitIfRunInterrupted`, and `process.exit(1)` error paths — so an interrupted command no longer leaves the `-wal` / `-shm` sidecar files behind. `TranslationCache.close()` is now idempotent (guarded by a `closed` flag) so the command's own close and the safety net never double-close the connection.

- **Fixed**: cli/docs — interrupting a document-translation run (`Ctrl-C` / `SIGINT`, including via `cleanup` → `sync --force-update`) no longer leaves the SQLite `-wal` / `-shm` sidecar files behind. `runTranslate` (`src/cli/doc-translate.ts`) called `process.exit()` from inside its `catch` block, which terminated the process before the `finally` ran, skipping `cache.close()` (the `PRAGMA wal_checkpoint(TRUNCATE)` + `db.close()` that flushes the WAL and unlinks the sidecars). The interrupt path now records the exit code and exits from `finally` after the cache is closed.

- **Changed**: cli/docs — the document-translation partial summary printed on interrupt (`Ctrl-C`) or failure no longer re-prints the provider, the model fallback chain, and the batch prompt format. That block already appears in the pre-run banner, so re-printing it was redundant noise (and misleading for fully-cached runs that did no API work). `printTranslateDocsRunSummary` no longer takes `models` / `provider` arguments.

- **Fixed**: cli/utils — `Ctrl-C` (`SIGINT`) now interrupts fully-cached document translation runs (e.g. `cleanup` → `sync --force-update`, `translate-docs`, `sync`). Cached runs do no real async I/O (synchronous `fs.*` + synchronous `better-sqlite3`), so the pipeline executed as one unbroken microtask cascade; Node only dispatches signal handlers at event-loop boundaries, so the `SIGINT` handler installed by `createRunInterruptScope` was queued but never ran until the run finished (the `⚠️ Interrupted` message never printed and repeated `Ctrl-C` did nothing). The `runMapWithConcurrency` worker loop and the sequential per-file loops in `doc-translate.ts` now yield to the macrotask queue via the new `yieldToEventLoop()` helper (`src/utils/concurrency.ts`), so the abort becomes observable mid-run and the run stops promptly.

- **Fixed**: dashboard (web) — the "By model and locale" matrix in the Statistics tab is no longer trapped inside a ~50%-wide `.stats-column`. Both the documentation-cache and UI-strings matrices are now rendered in a full-width `.stats-fullwidth` section below the two-column grid (each with its own labeled `stats-section` heading), so wide model×locale tables can use the entire available width with horizontal scrolling only when needed.

- **Added**: dashboard (web) — a right-justified "Close" button in the header tab row stops the local dashboard server via the new `POST /api/shutdown` endpoint (wired to the CLI's existing `shutdown()` path: `server.close()` + `TranslationCache.close()` + `process.exit`) and then closes the browser window.

- **Fixed**: cli/cache — the `dashboard` command now shuts down cleanly on Ctrl-C / `SIGINT` (and `SIGTERM`): it force-drains lingering keep-alive HTTP connections via `server.closeAllConnections()` and adds a 2s safety-net timeout so `TranslationCache.close()` always runs, checkpointing the WAL and letting SQLite remove the `-wal` / `-shm` sidecar files. (When an external process such as an IDE SQLite viewer holds `cache.db` open, SQLite cannot unlink the sidecars until that connection is also closed — this is expected WAL behavior, not a flush bug.)

- **Changed**: core/cache — `TranslationCache.backupTo` now finalizes the backup file as a self-contained rollback-journal database (`PRAGMA wal_checkpoint(TRUNCATE)` + `journal_mode = DELETE`) so a `cleanup` backup never leaves `-wal` / `-shm` sidecar files next to the `.sqlite` snapshot.

- **Changed**: cli/cache — `cleanup` now clears the entire `markdown_source_issues` table at the start of the run (via the new `TranslationCache.clearAllMarkdownIssues(dryRun)`), before the `sync --force-update` step repopulates it with only the currently-configured docs. This keeps the table always up to date and drops rows for files that were renamed, deleted, or removed from `docs[].contentPaths` — which a per-file scan never revisits, so the previous disk-existence prune left them lingering forever in the dashboard "Markdown issues" tab. Anything not re-scanned by `sync` can be rebuilt later with `check-markdown` (the dashboard already prompts for this). Honors `--dry-run` (reports the count without deleting). Removes the previous disk-existence prune (`pruneOrphanedMarkdownIssuesByDisk` / `listMarkdownIssueFilepaths`).

- **Fixed**: processors/emphasis — `applyEmphasisCloserSpacing` (the no-placeholder restore path used for non-CJK/RTL locales such as `hi-Latn`) no longer corrupts ASCII identifiers that contain underscores. The relaxed underscore-flanking rule in `scanDelimitersForSpacing` was added for no-space scripts (CJK), but `\p{L}` also matched ASCII letters, so intraword underscores in identifiers like `translation_demo_svg` or `my_config_value` (including inside link text and destinations) were treated as emphasis: the restore injected spaces (`translation _demo_ svg`) and fabricated an `emphasis` span, which then failed the AST quality check and triggered the full model-fallback + segment-splitting cascade. The relaxation now only applies when an adjacent character is a non-ASCII (tight-script) letter via the new `isTightScriptLetter` helper; CJK gluing behavior is unchanged.

- **Changed**: api — renamed the provider-agnostic LLM module `src/api/openrouter.ts` to `src/api/llm-client.ts` and the now-generic models catalog `src/api/openrouter-models-catalog.ts` to `src/api/provider-models-catalog.ts` (test files renamed to match) to stop implying they are OpenRouter-only. Internal call sites now use `LlmClient` instead of the legacy `OpenRouterClient` name; the deprecated `OpenRouterClient` / `OpenRouterClientOptions` exports are retained for backward compatibility. The catalog's canonical entry type is now `ProviderModelEntry` (with `OpenRouterCatalogModelEntry` kept as a deprecated alias) and its generic parse error message no longer says "OpenRouter". `src/cli/openrouter-catalog-model-filter.ts` keeps its name because it is intentionally OpenRouter-specific (it no-ops for every other provider).

- **Added**: ui-languages — new script-variant entries in `data/ui-languages-complete.json` (synced to the runtime symlink): `ha-Arab` (Hausa, Arabic, `rtl`), `kk-Latn` (Kazakh, Latin), `mn-Mong` (Mongolian, traditional vertical script), `sd-Deva` (Sindhi, Devanagari), `sr-Latn` (Serbian, Latin), and `uz-Cyrl` (Uzbek, Cyrillic). These are now valid `sourceLocale`/`targetLocales` and pick up the script directive and wrong-script validation below.

- **Changed**: api — wrong-script validation now covers every supported ISO 15924 script subtag, not just `*-Latn`. For non-Latin targets (`Cyrl`, `Arab`, `Deva`, `Mong`, `Han`, …) a completion is rejected and the next model retried when it contains letters from a *different* non-Latin script; Latin text (code, URLs, brand names, placeholders) is always allowed, so native-script→Latin fallback is left to the prompt directive and there are no false positives. Composite scripts (`Jpan`, `Kore`) and locales without a script subtag are not enforced. New helpers `disallowedScriptLetters` and `unicodeScriptPropertyForSubtag` in `src/core/locale-utils.ts` (re-exported from `config` and the package root); `mn-Mong` gets an explicit "traditional Mongolian vertical script (Mongolian Bichig), NOT Cyrillic" directive name.

- **Added**: prompts/api — script-aware translation for locales that carry an ISO 15924 script subtag (e.g. `hi-Latn`, `sr-Cyrl`, `zh-Hans`). Prompt builders now prepend a `SCRIPT REQUIREMENT` directive to the system prompt: `*-Latn` targets get a strong romanization rule (write Latin/Roman letters only, never Devanagari/Cyrillic/etc.), other scripts get a generic "write in {script} script" rule. This covers document single/batch, UI batch, and plural pass-B prompts via a new `targetLocale` builder option. Directive content lives in `PROMPTS.script` (`src/core/prompts.ts`); assembly via `targetScriptDirective` in `src/core/prompt-builder.ts`.

- **Added**: api — wrong-script validation with model fallback. `LlmClient` now rejects a `*-Latn` (romanized) completion that contains native-script letters (Devanagari, Cyrillic, Han, …) and retries the next model in the chain, throwing only when every model fails. Enforced for `translateDocumentSegment`, `translateDocumentBatch`, `translateUIBatch`, and `translatePluralCardinalBatch` (the latter via a new `targetLocale` option). Non-Latin script subtags are not enforced to avoid false positives from legitimate Latin text (code, URLs, brand names). New `ScriptValidationError` (exported) carries the offending characters.

- **Added**: core — locale helpers `scriptSubtag`, `isLatinScriptLocale`, `englishScriptName`, and `nonLatinLettersIn` in `src/core/locale-utils.ts` (re-exported from `config` and the package root) for script-subtag parsing and non-Latin letter detection.

- **Added**: cli — new `list-languages` command prints the bundled UI languages catalog (`data/ui-languages-complete.json`) as a human-readable table (code, text direction, English name, native name). The native name is the last column so non-Latin scripts (combining marks, wide CJK glyphs) whose display width differs from their string length cannot misalign the other columns. Passing an optional `SEARCH` argument (`ai-i18n-tools list-languages <term>`) filters entries whose code, native name, English name, or direction contain the term (case-insensitive); it needs no config. New module `src/cli/list-languages.ts` exposes `runListLanguages`.

- **Added**: cli — the translate commands (`translate-docs`, `translate-ui`, `translate-svg`) now print a `Provider: <name>` line immediately before the `Models (try in order):` block in their run headers and partial summaries, naming the active LLM provider. Adds `LlmClient.getProvider()` and `safeResolveActiveProvider()` (a non-throwing variant of `resolveActiveProvider`) so the provider can be shown even on dry runs without a client.

- **Changed**: config — the `ConfigValidationError` raised for unknown `sourceLocale` / `targetLocales` now ends with a hint to run `ai-i18n-tools list-languages` (optionally with a search term) so users can discover the available language codes.

- **Added**: config — `loadI18nConfigFromFile` now fatally validates that `sourceLocale` and every `targetLocales` entry exist in the bundled UI languages catalog (`data/ui-languages-complete.json`) right after the config is parsed, throwing a `ConfigValidationError` (CLI exits non-zero) that lists each unknown locale. A bare language subtag (e.g. `en`, `zh`, `pt`) is accepted when the catalog only carries its regional/script variants (`en-GB`, `zh-Hans`, `pt-BR`), while malformed tags such as `hi-Lan` are rejected.

- **Removed**: deps — pruned stale entries from `pnpm-workspace.yaml`. Dropped three `minimumReleaseAgeExclude` pins whose exact versions are no longer in the lockfile (`postcss@8.5.10` → resolves `8.5.15`, `vite@8.0.16` → resolves `7.3.5`, `http-proxy-middleware@3.0.6` → resolves `3.0.7`), and removed two redundant `overrides` (`i18next: ^26.1.0` and `joi@>=17.0.0 <17.13.4: ^17.13.4`) that no longer changed resolution (`i18next` stays `26.3.1`, `joi` stays `17.13.4`). Verified by re-resolution: no installed versions changed, `pnpm install --frozen-lockfile` passes, and `pnpm audit` stays clean. Load-bearing overrides (`postcss`, `serialize-javascript`, `uuid`, `esbuild`, `http-proxy-middleware`, the `gray-matter` alias, and the `express` v5 dedup pin) are kept.

- **Fixed**: deps — removed the stale `vite@>=8.0.0 <8.0.16: ^8.0.16` override from `pnpm-workspace.yaml`. No vite 8 is installed (astro 6 pins `vite@7.3.5`) and there is no current vite advisory, so the override fixed nothing and only rewrote the `vite` peer ranges of `vitest`/`@vitest/mocker`/`vitefu` (which actually accept `^6 || ^7 || ^8`) to `^8.0.16`, producing false "unmet peer vite" warnings in `pnpm peers check`.

- **Fixed**: deps — silenced the benign `@astrojs/tailwind` peer warning by adding `peerDependencyRules.allowedVersions` (`"@astrojs/tailwind>astro": "6"`) to `pnpm-workspace.yaml`. `@astrojs/tailwind@6.0.2` is the final release and pins its peer to `astro ^3 || ^4 || ^5`, but it builds correctly against `astro@6` (the `examples/astro-website` build passes), so we accept astro 6 instead of migrating the example to Tailwind v4 / `@tailwindcss/vite`.

- **Added**: scripts — `scripts/upgrade-dependencies.sh` now runs a non-fatal peer-dependency phase (`pnpm peers check`) after the security phase and reports any unmet peers in the upgrade summary. The build-safe doctor pass (typecheck/lint/build) does not exercise peer ranges, so issues like stale overrides rewriting a peer range previously went unreported; other package managers (no first-class peers checker) are reported as skipped.

- **Changed**: examples — `examples/multi-provider` and `examples/test-markdown` are no longer pnpm workspace packages and install nothing (removed from `pnpm-workspace.yaml`, dropped their `ai-i18n-tools` `workspace:^` dev dependency, and deleted their `node_modules/`). Their package scripts and READMEs now invoke the repo CLI directly via `node ../../bin/ai-i18n-tools.mjs …` (which only needs the library built once from the repo root) instead of the previously linked `ai-i18n-tools` bin, so neither folder needs a per-example install. Trade-off: running a `pnpm run` script that exits non-zero in these dirs may again surface pnpm's `Local package.json exists, but node_modules missing` note, but the folders stay install-free.

- **Fixed**: cli — `check-models` now always includes the active provider in its `list-models` hint (e.g. `ai-i18n-tools list-models -P deepseek`). Previously the `-P {provider}` part was gated on `activeProvider !== config.provider`, but the global `-P` / `--provider` override mutates the config `provider` key before the hint is built, so the two always matched and the flag was never shown.

- **Changed**: cli — `check-models` now hints to run `ai-i18n-tools list-models` when a configured model is not in the active provider's models list, so users can discover the currently available model ids. When the active provider was selected via the global `-P` / `--provider` override (i.e. it differs from the config `provider` key), the hint includes `-P {provider}` (e.g. `ai-i18n-tools -P deepseek list-models`).

- **Fixed**: cli — `check-models` and `list-models` now work for the `anthropic` provider. Anthropic's `GET /v1/models` is its native (non-OpenAI-compatible) endpoint and rejected the OpenAI-style `Authorization: Bearer` header with `401 Invalid bearer token` (even though chat translation, which uses the OpenAI-compatible endpoint, worked). Added `resolveModelsListRequestAuth` in `src/core/llm-providers.ts` to send `x-api-key` + `anthropic-version` for Anthropic (and the attribution headers for OpenRouter), and surface Anthropic's `display_name` as the model label via `modelDisplayName`.

- **Added**: cli — new `list-models` command lists every model advertised by the active provider's OpenAI-compatible `GET /models` endpoint (sorted by id, with input/output pricing in USD per 1M tokens when the provider returns it, and an `[expired]` tag for entries past `expiration_date`). The active provider follows the config `provider` key and is overridable for a single run with the global `-P` / `--provider` flag; keyless providers like Ollama need no API key. New module `src/cli/list-models.ts` exposes `runListModels`.

- **Changed**: cli — `check-models` now validates configured `translationModels` against any active provider's OpenAI-compatible `GET /models` list (not just OpenRouter), reporting ids that are missing or past `expiration_date` and exiting non-zero on problems. Pricing (USD per 1M tokens) is shown only when the provider returns it (e.g. OpenRouter); keyless providers like Ollama need no API key. Dropped the previous "catalog validation and pricing are only available for the OpenRouter provider" notice. Added `fetchProviderModelsCatalog`/`ProviderModelEntry` in `src/api/provider-models-catalog.ts` (the OpenRouter fetcher is now a thin wrapper).

- **Added**: examples — new `examples/multi-provider` example that translates a single Portuguese markdown document (`markdown-example.md`) while switching LLM providers via the global `-P` / `--provider` flag. One `ai-i18n-tools.config.json` configures `openai`, `anthropic`, `nvidia`, and `deepseek` (default `provider: "openai"`), with a README covering the required API-key env vars and how to compare provider outputs. Added matching pointers in the `LLM providers` sections of `README.md` and `docs/GETTING_STARTED.md`.

- **Added**: cli — global `-P, --provider <name>` option overrides the config `provider` key for a single run, so projects with several configured providers can switch without editing the config file (e.g. `ai-i18n-tools -P groq translate-ui`). The name must be configured under `providers`; an unknown value fails fast with the list of configured providers. `loadI18nConfigFromFile` accepts an optional `providerOverride` argument and exposes `applyProviderOverrideToRawInput`.

- **Changed**: examples — gave the `examples/test-markdown` files consistent locale-suffixed names: Portuguese source `test-markdown.md` → `test-markdown-pt-BR.md`, and configs `ai-i18n-tools.config.json` → `ai-i18n-tools.config-pt-BR.json` and `ai-i18n-tools.config-en.json` → `ai-i18n-tools.config-en-GB.json`. Updated `contentPaths` and all references/commands in the example README. Pass `-c` explicitly (e.g. `-c ai-i18n-tools.config-pt-BR.json`); outputs write to `translated-docs/test-markdown-pt-BR.{locale}.md`.

- **Removed**: scripts — deleted `scripts/build-ui-languages-complete.mjs` and the `build:ui-languages-master` npm script, plus the now-unused `scripts/fill-ui-language-labels.mjs` and its `scripts/lib/load-fill-label-config.mjs` helper (the config/model resolver was inlined into `scripts/validate-ui-language-labels.mjs`, which already audits and repairs `label`/`direction`). `data/ui-languages-complete.json` is now hand-maintained (the `pnpm build` step copies it to the runtime via `scripts/copy-runtime-ui-languages-json.mjs`).

- **Fixed**: locale-utils — `normalizeLocale` now Title-cases 4-letter ISO 15924 script subtags (e.g. `zh-hant` → `zh-Hant`) instead of upper-casing them like regions (`zh-HANT`), so script-based locales such as `zh-Hans` / `zh-Hant` canonicalize correctly in language-switcher rows, output codes, and link rewriting. Region subtags (`pt-BR`, `419`) are unchanged.

- **Changed**: ui-languages — pivoted Chinese entries from region/locale variants to script subtags in `data/ui-languages-complete.json` (and the synced `src/runtime/ui-languages-complete.json`): replaced `zh`, `zh-CN`, `zh-HK`, `zh-SG`, `zh-TW` with `zh-Hans` (简体中文 / Chinese (Simplified)) and `zh-Hant` (繁體中文 / Chinese (Traditional)). Updated `targetLocales` to `zh-Hans`/`zh-Hant` in the root `ai-i18n-tools.config.json`, `examples/astro-website`, and both `examples/test-markdown` configs, plus the matching docs (`docs/GETTING_STARTED.md`, `docs/ai-i18n-tools-context.md`, example READMEs). Re-run `translate-docs` / `sync` to regenerate locale bundles, manifests, `translated-docs`, and language-list blocks under the new codes.

- **Added**: llm — multi-provider LLM support. Configure providers under a top-level `providers` map and select the active one with a top-level `provider` key (optional when exactly one provider is configured). Built-in OpenAI-compatible presets ship for `openrouter`, `openai`, `anthropic`, `gemini`, `deepseek`, `cerebras`, `groq`, `mistral`, `xai`, `nvidia`, `alibaba`, `apifun`, and `ollama` (each needs only a `translationModels` list); any other key defines a custom endpoint via `baseUrl` (+ `apiKeyEnv`). New module `src/core/llm-providers.ts` exposes `PROVIDER_PRESETS`, `resolveActiveProvider`, `resolveProviderSettings`, and `resolveApiKey`.

- **Changed**: api — `OpenRouterClient` is now `LlmClient`, a provider-agnostic chat client built on the Vercel AI SDK (`generateText` via `createOpenAICompatible`) that routes every provider through its OpenAI-compatible `/chat/completions` endpoint. `OpenRouterClient` / `OpenRouterClientOptions` / `OpenRouterUsageStats` remain as deprecated aliases (`LlmClient` / `LlmClientOptions` / `LlmUsageStats`). OpenRouter-specific throughput routing, `HTTP-Referer` / `X-Title` headers, and exact `usage.cost` reporting now apply only when `openrouter` is the active provider; token usage is reported for all providers.

- **Changed**: config — the top-level `openrouter` config block is replaced by `provider` + `providers`. A legacy `openrouter` block is still accepted and is automatically migrated in-memory and rewritten on disk to `providers.openrouter` (with `provider: "openrouter"`); legacy `defaultModel` / `fallbackModel` fold into `translationModels`. `applyEnvOverrides` now maps `OPENROUTER_BASE_URL` → `providers.openrouter.baseUrl` and `OLLAMA_BASE_URL` → `providers.ollama.baseUrl` (only when those providers are configured). `check-models` validates against the OpenRouter catalog with pricing only for the `openrouter` provider; other providers list configured ids.

- **Added**: dependencies — added `ai` (`^6.0.208`) and `@ai-sdk/openai-compatible` (`^2.0.51`) for provider-agnostic LLM transport.

- **Changed**: tooling — `vitest.config.ts` coverage now excludes auto-generated sources via the glob `src/**/*.generated.ts` (e.g. `src/build-info.generated.ts`), so generated files no longer count toward coverage totals or thresholds. New generated sources should follow the `.generated.ts` naming convention to be excluded automatically.

- **Added**: tests — expanded unit coverage for `run-interrupt` (SIGTERM exit code 143, second-signal force-exit, `dispose` listener cleanup, `throwIfAbortSignal`, `runInterruptedExitCode`, and `bindRunInterruptScope` passthrough vs managed scopes), `markdown-quality-split` (`heading`/`admonition` types, depth ≥ 2 splitting, empty/whitespace input, line-midpoint fallback, and char-midpoint floor behavior), and `ui-languages` (`getJsonTargetLocaleCodes`/`resolveLocalesForJson`, `resolveUiLanguagesAbsPath`, `expandJsonTargetLocalesInRawInput`, and `loadUiLanguageEntries` edge cases).

- **Fixed**: tooling — quoted the `@11ty/gray-matter@2.1.0` entry under `minimumReleaseAgeExclude` in `pnpm-workspace.yaml`; the leading `@` is a reserved YAML indicator, so the unquoted scalar broke `pnpm install` with a "bad indentation of a sequence entry" parse error.

- **Fixed**: scripts — `_dedupe_min_release_age_exclude` in `scripts/upgrade-dependencies.sh` now emits YAML-safe quoting when rewriting `minimumReleaseAgeExclude`. Previously it stripped quotes and re-emitted scoped specs (e.g. `@11ty/gray-matter@…`) unquoted, producing invalid YAML, and its quoted-vs-unquoted idempotency check never matched, so every run re-broke `pnpm-workspace.yaml` (the root cause of the install parse error above).
