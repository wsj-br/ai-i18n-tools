# ai-i18n-tools 1.8.0 Release Notes

## Highlights

- **VitePress-first documentation:** A comprehensive multi-language VitePress documentation site under `docs/` (published to GitHub Pages on release) replaces the monolithic `GETTING_STARTED.md`, `PACKAGE_OVERVIEW.md`, and `LOCALE-ASSETS-GUIDE.md`. New `docsOutput.style: "vitepress"` and `init -t ui-vitepress` scaffold VitePress projects with locale-aware link rewriting for markdown, theme nav/sidebar, and homepage frontmatter.
- **New CLI commands:** `bench-models` benchmarks configured translation models in parallel with per-model timing, token, and cost reporting; `purge-locale` deletes a locale's cache rows and generated artifacts (documents, flat UI files, `strings.json` entries) with dry-run and backup support.
- **Breaking rename — `proofread-ui`:** The `lint-source` command is renamed to `proofread-ui` (no backward-compatible alias) to better reflect its AI proofreading of source-locale UI strings.
- **Finer-grained model routing:** Optional `providers.<name>.uiModels` and `localeModels` let you steer UI translation, plural generation, and proofreading separately from document/JSON/SVG pipelines; `ui.preferredModel` is removed in favor of `uiModels`.
- **More reliable doc output:** `sync` and `translate-*` commands now recreate translated files when the destination is missing or older than its source, even on cache hits — fixing stale or accidentally deleted outputs without extra LLM calls.
- **Richer markdown processing:** Nested admonitions (4+ colon fences) are fully supported; bracketed admonition titles translate inline; `check-markdown` reports malformed admonition syntax.
- **Config and examples cleanup:** `uiLanguagesPath` is renamed to `languagesManifestPath` (legacy key still accepted); all `examples/` folders pin published `^1.7.2` for degit-safe standalone use; `examples/astro-website` migrates to Tailwind 4.

## Why this release matters

Version 1.8.0 is a major documentation and VitePress integration release: translated docs sites get first-class link rewriting, theme localization, and a new starter template, while new `bench-models` and `purge-locale` commands make model selection and locale cleanup practical day-to-day. Under the hood, smarter output regeneration, nested admonition support, and per-pipeline model routing make translation runs more predictable and configurable.

## Detailed Changes

- **Fixed**: processors — VitePress link rewriting prefixes internal routes in translated markdown and home-layout frontmatter (`hero.actions[].link`, `features[].link`, `prev`/`next`) for output under `docs/<locale>/…`; shared public assets (`/logo.svg`, etc.) stay unprefixed.
- **Added**: processors — `prefixVitepressThemeNavLinks` and `prefixVitepressThemeConfigLinks` prefix navbar/sidebar `link` and `activeMatch` in `.vitepress/config.mts` per locale (same rules as markdown rewriting). Exported from `ai-i18n-tools`; requires `^1.8.0`.
- **Changed**: examples — `examples/vitepress-docs` imports `prefixVitepressThemeConfigLinks` from `ai-i18n-tools` (degit-safe) instead of a monorepo-relative `src/` path.
- **Changed**: docs — VitePress homepage uses `layout: home` (hero, feature cards, install section, doc links); added `docs/public/logo.svg` and home-page CSS. Extended frontmatter translation for VitePress `hero.name`, `hero.text`, and `features.*` fields.
- **Changed**: docs — `docs/index.md` is now a slim VitePress landing page independent from `README.md`; removed `scripts/sync-readme-to-docs.mjs` and README→index sync from `docs:dev`, `docs:build`, `docs:preview`, `docs:sync`, and `i18n:sync`. README remains the full GitHub/npm guide; update each file according to its audience.
- **Changed**: scripts — refactored root npm scripts: heavy workflows (`pre-release`, `update-all`, `docs:publish`, `release:github`) delegate to `scripts/*.sh`; removed per-pipeline `i18n:translate:ui` / `:svg` / `:docs` wrappers in favor of `i18n:translate:sync` (`sync`); `docs:sync` runs `translate-docs` on `docs/index.md`; `pre-release` expands to i18n sync, heading updates, full `sync`, docs build, and production checks for all buildable examples including `console-app` and `multi-provider`.
- **Changed**: config — renamed root-level `uiLanguagesPath` to `languagesManifestPath` (shared locale manifest for app language pickers and docs `languageListBlock` post-processing). Legacy `uiLanguagesPath` is accepted on load and auto-rewritten in config files.
- **Removed**: `dev/package-context.md` — maintainer reference consolidated into `AGENT.md` (deep-reference pointers) and existing `docs/reference/` pages.
- **Changed**: `AGENT.md`, `README.md`, `docs/ai-i18n-tools-context.md` — documentation pointers now reference `AGENT.md`, `docs/reference/`, and `dev/DEVEL.md` instead of `dev/package-context.md`.
- **Added**: config — optional `providers.<name>.uiModels` (UI-only fallback chain for `translate-ui`, plural generation, and `proofread-ui`) and `localeModels` (per-locale overrides for all translation pipelines). Resolution order: UI → `localeModels` → `uiModels` → `translationModels`; docs/JSON/SVG → `localeModels` → `translationModels`. `check-models` validates the union of all configured model ids.
- **Changed**: cli — translation runs print configured `uiModels` and per-locale `localeModels` tiers after the resolved fallback chain in the startup model summary.
- **Changed**: cli — `bench-models` accepts `--model <ids>` (comma-separated) to benchmark specific models instead of the configured list. When `--model` is passed, `translationModels` no longer needs to be set in config.
- **Changed**: cli — `bench-models` now benchmarks the union of `translationModels`, `uiModels`, and `localeModels` (deduplicated) instead of `translationModels` only; `check-models` already validated that full union.
- **Removed**: config — `ui.preferredModel` (use `providers.<active>.uiModels` instead).
- **Changed**: examples — `examples/astro-website` migrates from deprecated `@astrojs/tailwind` + Tailwind 3 to `@tailwindcss/vite` + Tailwind 4 so Astro 7 upgrades no longer hit the broken PostCSS peer path (`@astrojs/tailwind` only peers `astro ^3 || ^4 || ^5`). Removed the `peerDependencyRules.allowedVersions` workaround for `@astrojs/tailwind>astro` from `pnpm-workspace.yaml`.
- **Fixed**: lint — ignore `docs/**`, example `*.mts`, and `examples/**/.vitepress/cache/**` in ESLint so typed `recommendedTypeChecked` rules no longer crash on VitePress configs outside the package tsconfigs, and generated VitePress dep caches no longer flood lint with browser-globals errors (this had blocked root `ncu --doctor` during dependency upgrades).
- **Changed**: scripts — `upgrade-dependencies.sh` now fails closed on a preflight verify of every workspace package (skip with `UPGRADE_SKIP_PREFLIGHT=1`), treats doctor baseline failures as a non-zero exit, and fails on peer mismatches in CI / when `UPGRADE_STRICT_PEERS=1`. `detect_verify_cmd` also recognizes `docs:build` (VitePress), and `examples/vitepress-docs` gains a `build` script alias so doctor can verify it.
- **Added**: config - new `docsOutput.style: "vitepress"` alias (same layout as `doc-system` with empty `localeSubpath`; defaults `localePathLowercase` to `false` so BCP-47 folder names like `pt-BR` and `zh-Hans` are preserved) and `init -t ui-vitepress` starter template for VitePress documentation sites.
- **Added**: docs - comprehensive multi-language VitePress documentation site under `docs/` (GitHub Pages on release), replacing the monolithic `docs/GETTING_STARTED.md`, `docs/PACKAGE_OVERVIEW.md`, and `docs/LOCALE-ASSETS-GUIDE.md`; `README.md` remains the canonical landing copy synced into `docs/index.md` via `scripts/sync-readme-to-docs.mjs`.
- **Changed**: examples — `examples/vitepress-docs` now translates VitePress theme/nav/sidebar strings via `json[]` (`theme.en.json` → `theme.{locale}.json`), matching the main documentation site pattern instead of hard-coded labels in `config.mts`.
- **Changed**: scripts — root `i18n:*` npm scripts invoke `node bin/ai-i18n-tools.mjs` so `pnpm i18n:sync` works without a global CLI on `PATH`.
- **Changed**: docs — English documentation now covers VitePress throughout (integration guide, Workflow 2/3, configuration/CLI reference, examples index, images guide); `init -t ui-vitepress` template enables `translateJson` and scaffolds theme `json[]`.
- **Added**: processors — VitePress-aware markdown link normalizer (`src/processors/vitepress-link-normalize.ts`) runs during `translate-docs` when `docsOutput.rewriteVitepressLinks` is true or `docsOutput.vitepressLinks` is set (preset for `style: "vitepress"`). Rewrites README-style `docs/guide/…` paths to site routes (`/guide/…`), repo `examples/` folders to GitHub tree URLs, locale-relative `../guide/…` links to site routes, and homepage `./LICENSE` / `./README.md` links. `scripts/sync-readme-to-docs.mjs` uses the same normalizer when copying `README.md` → `docs/index.md`. Removed the standalone `scripts/fix-docs-links.mjs` workaround.
- **Changed**: examples — every folder under `examples/` now declares `"ai-i18n-tools": "^1.7.2"` (published semver) so it can be copied or cloned standalone (`npx degit wsj-br/ai-i18n-tools/examples/<name>`); monorepo contributors still get the local workspace copy via `ai-i18n-tools: workspace:*` in root `pnpm-workspace.yaml` `overrides`. Standalone fixtures (`multi-provider`, `test-markdown`) install the CLI as a dependency instead of invoking `node ../../bin/ai-i18n-tools.mjs`.
- **Added**: cli — new `bench-models` command (`src/cli/bench-models.ts`, registered in `src/cli/index.ts`) that benchmarks each configured translation model in isolation by translating one sample through a single-model `LlmClient` (no fallback chain). Models are benchmarked in parallel (bounded by config `concurrency`, default 4); each model still runs through its own single-model client so the reported time is that model's own wall-clock translation time. It prints a table of model id, input/output tokens, wall-clock translation time (`MM:SS.mmm`), and USD cost (`—` for providers that do not report cost, e.g. non-OpenRouter), plus a totals row and per-model failure details. Models default to the active provider's `translationModels` (override with `--models <ids>`); the sample defaults to a built-in English markdown block (override with `--text` / `--file`); source/target locales default to config `sourceLocale` and the first documentation target locale, falling back to the top-level `targetLocales` when no `docs[]` blocks are configured (override with `--source` / `--target`). Uses the document/markdown translate path (`translateDocumentSegment`).
- **Added**: cli — new `purge-locale` command (`src/cli/purge-locale.ts`, registered in `src/cli/index.ts`) that deletes all cached rows for one or more locales from the `translations`, `file_tracking`, and `translation_failures` tables, and (unless `--keep-files`) the locale's generated artifacts: translated documents (`.md` / `.mdx` / `.astro` outputs resolved from `docs[]` via `resolveTranslatedOutputPath`, unioned with an on-disk sweep of each block's output tree so orphaned outputs whose source was removed are also deleted — the sweep matches the `flat` filename suffix or the per-locale output directory, and is skipped for blocks with a custom `pathTemplate`), the per-locale flat UI file (`<ui.flatOutputDir>/<locale>.json`), and the locale's entries in `strings.json` (`translated`/`models` maps). Locales are passed via a repeatable `-l` / `--locale <code>` flag (normalized with `normalizeLocale`); it prints per-locale counts (cache rows, documents, `strings.json` entries, flat file), warns (does not error) for locales with nothing to purge, and prompts for confirmation unless `-y` / `--yes` / `-f` / `--force`. `--dry-run` reports counts and the files that would be removed without deleting; `--keep-files` purges only the SQLite cache; `--backup <path>` writes a SQLite backup before deletion (no backup unless set). Backed by a new `TranslationCache.countLocaleRows(locale)` helper (`src/core/cache.ts`) reusing the existing `clear(locale)` for deletion.
- **Fixed**: cli/docs — `sync` and the `translate-*` document/JSON commands now recreate a translated file when the destination is missing or older than its source, even when the source content hash is unchanged. Previously an unchanged (cache-hit) source was skipped as long as the output existed, so a translated file that had been deleted-then-restored stale, or whose source was touched/edited-and-reverted to identical bytes, would not be regenerated. A new `translatedOutputIsCurrent(outPath, sourceMtimeIso)` helper (`src/cli/helpers.ts`) replaces the prior `fs.existsSync(outPath)` skip guard in the markdown, Astro, JSON-doc, and SVG paths of `src/cli/doc-translate.ts` and in the nested-JSON path of `src/cli/translate-json-run.ts`; re-translation reuses the segment cache, so unchanged content costs no extra LLM calls.
- **Changed**: cli — renamed the `lint-source` command to `proofread-ui` for clarity (it AI-proofreads source-locale UI strings for spelling/grammar/terminology; the old name read like static code linting). This is a breaking change with no backward-compatible alias — the old `lint-source` name is removed. The implementation moved from `src/cli/lint-source.ts` to `src/cli/proofread-ui.ts` and its symbols/prompt identifiers were renamed accordingly (`runProofreadUI`, `ProofreadUIReport`, `buildProofreadUIPromptMessages`, `parseProofreadUIBatchResponse`, `LlmClient.proofreadUISourceBatch`, `PROMPTS.proofreadUI`, …). The results log is now `proofread-ui-results_<timestamp>.log`, console prefixes read `[proofread-ui]`, and `README.md` / `docs/GETTING_STARTED.md` / `docs/ai-i18n-tools-context.md` were updated. Source-text-keyed catalog entries change, so the affected UI strings re-translate on the next `pnpm i18n:self` run.
- **Fixed**: build — removed dead duplicate `src/api/openrouter.ts` and `src/cli/lint-source.ts`, which were still referencing renamed symbols (`LintSource*` → `ProofreadUI*`) and the obsolete top-level `config.openrouter` block removed in the multi-provider refactor; their orphaned test files (`tests/unit/openrouter.test.ts`, `tests/unit/lint-source.test.ts`) were also removed. The live implementations are `src/api/llm-client.ts` (re-exported as `OpenRouterClient`) and `src/cli/proofread-ui.ts`.
- **Fixed**: lint — added `references/**` to ESLint `ignores` so temporary external-reference snapshots (which may have missing dependencies) no longer break `pnpm run lint`. A new bracketed-title branch in `src/processors/admonition-placeholders.ts` masks only the directive prefix (`:::note[`) as `{{ADM_OPEN_n}}` and the trailing `]` / `{.attr}` remainder as `{{ADM_TCLOSE_n}}`, leaving the inner title text inline so it reaches the model (its own `**`/`_`/`` ` `` markup is handled by the downstream emphasis/inline-code protectors). The new `titleCloseMap` is threaded through `PlaceholderHandler.protectForTranslation`/`restoreAfterTranslation` (`src/processors/placeholder-handler.ts`), the empty-state shell in `src/cli/doc-translate.ts`, and the `ADM_(?:OPEN|END|TCLOSE)_\d+` leak guard in `src/processors/translation-placeholder-leaks.ts`. The legacy space form `:::note Title` continues to translate as before.
- **Added**: extractors/processors — nested admonitions (4+ colon fences, e.g. `:::::info[Parent]` wrapping `::::danger[Child]` wrapping `:::tip[Deep Child]`) are now supported. Openers are generalized from exactly `:::` to `:{3,}`, and the line scanner in `src/extractors/markdown-extractor.ts` tracks a colon-count depth stack so a whole nested block is captured as one translatable segment and round-trips exactly (exact colon counts preserved). Each opener's title is protected/translated by the same placeholder pass.
- **Added**: cli/check-markdown — malformed-admonition diagnostics. A new whole-file scanner (`collectMalformedAdmonitionIssues` in `src/processors/markdown-source-diagnostics.ts`) reports `ADMONITION_UNCLOSED` (opener with no closing fence), `ADMONITION_UNEXPECTED_CLOSE` (stray `:::`), and `ADMONITION_UNTERMINATED_TITLE` (`:::note[Title` with no `]`), skipping fenced code and YAML front matter. It is surfaced by `check-markdown` and the `translate-docs` source-issue refresh (`src/cli/check-markdown.ts`, `src/cli/doc-translate.ts`), written to `markdown_source_issues` with a deterministic synthetic `source_hash` (pruning is by filepath). The shared fence patterns now live in `src/processors/admonition-syntax.ts` so the extractor, placeholder protector, and diagnostics stay in sync.
