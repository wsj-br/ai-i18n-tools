# CLI 參考

|------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `version`                                                                                                  | 顯示 CLI 版本和建置時間戳記（與根程式的 `-V` / `--version` 相同資訊）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `init [-t ui-markdown\|ui-docusaurus\|ui-starlight\|ui-vitepress\|ui-nextra\|ui-astro-website\|ui-json-bundles] [-o path] [--with-translate-ignore]` | 寫入初始設定檔（包含 `concurrency`、`batchConcurrency`、`batchSize`、`maxBatchChars` 與 `docs[].addFrontmatter`）。`ui-vitepress` 會建立 VitePress 文件骨架（`docsOutput.style: "vitepress"`）以及主題字串用的 `vitepressThemeCatalog` — 全部置於 `translate-docs` 之內。`ui-nextra` 會建立 Nextra 文件骨架（`docsOutput.style: "nextra"`）以及主題字典用的 `nextraDictionaryPath`（側邊欄 `_meta.ts` 會自動收集）— 同樣置於 `translate-docs` 之內。`ui-json-bundles` 會建立 JSON 骨架（僅限 `json[]`）。`--with-translate-ignore` 會建立初始 `.translate-ignore`。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `check-models`                                                                                             | 將每個已設定的模型 ID 與作用中提供者的 `GET /models` 清單（成員資格和 `expiration_date`）進行驗證，需要該提供者的 API 金鑰（對於 Ollama 等無金鑰提供者則不需要），當任何已設定的 ID 遺失或過期時以非零值退出，並遵守提供者的 `requestTimeoutMs`。當提供者返回定價時（例如 OpenRouter），也會顯示每 100 萬個 token 的提示/完成費用（美元）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `list-models`                                                                                              | 列出作用中提供者透過其 `GET /models` 清單廣告的每個模型（按 ID 排序；作用中提供者遵循設定檔 `provider` 金鑰，可透過 `-P` / `--provider` 覆寫）。需要該提供者的 API 金鑰（對於 Ollama 等無金鑰提供者則不需要）。當提供者返回定價時（例如 OpenRouter），也會顯示每 100 萬個 token 的提示/完成費用（美元），並標記已過期的項目（`expiration_date`）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `bench-models [--model <ids>] [--text <text>\|--file <path>] [--source <locale>] [--target <locale>]` | 透過單獨翻譯一個樣本（單一模型客戶端，無後備鏈）來對每個已設定的模型進行基準測試。列印一個包含模型 ID、輸入/輸出權杖、實際翻譯時間以及 USD 成本（對於不報告成本的提供商為 `—`）的表格，外加一個總計列和每個模型的失敗情況。模型預設為當前提供商的 `translationModels`、`uiModels` 和 `localeModels` ID 的聯集（可用 `--model` 覆寫）；樣本預設為內建的英文 markdown 區塊（可用 `--text` / `--file` 覆寫）；來源/目標預設為設定中的 `sourceLocale` 和第一個 `docs[]` 目標語言環境，並回退到頂層的 `targetLocales`（可用 `--source` / `--target` 覆寫）。並行執行模型，受設定 `concurrency` 限制（預設為 4）；每個模型仍會單獨計時。需要當前提供商的 API 金鑰。 |
| `list-languages [search]`                                                                                  | 列出內建的使用者介面語言目錄（`data/ui-languages-complete.json`），顯示為人類可讀的表格（代碼、文字方向、英文名稱、原生名稱）；不需要設定檔或 API 金鑰。傳遞一個選擇性的 `search` 術語，以僅保留代碼、原生名稱、英文名稱或方向包含該術語的項目（不區分大小寫），例如 `list-languages portuguese`、`list-languages rtl`、`list-languages zh`。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `extract`                                                                                                  | 從 `t("…")` / `i18n.t("…")` 文字更新 `strings.json`，可選的 `package.json` 描述，以及可選的資訊清單 `englishName` 項目（請參閱 `ui.reactExtractor`）。當 `.html` / `.htm` 列在 `ui.uiExtractor.extensions` 中時，也會從 HTML 擷取 `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` 標記字串。需要非空的 `ui.sourceRoots`。不會呼叫 LLM。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `mark-html [paths...] [--write]`                                                                           | 將純粹的 `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` 標記插入 HTML，以便來源文字只編寫一次（在元素本身上）。掃描指定的檔案/目錄/glob（預設值：`.html` / `.htm` 在 `ui.sourceRoots` 下）。預設為模擬執行（報告每個檔案的新增計數以及任何需要手動 `<span data-i18n>` 的混合內容元素）；`--write` 會套用變更。此操作是冪等的，會尊重 `data-i18n-ignore`（跳過該元素及其子樹），永遠不會觸碰程式碼類元素（`code`、`pre`、`kbd`、`samp`、`var`）或僅包含數字的文字，且永遠不會發出有值的標記。不會呼叫 LLM。                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `generate-ui-languages [--master <path>] [--dry-run]` | 使用 `sourceLocale` + `targetLocales` 和捆綁的 `data/ui-languages-complete.json`（或 `--master`），將 `ui-languages.json` 寫入 `uiLanguagesPath` 中的路徑（必填）。對於主檔案中缺少的地區設定，會發出警告並產生 `TODO` 預留位置。如果您有包含自訂 `label` 或 `englishName` 值的現有清單，它們將被主目錄預設值取代 — 請在之後審閱並調整產生的檔案。 |
| `translate-docs …`                                                                                         | 翻譯 markdown、MDX、`.astro`、選用的 Docusaurus 目錄 JSON（`docusaurusCatalogDir`）、選用的 Nextra `_meta.ts`/字典 `.ts`，以及每個 `docs` 區塊的選用 VitePress 主題目錄。`-j`：最大並行語系數量；`-b`：每個檔案的最大並行批次 API 呼叫數。`--prompt-format`：批次傳輸格式（`xml` \| `json-array` \| `json-object`）。請參閱[快取行為與 `translate-docs` 旗標](/guide/documents/cli-options#cache-behaviour-and-translate-docs-flags)以及[批次提示格式](/guide/documents/cli-options#batch-prompt-format)。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `write-heading-ids …`                                                                                      | 至少需要一個 `docs[]` 區塊。在每個區塊的 `contentPaths` 下收集 `.md` / `.mdx`（遵守 `.translate-ignore`）。在每個平級 ATX `#` 標題的**正前方**插入 HTML anchor 行 `<a id="slug"></a>`（跳過圍在程式碼區塊內的標題）；如果 anchor 行已存在，則更新 `id`（如果它不再符合從目前標題文字衍生的 slug）。`-p` / `--path` 或 `-f` / `--file`：限制為專案相對路徑的檔案或目錄。`--slug-style`：`github`（預設值；doctoc / anchor-markdown-header）、`bitbucket`、`gitlab`、`pymdown`、`azure-devops`。使用 `pymdown` 時，可選 `--pymdown-case`、`--pymdown-normalize`、`--pymdown-percent-encode` / `--no-pymdown-percent-encode`。`--dry-run`：僅列出變更。                                                                                                                                                                                                                                                                                                                                    |
| `check-markdown …`                                                                                         | 掃描每個 `docs[]` 區塊的 `contentPaths` 下方的 markdown/MDX（與 `translate-docs` 相同，遵守 `.translate-ignore`）：分隔符配對、未關閉的內嵌程式碼，以及當 `**`/`__` 包裝 `[text](url)` 連結時的 `STRONG_OUTSIDE_LINK`。 `-p` / `--path` 或 `-f` / `--file`：可選範圍。將 `relativePath:line: [ISSUE_CODE] message` 行列印至 **stderr**；若有任何問題，則退出代碼為 **1**。 `--json`：在 **stdout** 上產生 JSON 報告。除非 `--no-cache`，否則將在 `cacheDir` 中寫入 `markdown_source_issues`。 `-v` 會將來源雜湊新增至 stderr 行。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `translate-svg …`                                                                                          | 翻譯 `config.svg` 中設定的 SVG 檔案（與文件分開）。需要 `features.translateSVG`。與文件相同的快取概念；支援 `--no-cache` 以略過該次執行的 SQLite 讀寫。 `-j`、`-b`、`--force`、`--force-update`、`-p` / `--path`、`--dry-run`。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `translate-ui [-l <codes>] [--force] [--dry-run] [-j <n>]` | 僅翻譯 UI 字串（`strings.json` → 地區設定 JSON）。`-l` / `--locale`：逗號分隔的目標地區設定（預設值：設定 `targetLocales` 減去 `sourceLocale`）。`--force`：重新翻譯每個地區設定的所有條目（忽略現有翻譯）。`--dry-run`：不寫入，不進行 API 呼叫。`-j`：最大平行地區設定數。需要 `features.translateUIStrings`。 |
| `translate-json …`                                                                                         | 根據 `json[]` 翻譯巢狀 JSON（需要 `features.translateJson`）。共用 SQLite 快取；`-l`、`-p` / `--path`、`--dry-run`、`--force`、`--force-update`、`-b`、`--prompt-format`。請參閱 [JSON](/guide/json)。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `sync-ui [-l <codes>] [--force] [--dry-run] [-j <n>]`                                                      | 提取，然後翻譯 UI 字串（需要 `features.translateUIStrings`）。僅限 UI — 無文件、SVG 或 `json[]`。與 `translate-ui` 具有相同的 `-l`、`--force`、`--dry-run` 和 `-j` 選項。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `proofread-ui [-l <code>] [--chunk <n>] [--dry-run] [--json] [-j <n>]`                                      | 執行 `extract` **首先**（需要 `features.translateUIStrings`）以使 `strings.json` 匹配來源，然後進行 LLM 審查 **來源語系** UI 字串（拼寫、語法）。**術語提示** 來自 `glossary.userGlossary` CSV（與 `translate-ui` 範圍相同 — 不是 `strings.json` / `uiGlossary`，因此不良複製不會被強化為詞彙）。使用活躍的 LLM 提供者（其 API 金鑰環境變數）。在失敗時退出 **1**（缺少功能標誌、提取失敗、缺少/無效目錄、缺少 API 金鑰，或當所有批次失敗時）；當執行完成成功時退出 **0**（發現是顧問）。在 `cacheDir` 下寫入 `proofread-ui-results_<timestamp>.log` 作為 **人類可讀** 報告（摘要、問題和每個字串 **OK** 列）；終端只列印摘要計數和問題（每個字串沒有 `[ok]` 列）。在最後一行列印記錄檔名稱。 `--json`：完整的機器可讀 JSON 報告只在 stdout 上；記錄檔保持人類可讀。 `--dry-run`：仍然執行 `extract`，然後只列印批次計劃（沒有 API 呼叫）。 `--chunk`：每個 API 批次的字串（預設 **50**）。 `-j`：最大平行批次（預設 `concurrency`）。使用 `--json` 時，人類風格的輸出轉到 stderr。連結使用 `path:line`，如同 `dashboard` UI 字串的「連結」按鈕。 |
| `export-ui-xliff [-l <codes>] [-o <dir>] [--untranslated-only] [--dry-run]`                                | 將 `strings.json` 匯出至 XLIFF 2.0（每個目標地區設定一個 `.xliff`）。`-o` / `--output-dir`：輸出目錄（預設值：與目錄相同的資料夾）。`--untranslated-only`：僅匯出該地區設定缺少翻譯的單元。唯讀；無 API。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `sync …` | 提取（如果啟用），然後是 UI 翻譯，然後在設定 `features.translateSVG` 和 `config.svg` 時進行 `translate-svg`，然後是文件翻譯，然後在設定 `features.translateJson` 和 `json[]` 時進行 `translate-json` — 除非使用 `--no-ui`、`--no-svg`、`--no-docs` 或 `--no-json` 跳過。共用旗標：`-l`、`-p` / `-f`、`--dry-run`、`-j`、`-b`（文件和 JSON 批次處理）、`--force` / `--force-update`。`--force` 會轉發到 UI 和 SVG 步驟以及文件/JSON；`--force-update` 適用於文件、JSON 和 SVG（不適用於 UI）。文件階段也會轉發 `--emphasis-placeholders` 和 `--debug-failed`（與 `translate-docs` 意義相同）。`--prompt-format` 不是 `sync` 旗標；文件和 JSON 步驟使用內建預設值（`json-array`）。 |
| `status [--max-columns <n>]` | 當 `features.translateUIStrings` 開啟時，會列印每個地區設定的 UI 覆蓋率（`Translated` / `Missing` / `Total`）。然後列印每個檔案 × 地區設定的 Markdown 翻譯狀態（無 `--locale` 過濾器；地區設定來自配置）。當 `features.translateJson` 開啟且 `json[]` 已配置時，也會列印每個區塊的 JSON 捆綁包狀態。大型地區設定列表會分割成重複的表格，最多包含 `n` 個地區設定欄位（預設 **9**），以便終端機中的行保持窄度。 |
| `statistics [--max-columns <n>]`                                                                           | 列印文件快取和 `strings.json` 統計資料（與翻譯儀表板 → **統計資料** 相同的彙總）。`--max-columns`：每個模型 × 語言環境表格的最大語言環境欄位數（預設為 **6**）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `cleanup [--dry-run] [--backup <path>]` | 清除整個 `markdown_source_issues` 表格，然後執行 `sync --force-update`（啟用時為擷取、UI、SVG、文件和 `translate-json`），以便目前設定的文件重新填入 Markdown 問題；然後移除過時的區段列（空 `last_hit_at` / 空檔案路徑）；刪除解析的來源路徑在磁碟上遺失的 `file_tracking` 列；移除其 `filepath` 中繼資料指向遺失檔案的翻譯列；修剪孤立的 `translation_failures` 列。同步後記錄四個修剪計數（過時區段、孤立 `file_tracking`、孤立翻譯、孤立失敗）以及預先的 Markdown 問題清除計數。`--backup <path>` 在修改前將 SQLite 備份寫入該路徑（除非設定此旗標，否則不備份）。 |
| `clean-temp [-r\|--root <path>] [-f\|--force] [--dry-run]` | **無設定。** 遍歷目錄樹（預設：目前工作目錄）以尋找 `*.log`、`*.tmp` 和 `cache.db.backup*.sqlite`，列印 `./…` 路徑，例如 `find -print`。如果匹配：提示 `Delete these files? (y/n)`，除非 `-f` / `--force`（不提示刪除）。如果沒有匹配：不提示退出。`--dry-run`：僅列出，不提示或刪除（覆寫 `--force`）。 |
| `purge-locale -l <code> [-l <code> …] [--dry-run] [-y\|--yes] [-f\|--force] [--keep-files] [--backup <path>]` | 從 `translations`、`file_tracking` 和 `translation_failures` 中刪除指定語言環境的所有快取行，**以及**該語言環境的生成工件：翻譯文件（從 `docs[]` 解析的 `.md` / `.mdx` / `.astro` 輸出，包括其來源已移除的孤立輸出 — 透過掃描每個區塊的輸出樹找到，除非配置了自訂 `pathTemplate`）、每個語言環境的平面 UI 檔案 (`<flatOutputDir>/<locale>.json`) 以及 `strings.json` 中該語言環境的條目。語言環境透過可重複的 `-l` / `--locale` 傳遞（正規化為 BCP-47）。列印每個語言環境的計數（快取行、文件、`strings.json` 條目、平面檔案）；對於沒有可清除內容的語言環境發出警告（不報錯）。除非 `-y` / `--yes` / `-f` / `--force`，否則會提示確認。`--dry-run`：報告計數和將被移除的檔案，不刪除任何內容。`--keep-files`：僅清除 SQLite 快取，保留生成的檔案和 `strings.json` 不變。除非傳遞了 `--backup <path>`，否則不會建立 SQLite 備份，該參數會在刪除前將備份寫入該路徑。 |
| `dashboard [-p <port>] [--no-open]`                                                                        | 啟動 Translation Dashboard（用於快取區段、`strings.json`、詞彙表、失敗和統計資料的本機網頁 UI）。預設連接埠為 **8675**（如果無法使用，則會嘗試下一個連接埠）。使用 `--no-open` 時，預設瀏覽器不會自動開啟。已淘汰的別名 `editor` 仍然可用，但會顯示警告。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `glossary-generate [-o <path>]`                                                                            | 寫入一個空的 `glossary-user.csv` 範本。`-o`：覆寫輸出路徑（預設：來自設定的 `glossary.userGlossary`，或 `glossary-user.csv`）。拒絕覆寫現有檔案（結束 **1**）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `help [command]`                                                                                           | 顯示子命令的說明（輸出與 `ai-i18n-tools <command> --help` 相同）。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

<a id="root-and-global-options"></a>
### 根目錄和全域選項

| 選項                       | 範圍         | 說明                                                                                      |
|------------------------------|---------------|-------------------------------------------------------------------------------------------|
| `-V` / `--version`           | 根程式碼  | 輸出版本號和建置時間戳記（與 `version` 子命令的資訊相同）。 |
| `-h` / `--help`              | 根程式  | 顯示根程式或與命令名稱一起使用的子命令的說明。      |
| `-c` / `--config <path>`     | 每個命令 | 設定檔路徑（預設值：`ai-i18n-tools.config.json`）。                                  |
| `-v` / `--verbose`           | 每個命令 | 詳細記錄。                                                                          |
| `-P` / `--provider <name>`   | 每個指令 | 此執行緒的活躍 LLM 提供者；會覆寫組態 `provider` 鍵。必須在 `providers` 下進行組態。 |
| `-L` / `--ui-lang <code>` | 所有命令 | 工具本身 UI 的語言（CLI 說明、日誌/摘要、儀表板）；最高優先級來源。請參閱[工具 UI 語言](/reference/environment-variables#tool-ui-language)。 |
| `-w` / `--write-logs [path]` | 選定的命令 | 將控制台輸出導向至 `.log` 檔案（預設路徑：在根目錄 `cacheDir` 下）。僅適用於 `translate-docs`、`translate-json`、`translate-svg`、`translate-ui`、`sync-ui`、`sync` 和 `cleanup`。 |

<a id="target-locales--l----locale"></a>
### 目標地區設定（`-l` / `--locale`）

| 命令 | 行為 |
|-----------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------|
| `translate-docs`、`translate-json`、`translate-svg`、`translate-ui`、`sync`、`sync-ui`、`export-ui-xliff` | `-l` / `--locale <codes>` — 以逗號分隔的目標 BCP-47 代碼（例如 `de,fr,pt-BR`）。省略時，預設值來自設定（`json[]` 區塊也可以設定每個區塊的 `targetLocales`；UI 步驟使用 `targetLocales` 減去 `sourceLocale`）。 |
| `proofread-ui`                                                                           | `-l` / `--locale <code>` — 要審核的單一來源語言（預設：設定檔 `sourceLocale`）。                                                            |
