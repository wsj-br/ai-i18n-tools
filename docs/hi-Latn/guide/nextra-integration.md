# Nextra integration

Next.js App Router par [Nextra](https://nextra.site/) 4 documentation sites ke liye `init -t ui-nextra` aur `docsOutput.style: "nextra"` ka upyog karein. Yeh preset ek alias hai `doc-system` ke liye jismein ek khaali `localeSubpath` aur BCP-47 locale folder ke naam surakshit rakhe gaye hain (`localePathLowercase` default roop se `false` hota hai, isliye folders `pt-BR`, `zh-Hans`, aadi bane rahte hain).

[Documents](/guide/documents/) aur chalne yogya [examples/nextra-docs](https://github.com/wsj-br/ai-i18n-tools/tree/main/examples/nextra-docs/) demo bhi dekhein.

<a id="quick-start"></a>
## Turant shuru karein

```bash
npx ai-i18n-tools init -t ui-nextra
# edit ai-i18n-tools.config.json (targetLocales, providers, contentPaths)
pnpm run i18n:sync   # or: ai-i18n-tools sync
pnpm run build       # Next.js build (project-specific script)
```

Jab aap page content, `_meta.ts` sidebar labels, aur theme dictionary modules ko ek `sync` run mein translate karte hain, tab `features.translateDocs` ko enable karein.

<a id="page-layout"></a>
## Page layout

i18n ke saath Nextra 4 **English source MDX ko ek locale folder ke andar rakhta hai** (aam taur par `content/en/`). Anuvadit copies sibling locale folders mein likhi jaati hain:

```text
content/en/index.mdx              →  content/pt-BR/index.mdx
content/en/guide/getting-started.mdx  →  content/zh-Hans/guide/getting-started.mdx
```

Ek `docs[]` block configure karein:

```json
{
  "contentPaths": ["content/en"],
  "outputDir": "content",
  "docsOutput": {
    "style": "nextra",
    "docsRoot": "content/en",
    "rewriteNextraLinks": true
  }
}
```

`contentPaths` ko apni English `.mdx` files aur directories par point karein. `docsRoot` ko `content/` ke andar English locale folder par set karein.

Nextra [internationalization](https://nextra.site/docs/guide/i18n) ko wire karein: `next.config` mein `i18n.locales` aur `defaultLocale` set karein, aur `ai-i18n-tools.config.json` mein `targetLocales` ko un locale codes aur `content/{locale}/` folder names ke saath align rakhein.

<a id="theme-strings"></a>
## Theme strings

Nextra theme chrome (`editLink`, search placeholder, footer, aur isi tarah) markdown se extract nahi kiya jaata hai. English strings ko ek TypeScript dictionary module mein likhein (jaise `app/_dictionaries/en.ts`) aur ise **`translate-docs`** ke andar translate karein:

```json
{
  "features": {
    "translateDocs": true
  },
  "docs": [
    {
      "contentPaths": ["content/en"],
      "outputDir": "content",
      "nextraDictionaryPath": "app/_dictionaries/en.ts",
      "docsOutput": {
        "style": "nextra",
        "docsRoot": "content/en"
      }
    }
  ]
}
```

Yeh tool `app/_dictionaries/{locale}.ts` likhta hai (default template: `{dir}/{locale}.ts`). `app/_dictionaries/get-dictionary.ts` mein per-locale module load karein aur anuvadit strings ko `<Layout>`, `<Search>`, `<Footer>`, aur sambandhit theme components ko pass karein.

Nextra theme dictionary strings ke liye `json[]` ka upyog **na karein** — yeh pattern sirf asambandhit app locale bundles ke liye hai.

<a id="sidebar-labels-_metats"></a>
## Sidebar labels (`_meta.ts`)

Nextra 3+ sidebar structure aur titles ke liye TypeScript `_meta.ts` / `_meta.tsx` files ka upyog karta hai. Jab `docsOutput.style` `"nextra"` hota hai, **`translate-docs`** automatically `_meta.ts`, `_meta.tsx`, aur `_meta.js` ko `docsRoot` ke niche collect karta hai, `export default { … }` meta map mein string literals ko translate karta hai, aur `content/{locale}/**` ke niche mirrored files likhta hai.

**Recommended pattern:** English literals ko `content/en/**/_meta.ts` mein inline rakhein (jaise [swr-site](https://github.com/shuding/nextra/tree/main/examples/swr-site)):

```text
content/en/_meta.ts           English sidebar labels (source)
content/pt-BR/_meta.ts        Translated copy (generated by translate-docs)
```

Vikalpik: `docs[].nextraMetaGlob` ke saath collection ko override karein ya `docs[].nextraMetaTranslatableKeys` ke saath translatable property names ko pratibandhit karein (default: `title`, `display`, `breadcrumb`).

JSON sidecars (`i18n/meta.en.json`) ya patli `_meta.ts` files jo anuvadit JSON import karti hain, unhe haath se **na likhein** — jab English badalta hai, tab `sync` / `translate-docs` ke saath locale `_meta` files ko regenerate karein.

<a id="framework-shell-translation"></a>
## Framework shell anuvaad

| Framework | Shell / theme strings | Pipeline |
|-----------|----------------------|----------|
| Docusaurus | `write-translations` catalog (`{ message, description }`) | Documents — `docs[].docusaurusCatalogDir` + `translate-docs` |
| VitePress | Theme/nav/sidebar catalog | Documents — `docsOutput.vitepressThemeCatalog` + `translate-docs` |
| Nextra | `_meta.ts` sidebar labels | Documents — auto jab `style: "nextra"` + `translate-docs` |
| Nextra | Theme dictionary `.ts` | Documents — `docs[].nextraDictionaryPath` + `translate-docs` |
| Astro Starlight | Built-in UI strings (kai sthaaneeya bhashaen); koi atirikt shell pipeline nahin | Dastavez — `translate-docs` (keval prishth) |

Framework shell/theme strings ko `json[]` mein **na** daalein — vah pipeline unrelated app locale bundles ke liye hai. Anya framework patterns ke liye [Docusaurus integration](/guide/docusaurus-integration) aur [VitePress integration](/guide/vitepress-integration) dekhein.

<a id="optional-t-hybrid"></a>
## Vaikalpik: `t()` for `app/` React (hybrid)

**Default:** `_meta.ts` / `_meta.tsx` object-literal strings ko **`translate-docs`** ke andar anuvadit kiya jaata hai — kisi `t()` ki aavashyakta nahin hai.

**Vaikalpik hybrid:** teams atirikt roop se `app/` layout chrome, custom MDX components, ya `_meta.tsx` labels ke liye **`t()` + `translate-ui`** ka upyog kar sakti hain jo keval JSX component bodies ke andar rahte hain (v1 mein object-literal extraction ke alava). Yah meta files ke liye translate-meta ko **nahin** badalta hai jab tak ki aap spasht roop se sidebar labels ko components mein refactor na karen.

| Content | Default pipeline | Vaikalpik vikalp |
|---------|------------------|----------------------|
| MDX page bodies | `translate-docs` | — |
| `_meta.ts` / `_meta.tsx` object titles | `translate-docs` | JSX (hybrid) mein `t()` mein refactor karen |
| `app/` layout, `_components/` | `nextraDictionaryPath` + dictionary `.ts` | `t()` + `translate-ui` |

**AI agent prompt ka udaharan** (jab layout chrome ko `t()` mein migrate kar rahe hon to Cursor ya kisi anya coding agent mein copy karen):

```markdown
Add i18n to our Nextra 4 app/ layout using ai-i18n-tools translate-ui (optional hybrid).

Context:
- We already translate MDX pages and _meta.ts via translate-docs (default).
- We want t() in app/[lang]/layout.tsx and app/_components/ for labels not covered by nextraDictionaryPath.
- English-as-key: t("Edit this page on GitHub") in source; strings.json + locales/{locale}.json from extract + translate-ui.
- Do not move _meta.ts sidebar labels into t() unless we explicitly ask — translate-docs handles _meta object literals.

Requirements:
1. Wire getRequestConfig / i18n provider for the app router locale param.
2. Replace hard-coded layout strings with t() calls; keep structure and Nextra theme APIs unchanged.
3. Enable features.translateUIStrings, set ui.sourceRoots to app/ (and mdx-components if needed).
4. Do not duplicate dictionary.ts strings that nextraDictionaryPath already translates — pick one approach per string.

After editing: run extract, translate-ui (or sync), verify en + one target locale in dev.
```

<a id="link-conventions"></a>
## Link conventions

Nextra Next.js `i18n` (`/guide/getting-started`, `/pt-BR/guide/getting-started`) ke madhyam se locale-prefixed routes serve karta hai. **In-page links locale-neutral rahne chahiye** (`/guide/getting-started`) taki Next.js active locale ko svachalit roop se prefix kar sake.

Built-in normalizer ko enable karein taaki `translate-docs` har translated file mein links ko automatically theek kar de:

```json
"docsOutput": {
  "style": "nextra",
  "docsRoot": "content/en",
  "rewriteNextraLinks": true
}
```

`rewriteNextraLinks` default roop se enable hota hai jab `style` `"nextra"` hota hai.

| Angrezi srot mein lekhak | Normalizer ke baad |
|--------------------------|------------------|
| `[Guide](content/en/guide/getting-started.mdx)` | `[Guide](/guide/getting-started)` |
| `[Guide](/guide/getting-started.mdx)` | `[Guide](/guide/getting-started)` |
| `[Demo](https://github.com/org/repo)` | aparivartit (poora URL) |

**Authoring rules**

- Cross-page doc links: Angrezi MDX mein **locale-neutral site routes** (`/guide/…`) ka upyog karen, ya `content/en/…` / relative `.mdx` paths ka upyog karen aur normalizer ko `sync` ke dauran unhen rewrite karne den.
- Content tree ke bahar repo files: **poore URLs** ka upyog karen.
- `content/<locale>/` mein links ko haath se edit **na** karen — `sync` / `translate-docs` ke saath punarutpann karen.

<a id="optional-locale-proxy"></a>
## Vaikalpik locale proxy

Nextra i18n sites ke liye ek locale-detection proxy pradan karta hai. Ise apne project root mein `proxy.ts` se export karen:

```ts
export { proxy } from 'nextra/locales'

export const config = {
  matcher: [
    '/((?!api|_next/static|_next/image|favicon.ico|icon.svg|apple-icon.png|manifest|_pagefind).*)',
  ],
}
```

**Site locale codes vs `sourceLocale`:** Nextra aur Next.js `next.config`, `content/{locale}/`, aur `NEXT_LOCALE` cookie mein short route codes (`en`, `pt-BR`, `zh-Hans`) ka upyog karte hain. `ai-i18n-tools.config.json` mein `sourceLocale` anuvad ki gunvatta ke liye BCP-47 tag ho sakta hai jaise `en-GB` — vah tag site route **nahin** hai. Yadi browser cookie ya `Accept-Language` `i18n.locales` ke bahar ke tag mein resolve hota hai (udaharan ke liye `en-GB` jab keval `en` configure kiya gaya ho), to Nextra ka stock proxy ek loop mein redirect kar sakta hai. [examples/nextra-docs](https://github.com/wsj-br/ai-i18n-tools/tree/main/examples/nextra-docs/) demo `nextra/locales` ko wrap karta hai taki invalid cookies aur paths ko default site locale par reset kiya ja sake isse pahle ki vah delegate kare.

Yah `output: 'export'` static exports ke saath kaam nahin karta hai. [Nextra i18n docs](https://nextra.site/docs/guide/i18n) dekhen.

[Configuration — `docsOutput`](/reference/configuration#docsoutput) aur [Output layouts](/guide/documents/output-layouts) bhi dekhen.
