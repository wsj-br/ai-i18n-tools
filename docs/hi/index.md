## सेटअप से आपकी पहली नई भाषा तक

<div class="home-steps">

1. **अपने प्रोजेक्ट को तैयार करें।** अपनी भाषाएँ, एक अनुवाद प्रोवाइडर और आज़माने के लिए मॉडल चुनें। ऐप्स के लिए, उपयोगकर्ता को दिखने वाले टेक्स्ट को मार्क करें और अनुवाद रनटाइम सेट अप करें। साइटों के लिए, अपने फ्रेमवर्क की भाषा रूटिंग को सक्षम करें। गाइड में कोडिंग-एजेंट प्रॉम्प्ट शामिल हैं जहाँ सोर्स में बदलाव की ज़रूरत होती है।
2. **ऐसी फ़ाइलों में अनुवाद करें जिनका आप इस्तेमाल कर सकते हैं।** सेटअप तैयार हो जाने के बाद, `sync` चलाएँ। यह समर्थित ऐप स्ट्रिंग्स निकालता है, आपके द्वारा सक्षम की गई सामग्री का अनुवाद करता है, और लोकेल फ़ाइलें या स्थानीय पेज लिखता है।
3. **लोड करें, जाँचें और आगे बढ़ते रहें।** आउटपुट को अपने ऐप या साइट से कनेक्ट करें, भाषा स्विचिंग को वायर करें और एक टारगेट भाषा की जाँच करें। नए या बदले हुए टेक्स्ट का अनुवाद करने के लिए सोर्स में बदलाव के बाद फिर से चलाएँ।

</div>

आप रनटाइम और रूटिंग सेटअप को मैन्युअल रूप से या कोडिंग एजेंट के साथ संभालते हैं। CLI निष्कर्षण, अनुवाद, सत्यापन और फ़ाइल जनरेशन को संभालता है—स्वचालित स्रोत पुनर्लेखन या भाषा-स्विचर इंस्टॉलेशन को नहीं। [पूर्ण त्वरित शुरुआत का पालन करें](/hi/guide/quick-start)।

## आपका स्रोत टेक्स्ट। अधिक भाषाओं के लिए तैयार।

यह JS/TS का उदाहरण, रनटाइम सेटअप और अनुवाद के बाद परिणाम का स्वरूप दिखाता है। सोर्स स्ट्रिंग को मार्क करने से उसे खोजा जा सकता है; हर जेनरेट की गई लोकेल फ़ाइल उस वाक्य को उसके अनुवाद से मैप करती है।

::: code-group

```js [Prepared source]
t("Save changes");
```

```json [Generated de.json]
{
  "Save changes": "Änderungen speichern"
}
```

```json [Generated pt-BR.json]
{
  "Save changes": "Salvar alterações"
}
```

```json [Generated zh-Hans.json]
{
  "Save changes": "保存更改"
}
```

:::

स्रोत वाक्य आपके कोड में पठनीय रहता है। आपका ऐप रनटाइम पर जेनरेट की गई लोकेल फ़ाइलों को लोड करता है। पूरी वायरिंग देखना चाहते हैं? [कार्यशील Next.js उदाहरण देखें](/hi/examples#nextjs-app)। वेबसाइटें एक अलग तरीका अपनाती हैं: हर पैराग्राफ को रैप करने के बजाय [स्थानीयकृत पृष्ठ जेनरेट करें](/hi/guide/add-i18n-to-website)।
