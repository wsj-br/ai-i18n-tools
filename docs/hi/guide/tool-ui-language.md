# टूल UI भाषा

`ai-i18n-tools` अपने स्वयं के यूज़र इंटरफ़ेस को स्थानीयकृत करता है — CLI सहायता टेक्स्ट, उच्च-ट्रैफ़िक लॉग/सारांश/त्रुटि संदेश, और अनुवाद डैशबोर्ड — आपके प्रोजेक्ट के `sourceLocale` / `targetLocales` से स्वतंत्र रूप से। किसी कॉन्फ़िगरेशन की आवश्यकता नहीं है: डिफ़ॉल्ट रूप से टूल आपके OS लोकेल का अनुसरण करता है।

<a id="locale-resolution"></a>
## लोकेल रिज़ॉल्यूशन

UI लोकेल इन स्रोतों से हल किया जाता है, उच्चतम प्राथमिकता पहले:

1. `-L` / `--ui-lang <code>` ग्लोबल फ़्लैग (उदाहरण के लिए `-L pt-BR`)।
2. `AI_I18N_LANG` पर्यावरण चर (उदाहरण के लिए `export AI_I18N_LANG=es`)।
3. `ai-i18n-tools.config.json` में `uiLanguage` कॉन्फ़िग कुंजी (BCP-47 स्ट्रिंग)।
4. होस्ट OS लोकेल (`Intl.DateTimeFormat().resolvedOptions().locale` के माध्यम से)।

<a id="matching-and-fallback"></a>
## मिलान और फ़ॉलबैक

अनुरोधित लोकेल को भेजे गए UI भाषाओं के साथ ठीक से या निकटतम भिन्नता से मिलान किया जाता है (उदाहरण के लिए `pt-PT` `pt-BR` में हल होता है, और `en-US` `en-GB` में हल होता है); जब कुछ भी मेल नहीं खाता है तो यह स्रोत लोकेल (`en-GB`) पर वापस आ जाता है। जब एक UI भाषा का स्पष्ट रूप से अनुरोध किया जाता है (फ़्लैग, env var, या `uiLanguage` के माध्यम से) लेकिन कोई भेजा गया बंडल मेल नहीं खाता है, तो CLI एक बार की चेतावनी प्रिंट करता है कि डिफ़ॉल्ट लोकेल का उपयोग किया जाएगा; होस्ट OS से अनुमानित लोकेल कभी चेतावनी नहीं देता है।

<a id="shipped-ui-languages"></a>
## भेजी गई UI भाषाएँ

अंग्रेज़ी (यूके, स्रोत), जर्मन, स्पैनिश, फ़्रेंच, हिंदी, जापानी, कोरियाई, पुर्तगाली (ब्राज़ील), चीनी (सरलीकृत), चीनी (पारंपरिक)।

<a id="translation-dashboard"></a>
## अनुवाद डैशबोर्ड

अनुवाद डैशबोर्ड `GET /api/ui-i18n` से हल किए गए लोकेल, लेआउट दिशा और अनुवाद बंडल को पढ़ता है और उन्हें लोड होने पर लागू करता है (यह `<html lang>` / `dir` सेट करता है और `data-i18n*` विशेषताओं के माध्यम से स्थिर मार्कअप को स्थानीयकृत करता है)।
