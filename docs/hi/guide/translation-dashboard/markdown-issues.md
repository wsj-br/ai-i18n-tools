# मार्कडाउन संबंधी समस्याएँ (स्थिर जाँच)

**मार्कडाउन संबंधी समस्याएँ** टैब `markdown_source_issues` SQLite तालिका से पंक्तियों को सूचीबद्ध करता है। प्रत्येक पंक्ति एक **पूर्व-अनुवाद** खोज है: उदाहरण के लिए, परिसीमन रन जो कभी भी CommonMark-शैली के नियमों के तहत जोर/स्ट्राइकथ्रू के रूप में युग्मित नहीं होते हैं, `translate-docs` मास्किंग के लिए उपयोग करता है, एक इनलाइन कोड स्पैन जो बैकटिक्स के साथ खोला गया है लेकिन कभी बंद नहीं हुआ है, या `STRONG_OUTSIDE_LINK` जब `**` / `__` एक `[text](url)` लिंक को रैप करते हैं (बोल्ड को केवल लिंक टेक्स्ट के अंदर रखें)।

यह **विफलताओं** के समान **नहीं** है, जो प्रति-स्थानिक मॉडल आउटपुट और अनुवाद-पश्चात सत्यापन समस्याओं (`AST mismatch`, प्लेसहोल्डर लीक, और इसी तरह) को रिकॉर्ड करता है।

<a id="when-to-use-it"></a>
## इसका उपयोग कब करें

इस टैब का उपयोग तब करें जब आप टोकन खर्च करने से पहले **स्रोत मार्कडाउन** को ठीक करना चाहते हैं — खासकर जब गुणवत्ता जाँच [विफलताएँ](/hi/guide/translation-dashboard/failures) टैब में संरचना पर विफल होती रहती हैं।

<a id="how-to-use-the-tab"></a>
## टैब का उपयोग कैसे करें

1. **सारांश** पट्टी पढ़ें — कुल समस्या पंक्तियाँ और प्रति समस्या कोड गणना।
2. फ़ाइलपाथ (`doc-block:{index}:` उपसर्गों सहित कैश कुंजी के विरुद्ध आंशिक मिलान), **समस्या कोड**, या **स्रोत हैश** द्वारा फ़िल्टर करें।
3. **फ़ाइलपाथ + पंक्ति** (डिफ़ॉल्ट) या **नवीनतम स्कैन समय** द्वारा सॉर्ट करें।
4. 🔗 लिंक बटन टर्मिनल पर फ़ाइल/पंक्ति संकेत लॉग करता है जहाँ `ai-i18n-tools dashboard` चल रहा है।

स्रोत फ़ाइल को ठीक करें, फिर अनुवाद को फिर से चलाएँ।

<a id="refreshing-rows"></a>
## पंक्तियों को ताज़ा करना

| कमांड / इवेंट | प्रभाव |
| --- | --- |
| `ai-i18n-tools check-markdown` | कॉन्फ़िगर किए गए दस्तावेज़ों को फिर से स्कैन करें; वैकल्पिक `-p` / `--path` स्कोप, `--no-cache`, `--json` |
| `translate-docs` (डिफ़ॉल्ट) | प्रत्येक मार्कडाउन फ़ाइल के लिए पंक्तियों को फिर से स्कैन करता है और बदलता है जब `docs[].warnMarkdownSourceIssues` `false` नहीं होता है |
| एक फ़ाइलपाथ के लिए सभी अनुवाद हटाएँ | उस फ़ाइलपाथ के लिए मार्कडाउन समस्या पंक्तियों को हटाता है (विफलताओं के समान सफाई) |
| `cleanup` | पूरी `markdown_source_issues` तालिका को साफ़ करता है, फिर पंक्तियों को फिर से भरने के लिए `sync --force-update` चलाता है |

<a id="common-issue-codes"></a>
## सामान्य समस्या कोड

| कोड | अर्थ |
| --- | --- |
| अयुग्मित जोर / स्ट्राइकथ्रू | परिसीमन रन जो CommonMark नियमों के तहत कभी बंद नहीं होते हैं |
| बंद न किया गया इनलाइन कोड | बैकटिक स्पैन खोला गया लेकिन बंद नहीं किया गया |
| `STRONG_OUTSIDE_LINK` | बोल्ड मार्कर एक मार्कडाउन लिंक को रैप करते हैं — बोल्ड को लिंक टेक्स्ट के अंदर ले जाएँ |

यह भी देखें [जटिल मार्कडाउन और विफल गुणवत्ता जाँच](/hi/guide/documents/#complex-markdown-and-failed-quality-checks)।
