# Intlayer का यथावत अनुवाद

[Intlayer](https://intlayer.org/) उन ऐप्लिकेशनों के लिए एक अच्छा समाधान है जो अनुवादों को टाइप किए गए सामग्री शब्दकोशों में रखते हैं, या जो अनुवाद प्रबंधन प्रणाली और मानव अनुवाद का उपयोग करते हैं। `translate-intlayer` उस दर्शक वर्ग के लिए है। यह आपके `*.content.ts` शब्दकोशों के अंदर छूटे हुए और पुराने लोकेल लीफ को यथास्थान भरता है। शब्दकोश सत्य का स्रोत बने रहते हैं, Intlayer रनटाइम पर रहता है, और ai-i18n-tools अनुवाद इंजन (प्रदाता चयन, शब्दावली, अनुवाद संदर्भ और मॉडल फ़ॉलबैक) के रूप में कार्य करता है।

<a id="keep-intlayer-or-move-to-source-string-calls"></a>
## Intlayer को बनाए रखें या स्रोत-स्ट्रिंग कॉल पर जाएँ?

| आपके दर्शक | कमांड | गाइड |
| --- | --- | --- |
| टाइप किए गए सामग्री शब्दकोश, एक अनुवाद प्रबंधन प्रणाली, या मानव अनुवाद। Intlayer रनटाइम पर रहता है। | `translate-intlayer` | यह पृष्ठ |
| स्रोत-स्ट्रिंग कॉल, `t('…')`, जिसमें स्रोत-भाषा का टेक्स्ट उस कोड के साथ रखा जाता है जो इसका उपयोग करता है। स्रोत भाषा कोई भी भाषा हो सकती है। | `migrate-intlayer` | [Intlayer से स्रोत-स्ट्रिंग कॉल में माइग्रेट करना](/hi/guide/migrating-from-intlayer) |

`translate-intlayer` एक चल रहा कार्य है जिसे आप जब भी स्रोत स्ट्रिंग जोड़ते हैं या मौजूदा स्ट्रिंग को संपादित करते हैं तो फिर से चलाते हैं। `migrate-intlayer` दूसरे दर्शक वर्ग के लिए एक बार का बदलाव है। प्रत्येक फिर से लिखी गई कॉल स्रोत-भाषा स्ट्रिंग को उस कोड के साथ ले जाती है जो इसका उपयोग करता है, जिससे रखरखाव सरल हो जाता है और उस कोड की जटिलता कम हो जाती है। वह भाषा `sourceLocale` है, और यह कोई भी भाषा हो सकती है।

<a id="what-translate-intlayer-does"></a>
## `translate-intlayer` क्या करता है

1. `*.content.ts` डिफ़ॉल्ट एक्सपोर्ट्स को पार्स करता है और हर `t({ locale: '…' })` लीफ को इकट्ठा करता है। स्थानीय मान सामान्य स्ट्रिंग या इंटलेयर `insert('…')` इंसर्शन नोड हो सकते हैं।
2. UI ब्लॉक के `ui.stringsJson` को स्रोत पाठ से भरता है, फिर गायब और पुरानी स्थानीय भाषाओं के लिए [`translate-ui`](/hi/reference/cli-commands/ui-strings#translate-ui) जैसा ही इंजन चलाता है।
3. नई प्रति-स्थानीय स्ट्रिंग को प्रत्येक `t({ … })` ऑब्जेक्ट में वापस लिखता है। संपादन सटीक होते हैं: केवल गायब या पुरानी स्थानीय पंक्तियाँ बदलती हैं, इसलिए आपका स्वरूपण, कुंजी क्रम और टिप्पणियाँ संरक्षित रहती हैं। मौजूदा अनुवाद वैसे ही छोड़े जाते हैं जैसे वे लिखे गए थे। जब कोई लीफ `insert('…')` का उपयोग करती है, तो नए स्थानीय मान भी `insert(…)` में लपेटे जाते हैं, ताकि लीफ रनटाइम पर कॉल करने योग्य बनी रहे।
4. प्लेसहोल्डर को संरक्षित रखता है। इंटलेयर का इंसर्शन सिंटैक्स <code v-pre>{{token}}</code> अपरिवर्तित रूप से पास किया जाता है। एकल-ब्रेकेट `{token}` प्लेसहोल्डर भी समर्थित हैं: वे अनुवाद के लिए <code v-pre>{{token}}</code> बन जाते हैं और लिखने पर `{token}` पर वापस आ जाते हैं।
5. `--dry-run` के साथ ड्राई रन करें: यह LLM को कॉल किए बिना या कुछ भी लिखे बिना छूटे हुए/पुराने काउंट की रिपोर्ट करता है।

<a id="missing-vs-stale"></a>
## छूटे हुए बनाम पुराने

एक लीफ + लोकेल का अनुवाद तब किया जाता है जब:

- लोकेल लीफ से अनुपस्थित है (छूटा हुआ), या
- उस लोकेल के लिए पिछली बार चलाने के बाद से स्रोत-लोकेल टेक्स्ट बदल गया है (पुराना)। स्रोत भाषा `sourceLocale` है और कोई भी भाषा हो सकती है।

`cacheDir` में प्रति लीफ के अनुसार पुरानापन ट्रैक किया जाता है, इसलिए एक अंग्रेजी स्ट्रिंग को संपादित करने से अगली बार चलाने पर केवल वही लीफ फिर से अनुवादित होती है; बाकी सब कुछ कैश में रहता है। एक अनुवाद जो पहली बार चलाने पर पहले से ही पुराना था, उसे वर्तमान के रूप में स्वीकार किया जाता है — केवल बाद के संपादन ही उसे पुराना चिह्नित करते हैं।

<a id="translate-your-project"></a>
## अपनी परियोजना का अनुवाद करें

1. `ai-i18n-tools` इंस्टॉल करें ([इंस्टॉलेशन](/hi/guide/installation) देखें)। यदि आपके प्रोजेक्ट में अभी तक कोई `ai-i18n-tools.config.json` नहीं है, तो एक स्केफोल्ड करें:

   ```bash
   ai-i18n-tools init -P gemini
   ```

`sourceLocale` और `targetLocales` को उन लोकेल पर सेट करें जिनका आपके शब्दकोश उपयोग करते हैं, और `ui.sourceRoots`, `ui.stringsJson`, और `ui.flatOutputDir` को अपने स्रोत और एक कैटलॉग पथ पर इंगित करें — वही कुंजियाँ जिनका `translate-ui` उपयोग करता है, [UI स्ट्रिंग — चरण 1: आरंभ करें](/hi/guide/ui-strings/#step-1-initialise) देखें। कैटलॉग एक स्क्रैच डायरेक्टरी (उदाहरण के लिए `.i18n/`) में रह सकता है; इसका उपयोग अनुवाद कैश के रूप में किया जाता है और आप इसे कभी भी मैन्युअल रूप से संपादित नहीं करते हैं।
2. पहले यह देखने के लिए ड्राई रन करें कि क्या भरा जाएगा:

   ```bash
   ai-i18n-tools translate-intlayer src --dry-run
   ```

3. इसे लागू करें (एक प्रदाता API कुंजी की आवश्यकता है):

   ```bash
   ai-i18n-tools translate-intlayer src
   ```

4. जब भी आप कोई नई स्ट्रिंग जोड़ें या किसी अंग्रेजी स्ट्रिंग को संपादित करें तो फिर से चलाएँ। केवल नई या बदली हुई लीफ का अनुवाद किया जाता है। आवश्यकता पड़ने पर `-l de,fr` या `--ui-block` के साथ एक रन को स्कोप करें।

<a id="run-the-example"></a>
## उदाहरण चलाएँ

[intlayer-translate](https://github.com/wsj-br/ai-i18n-tools/tree/main/examples/intlayer-translate) उदाहरण एक छोटा Vite + React ऐप है जिसके शब्दकोश अंग्रेजी और ब्राज़ीलियाई पुर्तगाली के साथ आते हैं; स्पेनिश और सरलीकृत चीनी जानबूझकर गायब हैं। `pristine/` एक रीड-ओनली संदर्भ है; `src/` कार्यशील प्रति है। `pnpm reset` `src/` को उस प्रारंभिक स्थिति में लौटाता है (और कैटलॉग और कैश को साफ़ करता है) ताकि आप अभ्यास दोहरा सकें।

```bash
npx degit wsj-br/ai-i18n-tools/examples/intlayer-translate intlayer-translate
cd intlayer-translate
pnpm install
pnpm reset
pnpm translate:dry
pnpm translate
```

`pnpm dev` `http://localhost:3093` पर ऐप चलाता है। अनुवाद करने से पहले लोकेल को `es` या `zh-Hans` पर स्विच करें और स्ट्रिंग अंग्रेज़ी में वापस आ जाती हैं; `pnpm translate` के बाद भरे हुए अनुवाद दिखाई देते हैं। एक अंग्रेज़ी स्ट्रिंग संपादित करें और केवल उस लीफ को रीफ़्रेश होते देखने के लिए `pnpm translate` को फिर से चलाएँ।

पूर्ण विवरण: [examples/intlayer-translate/README.md](https://github.com/wsj-br/ai-i18n-tools/blob/main/examples/intlayer-translate/README.md).

<a id="command"></a>
## कमांड

```bash
ai-i18n-tools translate-intlayer [paths...] [-l <codes>] [--ui-block <selector>] [--dry-run] [-j <n>]
```

`features.translateUIStrings` और UI ब्लॉक के `ui.stringsJson` (`translate-ui` के समान) की आवश्यकता है। `--dry-run` किसी LLM को कॉल नहीं करता है।

| विकल्प | अर्थ |
| --- | --- |
| `[paths...]` | स्कैन करने के लिए फ़ाइलें/डिर/ग्लोब (डिफ़ॉल्ट: `ui.sourceRoots`) |
| `-l`, `--locale <codes>` | भरने के लिए कॉमा-सेपरेटेड लक्ष्य लोकले (डिफ़ॉल्ट: ब्लॉक का `targetLocales`) |
| `--ui-block <selector>` | UI ब्लॉक: शून्य-आधारित इंडेक्स, विवरण, या `stringsJson` पाथ (डिफ़ॉल्ट: ब्लॉक 0) |
| `--dry-run` | केवल गुम/पुरानी गणनाओं की रिपोर्ट करें; कोई LLM कॉल नहीं, कोई राइट्स नहीं |
| `-j`, `--concurrency <n>` | अधिकतम समानांतर लक्ष्य लोकले (डिफ़ॉल्ट: कॉन्फ़िग `concurrency` या 4) |

**यह भी देखें:** [CLI — UI स्ट्रिंग](/hi/reference/cli-commands/ui-strings#translate-intlayer), [इंटलेयर से स्रोत-स्ट्रिंग कॉल में माइग्रेट करना](/hi/guide/migrating-from-intlayer)
