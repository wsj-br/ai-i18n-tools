# CLI 참조

| 명령                                                                                                    | 설명                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `version`                                                                                                  | CLI 버전 및 빌드 타임스탬프 출력 (루트 프로그램의 `-V` / `--version`와 동일한 정보).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `init [-t ui-markdown\|ui-docusaurus\|ui-starlight\|ui-vitepress\|ui-nextra\|ui-astro-website\|ui-json-bundles] [-o path] [--with-translate-ignore]` | 시작 구성 파일을 작성합니다(`concurrency`, `batchConcurrency`, `batchSize`, `maxBatchChars`, `docs[].addFrontmatter` 포함). `ui-vitepress`는 VitePress 문서(`docsOutput.style: "vitepress"`)와 테마 문자열용 `vitepressThemeCatalog`을 모두 `translate-docs` 내에 스캐폴드합니다. `ui-nextra`은 Nextra 문서(`docsOutput.style: "nextra"`)와 테마 사전용 `nextraDictionaryPath`를 스캐폴드합니다(사이드바 `_meta.ts`은 자동으로 수집됨). 이 또한 `translate-docs` 내에 있습니다. `ui-json-bundles`는 JSON(`json[]`만)을 스캐폴드합니다. `--with-translate-ignore`은 시작 `.translate-ignore`을 생성합니다. |
| `check-models`                                                                                             | 구성된 각 모델 ID를 활성 공급자의 `GET /models` 목록(멤버십 및 `expiration_date`)과 대조하여 검증합니다. 해당 공급자의 API 키가 필요합니다(Ollama와 같은 키리스 공급자는 필요 없음). 구성된 ID가 누락되었거나 만료된 경우 0이 아닌 값으로 종료하며, 공급자의 `requestTimeoutMs`을 존중합니다. 공급자가 가격(예: OpenRouter)을 반환하는 경우 프롬프트/완료에 대한 100만 토큰당 USD도 표시합니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `list-models`                                                                                              | 활성 공급자가 `GET /models` 목록을 통해 광고하는 모든 모델을 나열합니다(ID별로 정렬됨. 활성 공급자는 구성 `provider` 키를 따르며, `-P` / `--provider`로 재정의할 수 있음). 해당 공급자의 API 키가 필요합니다(Ollama와 같은 키리스 공급자는 필요 없음). 공급자가 가격(예: OpenRouter)을 반환하는 경우 프롬프트/완료에 대한 100만 토큰당 USD도 표시하고, `expiration_date` 이후의 항목을 태그합니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `bench-models [--model <ids>] [--text <text>\|--file <path>] [--source <locale>] [--target <locale>]` | 단일 모델 클라이언트, 대체 체인 없음)에서 단일 샘플을 번역하여 구성된 각 모델을 벤치마킹합니다. 모델 ID, 입력/출력 토큰, 실제 번역 시간, USD 비용(비용을 보고하지 않는 공급자의 경우 `—`) 테이블과 총계 행 및 모델별 실패를 출력합니다. 모델은 활성 공급자의 `translationModels`, `uiModels`, `localeModels` ID의 통합으로 기본 설정됩니다(`--model`로 재정의); 샘플은 내장된 영어 마크다운 블록으로 기본 설정됩니다(`--text` / `--file`로 재정의); 소스/대상은 구성 `sourceLocale` 및 첫 번째 `docs[]` 대상 로케일로 기본 설정되며, 최상위 `targetLocales`으로 대체됩니다(`--source` / `--target`로 재정의). 구성 `concurrency`(기본값 4)에 따라 병렬로 모델을 실행합니다. 각 모델은 개별적으로 시간이 측정됩니다. 활성 공급자의 API 키가 필요합니다. |
| `list-languages [search]`                                                                                  | 번들 UI 언어 카탈로그(`data/ui-languages-complete.json`)를 사람이 읽을 수 있는 테이블(코드, 텍스트 방향, 영어 이름, 네이티브 이름)로 나열합니다. 구성이나 API 키가 필요하지 않습니다. 선택적으로 `search` 용어를 전달하여 코드, 네이티브 이름, 영어 이름 또는 방향에 해당 용어를 포함하는 항목만 유지합니다(대소문자 구분 없음). 예: `list-languages portuguese`, `list-languages rtl`, `list-languages zh`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `extract`                                                                                                  | `t("…")` / `i18n.t("…")` 리터럴, 선택적 `package.json` 설명 및 선택적 매니페스트 `englishName` 항목(참조 `ui.reactExtractor`)에서 `strings.json` 업데이트. `.html` / `.htm`이 `ui.uiExtractor.extensions`에 나열된 경우 HTML에서 `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` 마커 문자열도 캡처합니다. 비어 있지 않은 `ui.sourceRoots`이 필요합니다. LLM을 호출하지 않습니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `mark-html [paths...] [--write]`                                                                           | HTML에 원시 `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` 마커를 삽입하여 소스 텍스트를 한 번만 작성합니다(요소 자체에). 지정된 파일/디렉토리/글롭을 스캔합니다(기본값: `.html` / `.htm` `ui.sourceRoots` 아래). 기본적으로 드라이런(파일별 추가 수 및 수동 `<span data-i18n>`이 필요한 혼합 콘텐츠 요소 보고); `--write`은 변경 사항을 적용합니다. 멱등성이 있으며 `data-i18n-ignore`을 존중하여(요소 및 하위 트리 건너뜀) 코드와 유사한 요소(`code`, `pre`, `kbd`, `samp`, `var`) 또는 비어 있거나 숫자만 있는 텍스트는 절대 건드리지 않으며, 값이 있는 마커는 절대 내보내지 않습니다. LLM을 호출하지 않습니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `generate-ui-languages [--master <path>] [--dry-run]` | `sourceLocale` + `targetLocales` 및 번들로 제공되는 `data/ui-languages-complete.json`(또는 `--master`)를 사용하여 `uiLanguagesPath`의 경로에 `ui-languages.json`을(를) 씁니다(필수). 마스터 파일에 없는 로케일에 대해 경고하고 `TODO` 자리 표시자를 내보냅니다. 사용자 지정된 `label` 또는 `englishName` 값이 포함된 기존 매니페스트가 있는 경우 마스터 카탈로그 기본값으로 대체됩니다. 생성된 파일을 검토하고 나중에 조정하세요. |
| `translate-docs …` | 마크다운, MDX, `.astro`, 선택적 Docusaurus 카탈로그 JSON(`docusaurusCatalogDir`), 선택적 Nextra `_meta.ts`/사전 `.ts`, 각 `docs` 블록에 대한 선택적 VitePress 테마 카탈로그를 번역합니다. `-j`: 최대 병렬 로케일; `-b`: 파일당 최대 병렬 배치 API 호출. `--prompt-format`: 배치 와이어 형식(`xml` \| `json-array` \| `json-object`). [캐시 동작 및 `translate-docs` 플래그](/guide/documents/cli-options#cache-behaviour-and-translate-docs-flags) 및 [배치 프롬프트 형식](/guide/documents/cli-options#batch-prompt-format)을 참조하십시오. |
| `write-heading-ids …`                                                                                      | 최소한 하나의 `docs[]` 블록이 필요합니다. 각 블록의 `contentPaths` 아래에 있는 `.md` / `.mdx`를 수집합니다(`.translate-ignore` 적용). 평면 ATX `#` 제목 바로 **앞**에 HTML 앵커 줄 `<a id="slug"></a>`을 삽입합니다(_fence 코드 블록 내부의 제목은 건너뜀); 이미 앵커 줄이 있는 경우, 현재 제목 텍스트에서 유도된 slug와 일치하지 않으면 `id`을 업데이트합니다. `-p` / `--path` 또는 `-f` / `--file`: 프로젝트 기준 파일 또는 디렉터리로 제한. `--slug-style`: `github`(기본값; doctoc / anchor-markdown-header), `bitbucket`, `gitlab`, `pymdown`, `azure-devops`. `pymdown` 사용 시, 선택적 `--pymdown-case`, `--pymdown-normalize`, `--pymdown-percent-encode` / `--no-pymdown-percent-encode` 가능. `--dry-run`: 변경 사항만 나열합니다.                                                                                                                                                                                                                                                                                                                                    |
| `check-markdown …`                                                                                         | 각 `docs[]` 블록의 `contentPaths` 아래 마크다운/MDX를 스캔합니다(`translate-docs`과 동일한 탐지 방식, `.translate-ignore` 적용): 구분자 쌍, 닫히지 않은 인라인 코드, `STRONG_OUTSIDE_LINK`에서 `**`/`__`가 `[text](url)` 링크를 감쌀 때. `-p` / `--path` 또는 `-f` / `--file`: 선택적 범위. **stderr**에 `relativePath:line: [ISSUE_CODE] message` 줄을 출력합니다. 문제가 하나라도 있으면 종료 코드 **1**. `--json`: **stdout**에 JSON 보고서 출력. `--no-cache`이 아닌 경우 `cacheDir`에 `markdown_source_issues`를 작성합니다. `-v`은 stderr 줄에 소스 해시를 추가합니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `translate-svg …`                                                                        | `config.svg`에 구성된 SVG 파일을 번역합니다(문서와 별도). `features.translateSVG`가 필요합니다. 문서와 동일한 캐시 방식을 사용하며, 해당 실행에서 SQLite 읽기/쓰기를 건너뛰기 위해 `--no-cache`를 지원합니다. `-j`, `-b`, `--force`, `--force-update`, `-p` / `--path`, `--dry-run`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `translate-ui [-l <codes>] [--force] [--dry-run] [-j <n>]` | UI 문자열만 번역합니다(`strings.json` → 로케일 JSON). `-l` / `--locale`: 쉼표로 구분된 대상 로케일(기본값: 구성 `targetLocales`에서 `sourceLocale` 제외). `--force`: 로케일당 모든 항목을 다시 번역합니다(기존 번역 무시). `--dry-run`: 쓰기 없음, API 호출 없음. `-j`: 최대 병렬 로케일. `features.translateUIStrings`가 필요합니다. |
| `translate-json …`                                                                                         | `json[]`에 따라 중첩된 JSON을 번역합니다(`features.translateJson` 필요). 공유 SQLite 캐시; `-l`, `-p` / `--path`, `--dry-run`, `--force`, `--force-update`, `-b`, `--prompt-format`. [JSON](/guide/json)을 참조하세요.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `sync-ui [-l <codes>] [--force] [--dry-run] [-j <n>]`                                                      | UI 문자열을 추출한 후 번역합니다(`features.translateUIStrings` 필요). UI 전용 — 문서, SVG 또는 `json[]`는 포함되지 않음. `translate-ui`과 동일한 `-l`, `--force`, `--dry-run`, `-j` 옵션 사용.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `proofread-ui [-l <code>] [--chunk <n>] [--dry-run] [--json] [-j <n>]` | `extract`를 **먼저** 실행하고(`features.translateUIStrings` 필요) `strings.json`가 소스와 일치하도록 한 다음, **소스 로캘** UI 문자열(철자, 문법)에 대한 LLM 검토를 실행합니다. **용어 힌트**는 `glossary.userGlossary` CSV에서만 가져옵니다(`translate-ui`와 동일한 범위 — `strings.json`/`uiGlossary`는 아니므로 잘못된 복사본이 용어로 강화되지 않습니다). 활성 LLM 공급자(API 키 환경 변수)를 사용합니다. 실패 시 **1**로 종료됩니다(누락된 기능 플래그, 추출 실패, 누락/잘못된 카탈로그, 누락된 API 키 또는 모든 배치가 실패한 경우). 실행이 성공적으로 완료되면 **0**으로 종료됩니다(결과는 권고 사항임). `cacheDir` 아래에 `proofread-ui-results_<timestamp>.log`을 **사람이 읽을 수 있는** 보고서(요약, 문제 및 문자열별 **OK** 행)로 작성합니다. 터미널은 요약 개수 및 문제만 인쇄합니다(문자열당 `[ok]` 행 없음). 마지막 줄에 로그 파일 이름을 인쇄합니다. `--json`: 표준 출력에만 전체 기계 판독 가능한 JSON 보고서(로그 파일은 사람이 읽을 수 있는 상태로 유지됨). `--dry-run`: 여전히 `extract`을 실행한 다음 배치 계획만 인쇄합니다(API 호출 없음). `--chunk`: API 배치당 문자열 수(**50**이 기본값). `-j`: 최대 병렬 배치 수(`concurrency`이 기본값). `--json`을 사용하면 사람이 읽을 수 있는 출력이 표준 오류로 이동합니다. 링크는 `dashboard` UI 문자열의 “링크” 버튼처럼 `path:line`을 사용합니다. |
| `export-ui-xliff [-l <codes>] [-o <dir>] [--untranslated-only] [--dry-run]`              | XLIFF 2.0으로 `strings.json` 내보내기 (대상 로캘당 `.xliff` 하나씩). `-o` / `--output-dir`: 출력 디렉터리 (기본값: 카탈로그와 동일한 폴더). `--untranslated-only`: 해당 로캘에서 번역이 누락된 항목만. 읽기 전용; API 없음.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `sync …` | (활성화된 경우) 추출, UI 번역, `features.translateSVG` 및 `config.svg`이 설정된 경우 `translate-svg`, 문서 번역, `features.translateJson` 및 `json[]`이 설정된 경우 `translate-json` 순으로 진행됩니다. 단, `--no-ui`, `--no-svg`, `--no-docs` 또는 `--no-json`으로 건너뛸 수 있습니다. 공유 플래그: `-l`, `-p` / `-f`, `--dry-run`, `-j`, `-b`(문서 및 JSON 배치), `--force` / `--force-update`. `--force`는 UI 및 SVG 단계뿐만 아니라 문서/JSON으로 전달됩니다. `--force-update`은 문서, JSON 및 SVG에 적용됩니다(UI에는 적용되지 않음). 문서 단계는 `--emphasis-placeholders` 및 `--debug-failed`도 전달합니다(`translate-docs`과 동일한 의미). `--prompt-format`는 `sync` 플래그가 아닙니다. 문서 및 JSON 단계는 내장된 기본값(`json-array`)을 사용합니다. |
| `status [--max-columns <n>]` | `features.translateUIStrings`이 켜져 있으면 로캘별 UI 적용 범위(`Translated` / `Missing` / `Total`)를 인쇄합니다. 그런 다음 파일 × 로캘별 마크다운 번역 상태를 인쇄합니다(`--locale` 필터 없음, 로캘은 구성에서 가져옴). `features.translateJson`이 켜져 있고 `json[]`이 구성되어 있으면 블록별 JSON 번들 상태도 인쇄합니다. 큰 로캘 목록은 최대 `n`개 로캘 열(**9**가 기본값)로 반복되는 테이블로 분할되어 터미널에서 줄이 좁게 유지됩니다. |
| `statistics [--max-columns <n>]`                                                                           | 문서 캐시 및 `strings.json` 통계를 출력합니다(번역 대시보드 → **통계**와 동일한 집계). `--max-columns`: 모델당 최대 로케일 열 수 × 로케일 테이블(기본값 **6**).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `cleanup [--dry-run] [--backup <path>]` | 전체 `markdown_source_issues` 테이블을 지운 다음 `sync --force-update`(활성화된 경우 추출, UI, SVG, 문서 및 `translate-json`)를 실행하여 현재 구성된 문서에 대한 마크다운 문제가 다시 채워지도록 합니다. 그런 다음 오래된 세그먼트 행(null `last_hit_at` / 빈 파일 경로)을 제거하고, 해결된 소스 경로가 디스크에 없는 `file_tracking` 행을 삭제하고, `filepath` 메타데이터가 누락된 파일을 가리키는 번역 행을 제거하고, 고아 `translation_failures` 행을 정리합니다. 동기화 후 4개의 정리 횟수(오래된 세그먼트, 고아 `file_tracking`, 고아 번역, 고아 실패)와 선행 마크다운 문제 지우기 횟수를 기록합니다. `--backup <path>`는 수정 전에 해당 경로에 SQLite 백업을 기록합니다(이 플래그가 설정되지 않으면 백업 없음). |
| `clean-temp [-r\|--root <path>] [-f\|--force] [--dry-run]` | **구성 없음.** 디렉터리 트리(기본값: 현재 작업 디렉터리)를 `*.log`, `*.tmp`, `cache.db.backup*.sqlite`에 대해 탐색하고, `find -print`와 같은 `./…` 경로를 출력합니다. 일치하는 항목이 있는 경우: `-f` / `--force` (프롬프트 없이 삭제)가 아니면 `Delete these files? (y/n)` 프롬프트를 표시합니다. 일치하는 항목이 없는 경우: 프롬프트 없이 종료합니다. `--dry-run`: 목록만 표시하고 프롬프트 또는 삭제는 하지 않습니다(`--force` 재정의). |
| `purge-locale -l <code> [-l <code> …] [--dry-run] [-y\|--yes] [-f\|--force] [--keep-files] [--backup <path>]` | `translations`, `file_tracking`, `translation_failures`에서 지정된 로캘의 모든 캐시된 행을 삭제**하고** 해당 로캘에 대해 생성된 아티팩트를 삭제합니다. 삭제 대상에는 번역된 문서(`pathTemplate`이 별도로 구성되지 않은 경우 각 블록의 출력 트리를 스캔하여 찾은 `docs[]` 기반의 `.md` / `.mdx` / `.astro` 출력물 및 소스가 제거된 고립된 출력물 포함), 로캘별 플랫 UI 파일(`<flatOutputDir>/<locale>.json`), `strings.json` 내의 로캘 항목이 포함됩니다. 로캘은 반복 가능한 `-l` / `--locale`를 통해 전달됩니다(BCP-47로 정규화됨). 로캘별 개수(캐시 행, 문서, `strings.json` 항목, 플랫 파일)를 출력하며, 삭제할 항목이 없는 로캘에 대해서는 오류 대신 경고를 표시합니다. `-y` / `--yes` / `-f` / `--force` 옵션이 없는 경우 확인 프롬프트를 표시합니다. `--dry-run`: 삭제될 파일과 개수만 보고하고 실제로는 삭제하지 않습니다. `--keep-files`: SQLite 캐시만 삭제하고 생성된 파일과 `strings.json`은 그대로 둡니다. `--backup <path>`이 전달되지 않으면 SQLite 백업을 생성하지 않으며, 해당 옵션 사용 시 삭제 전 지정된 경로에 백업을 기록합니다. |
| `dashboard [-p <port>] [--no-open]`                                                                        | 번역 대시보드를 실행합니다(캐시 세그먼트, `strings.json`, 용어집, 실패 내역 및 통계를 위한 로컬 웹 UI). 기본 포트는 **8675**이며, 사용 불가 시 다음 포트로 재시도합니다. `--no-open` 옵션을 사용하면 기본 브라우저가 자동으로 열리지 않습니다. 더 이상 사용되지 않는 별칭 `editor`은 여전히 작동하지만 경고 메시지를 출력합니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `glossary-generate [-o <path>]`                                                                            | 비어 있는 `glossary-user.csv` 템플릿을 작성합니다. `-o`: 출력 경로를 재정의합니다(기본값: 구성의 `glossary.userGlossary` 또는 `glossary-user.csv`). 기존 파일을 덮어쓰는 것을 거부합니다(종료 **1**).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `help [command]`                                                                         | 하위 명령어에 대한 도움말을 표시합니다(`ai-i18n-tools <command> --help`과 동일한 출력).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
