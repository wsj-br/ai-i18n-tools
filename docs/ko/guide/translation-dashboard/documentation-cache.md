# 문서 캐시

**문서** 탭에는 구성된 `cacheDir`에 따라 SQLite에 저장된 캐시된 문서 세그먼트 번역이 나열됩니다. 각 행은 하나의 소스 세그먼트(파일 경로, 줄 힌트 및 소스 해시로 식별됨)가 하나의 대상 로캘로 번역된 것입니다.

전체 파이프라인을 다시 실행하지 않고 캐시된 문서 번역을 **검토, 재정의 또는 정리**하려면 이 탭을 사용하십시오.

<a id="filters"></a>
## 필터

| 필터 | 목적 |
| --- | --- |
| **파일 경로 선택** / **파일 이름(부분)** | 하나의 파일 또는 경로 부분 문자열로 좁히기 |
| **모든 로캘** | 대상 로캘 |
| **모든 모델** | 번역을 생성한 모델 |
| **소스 해시** | 정확한 세그먼트 해시 |
| **소스 텍스트 검색** / **번역된 텍스트 검색** | 부분 문자열 일치 |
| **모든 항목** | **오래됨**(생성 이후 재사용되지 않음) 또는 **활성**(`last_hit_at` 타임스탬프가 있음) |

필터를 변경한 후 **적용**을 클릭하십시오. **지우기**는 모든 필터 필드를 재설정합니다.

<a id="edit-a-translation"></a>
## 번역 편집

1. 행에서 편집 아이콘을 클릭합니다.
2. 모달에서 번역된 텍스트를 변경하고 저장합니다.

캐시는 해당 행에 대한 모델 `user-edited`을 저장합니다. 디스크의 마크다운 출력이 캐시와 일치하도록 `sync --force-update` 또는 `translate-docs --force-update`를 실행하십시오.

나중에 리포지토리의 **소스 텍스트**가 변경되면 세그먼트 해시가 변경되고 이전 텍스트에 대한 수동 편집은 다음 번역 실행 시 대체됩니다.

<a id="delete-rows"></a>
## 행 삭제

- **행 삭제 아이콘** — 하나의 캐시 항목(하나의 소스 해시에 대한 하나의 로캘)을 제거합니다.
- **필터링된 항목 삭제** — 현재 필터와 일치하는 모든 행을 제거합니다(확인 필요).
- **파일 경로에 대한 모든 항목 삭제** — 선택한 파일 경로에 대한 모든 캐시된 번역을 제거하며, 해당 파일에 대한 관련 실패 및 마크다운 문제 행도 포함됩니다.

대량 삭제 후, 누락된 번역을 다시 생성하려면 `translate-docs` 또는 `sync`을 실행하십시오.

<a id="table-columns"></a>
## 테이블 열

| 열 | 의미 |
| --- | --- |
| **파일 경로** | 소스 파일의 캐시 키 |
| **Line #** | 소스 파일의 줄 힌트 |
| **Source hash** | 소스 세그먼트 텍스트의 해시 |
| **Source text** | 원본 세그먼트 (소스 로케일) |
| **Locale** | 대상 로케일 |
| **Translated text** | 캐시된 번역 |
| **Model** | 번역을 생성한 모델 (또는 `user-edited`) |
| **Created** | 행이 처음 작성된 시점 |
| **Last hit** | 이 캐시 항목이 마지막으로 재사용된 시점 (빨간색 대시는 오래됨을 의미) |

페이지 매김은 기본적으로 페이지당 50개 행으로 설정됩니다(25개 또는 100개도 사용 가능).

<a id="log-links"></a>
## 로그 링크

행의 🔗 컨트롤은 대시보드가 실행 중인 터미널에 파일:줄 힌트를 출력하도록 서버에 요청합니다. 이를 사용하여 편집기에서 올바른 소스 위치를 엽니다.
