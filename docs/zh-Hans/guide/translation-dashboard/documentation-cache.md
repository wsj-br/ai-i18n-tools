# 文档缓存

**文档**选项卡列出了存储在您配置的 `cacheDir` 下的 SQLite 中的缓存文档段翻译。每行是一个源段（由文件路径、行提示和源哈希标识），翻译成一个目标语言环境。

当您想要**审查、覆盖或清理**缓存的文档翻译而无需重新运行整个管道时，请使用此选项卡。

<a id="filters"></a>
## 筛选器

| 筛选器 | 用途 |
| --- | --- |
| **选择文件路径** / **文件名（部分）** | 缩小到单个文件或路径子字符串 |
| **所有语言环境** | 目标语言环境 |
| **所有模型** | 生成翻译的模型 |
| **源哈希** | 精确段哈希 |
| **源文本搜索** / **翻译文本搜索** | 子字符串匹配 |
| **所有条目** | **陈旧**（创建后从未重复使用）或 **活动**（具有 `last_hit_at` 时间戳） |

更改筛选器后点击**应用**。**清除**重置所有筛选器字段。

<a id="edit-a-translation"></a>
## 编辑翻译

1. 点击行上的编辑图标。
2. 在模态框中更改翻译文本并保存。

缓存存储该行的模型 `user-edited`。运行 `sync --force-update` 或 `translate-docs --force-update`，以便磁盘上的 Markdown 输出与缓存匹配。

如果您的存储库中的**源文本**稍后发生更改，则段哈希会更改，并且旧文本的手动编辑将在下次翻译运行时被取代。

<a id="delete-rows"></a>
## 删除行

- **行删除图标** — 删除一个缓存条目（一个源哈希的一个语言环境）。
- **删除已筛选** — 删除所有与当前筛选器匹配的行（需要确认）。
- **删除文件路径的所有内容** — 删除所选文件路径的所有缓存翻译，包括该文件的相关失败和 Markdown 问题行。

批量删除后，运行 `translate-docs` 或 `sync` 以重新生成缺失的翻译。

<a id="table-columns"></a>
## 表格列

| 列 | 含义 |
| --- | --- |
| **文件路径** | 源文件的缓存键 |
| **行号** | 源文件中的行提示 |
| **源哈希** | 源段文本的哈希值 |
| **源文本** | 原始段（源语言环境） |
| **语言环境** | 目标语言环境 |
| **译文** | 缓存的译文 |
| **模型** | 生成译文的模型（或 `user-edited`） |
| **创建时间** | 行首次写入的时间 |
| **上次命中** | 此缓存条目上次重用的时间（红色破折号 = 过期） |

分页默认为每页 50 行（也可选择 25 或 100 行）。

<a id="log-links"></a>
## 日志链接

行中的 🔗 控件会要求服务器将文件:行提示打印到运行仪表板的终端。使用它可以在编辑器中打开正确的源位置。
