<a id="cli-reference"></a>
# Référence de la CLI

| Command                                                                                                    | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `version`                                                                                                  | Affiche la version de l'interface en ligne de commande et l'horodatage de compilation (les mêmes informations que `-V` / `--version` du programme racine).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `init [-t ui-markdown\|ui-docusaurus\|ui-starlight\|ui-vitepress\|ui-astro-website\|ui-json-bundles] [-o path] [--with-translate-ignore]` | Écrit un fichier de configuration de démarrage (inclut `concurrency`, `batchConcurrency`, `batchSize`, `maxBatchChars` et `docs[].addFrontmatter`). `ui-vitepress` échafaude les documents VitePress (`docsOutput.style: "vitepress"`) plus le thème JSON via `json[]`. `ui-json-bundles` échafaude JSON (`json[]` uniquement). `--with-translate-ignore` crée un `.translate-ignore` de démarrage. |
| `check-models`                                                                                             | Valide chaque ID de modèle configuré par rapport à la liste `GET /models` du fournisseur actif (appartenance et `expiration_date`), nécessite la clé API de ce fournisseur (aucune pour les fournisseurs sans clé comme Ollama), se termine avec un code non nul si un ID configuré est manquant ou expiré, et respecte les `requestTimeoutMs` du fournisseur. Lorsque le fournisseur renvoie des tarifs (par exemple, OpenRouter), affiche également les USD par 1 million de jetons pour l'invite/l'achèvement.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `list-models`                                                                                              | Liste tous les modèles annoncés par le fournisseur actif via sa liste `GET /models` (triés par ID ; le fournisseur actif suit la clé de configuration `provider`, substitution avec `-P` / `--provider`). Nécessite la clé API de ce fournisseur (aucune pour les fournisseurs sans clé comme Ollama). Lorsque le fournisseur renvoie des tarifs (par exemple, OpenRouter), affiche également les USD par 1 million de jetons pour l'invite/l'achèvement, et marque les entrées expirées (`expiration_date`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `bench-models [--model <ids>] [--text <text>\|--file <path>] [--source <locale>] [--target <locale>]` | Évalue chaque modèle configuré en traduisant un échantillon de manière isolée (client à modèle unique, pas de chaîne de secours). Affiche un tableau avec l'ID du modèle, les jetons d'entrée/sortie, le temps de traduction réel et le coût en USD (`—` pour les fournisseurs qui ne déclarent pas le coût), ainsi qu'une ligne de totaux et les échecs par modèle. Les modèles sont par défaut l'union des ID `translationModels`, `uiModels` et `localeModels` du fournisseur actif (remplacez par `--model`) ; l'échantillon est par défaut un bloc Markdown anglais intégré (remplacez par `--text` / `--file`) ; la source/cible est par défaut la configuration `sourceLocale` et la première locale cible `docs[]`, en revenant à `targetLocales` de niveau supérieur (remplacez par `--source` / `--target`). Exécute les modèles en parallèle, limité par la configuration `concurrency` (4 par défaut) ; chaque modèle est toujours chronométré individuellement. Nécessite la clé API du fournisseur actif. |
| `list-languages [search]`                                                                                  | Liste le catalogue des langues de l'interface utilisateur intégrées (`data/ui-languages-complete.json`) sous forme de tableau lisible par l'homme (code, direction du texte, nom anglais, nom natif) ; ne nécessite aucune configuration ni clé API. Passez un terme `search` optionnel pour ne conserver que les entrées dont le code, le nom natif, le nom anglais ou la direction contiennent ce terme (insensible à la casse), par exemple `list-languages portuguese`, `list-languages rtl`, `list-languages zh`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `extract`                                                                                                  | Met à jour `strings.json` à partir des littéraux `t("…")` / `i18n.t("…")`, d'une description `package.json` optionnelle et d'entrées de manifeste `englishName` optionnelles (voir `ui.reactExtractor`). Lorsque `.html` / `.htm` sont listés dans `ui.uiExtractor.extensions`, capture également les chaînes de marqueurs `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` à partir du HTML. Nécessite un `ui.sourceRoots` non vide. N'appelle pas d'LLM.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `mark-html [paths...] [--write]`                                                                           | Insère des marqueurs `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` bruts dans le HTML afin que le texte source soit écrit une seule fois (sur l'élément lui-même). Analyse les fichiers/dossiers/globes donnés (par défaut : `.html` / `.htm` sous `ui.sourceRoots`). Exécution à blanc par défaut (rapporte les comptes d'ajout par fichier et tous les éléments à contenu mixte nécessitant une `<span data-i18n>` manuelle) ; `--write` applique les modifications. Idempotent, respecte `data-i18n-ignore` (ignore l'élément et son sous-arbre), ne touche jamais aux éléments de type code (`code`, `pre`, `kbd`, `samp`, `var`) ou au texte vide/composé uniquement de chiffres, et n'émet jamais de marqueur valorisé. N'appelle pas d'IA générative.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `generate-ui-languages [--master <path>] [--dry-run]` | Écrit `ui-languages.json` dans le chemin de `uiLanguagesPath` (obligatoire) en utilisant `sourceLocale` + `targetLocales` et le `data/ui-languages-complete.json` fourni (ou `--master`). Avertit et émet des espaces réservés `TODO` pour les paramètres régionaux manquants dans le fichier maître. Si vous avez un manifeste existant avec des valeurs `label` ou `englishName` personnalisées, elles seront remplacées par les valeurs par défaut du catalogue maître — examinez et ajustez le fichier généré par la suite. |
| `translate-docs …` | Traduit le markdown, MDX, `.astro` et le JSON de catalogue Docusaurus facultatif pour chaque bloc `docs` (`contentPaths`, `docusaurusCatalogDir` facultatif). `-j` : nombre maximal de paramètres régionaux parallèles ; `-b` : nombre maximal d'appels d'API de lot parallèles par fichier. `--prompt-format` : format de transmission de lot (`xml` \| `json-array` \| `json-object`). Voir [Comportement du cache et indicateurs `translate-docs`](/guide/documents/cli-options#cache-behaviour-and-translate-docs-flags) et [Format d'invite de lot](/guide/documents/cli-options#batch-prompt-format). |
| `write-heading-ids …`                                                                                      | Nécessite au moins un bloc `docs[]`. Rassemble les éléments `.md` / `.mdx` sous le `contentPaths` de chaque bloc (respecte `.translate-ignore`). Insère une ligne d'ancre HTML `<a id="slug"></a>` immédiatement **avant** chaque en-tête ATX plat `#` (saute les en-têtes situés dans les blocs de code délimités) ; lorsqu'une ligne d'ancre est déjà présente, met à jour le `id` si celui-ci ne correspond plus au slug dérivé du texte actuel de l'en-tête. `-p` / `--path` ou `-f` / `--file` : limite à un fichier ou un répertoire relatif au projet. `--slug-style` : `github` (par défaut ; doctoc / anchor-markdown-header), `bitbucket`, `gitlab`, `pymdown`, `azure-devops`. Avec `pymdown`, `--pymdown-case` facultatif, `--pymdown-normalize`, `--pymdown-percent-encode` / `--no-pymdown-percent-encode`. `--dry-run` : affiche uniquement les modifications.                                                                                                                                                                                                                                                                                                                                    |
| `check-markdown …`                                                                                         | Analyse les fichiers Markdown/MDX présents dans le répertoire `contentPaths` de chaque bloc `docs[]` (découverte identique à `translate-docs`, respecte `.translate-ignore`) : appariement des délimiteurs, code en ligne non fermé, et `STRONG_OUTSIDE_LINK` lorsque `**`/`__` encadrent un lien `[text](url)`. `-p` / `--path` ou `-f` / `--file` : portée facultative. Affiche des lignes `relativePath:line: [ISSUE_CODE] message` sur **stderr** ; code de sortie **1** s'il y a des problèmes. `--json` : rapport JSON sur **stdout**. Écrit `markdown_source_issues` dans `cacheDir` sauf si `--no-cache`. `-v` ajoute les hachages source aux lignes stderr.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `translate-svg …`                                                                        | Traduit les fichiers SVG configurés dans `config.svg` (distincts de la documentation). Nécessite `features.translateSVG`. Mêmes principes de cache que pour la documentation ; prend en charge `--no-cache` pour ignorer les lectures/écritures SQLite lors de cette exécution. `-j`, `-b`, `--force`, `--force-update`, `-p` / `--path`, `--dry-run`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `translate-ui [-l <codes>] [--force] [--dry-run] [-j <n>]` | Traduit uniquement les chaînes d'interface utilisateur (`strings.json` → JSON de paramètres régionaux). `-l` / `--locale` : paramètres régionaux cibles séparés par des virgules (par défaut : configuration `targetLocales` moins `sourceLocale`). `--force` : retraduit toutes les entrées par paramètre régional (ignore les traductions existantes). `--dry-run` : pas d'écritures, pas d'appels d'API. `-j` : nombre maximal de paramètres régionaux parallèles. Nécessite `features.translateUIStrings`. |
| `translate-json …` | Traduit le JSON imbriqué par `json[]` (nécessite `features.translateJson`). Cache SQLite partagé ; `-l`, `-p` / `--path`, `--dry-run`, `--force`, `--force-update`, `-b`, `--prompt-format`. Voir [JSON](/guide/json). |
| `sync-ui [-l <codes>] [--force] [--dry-run] [-j <n>]`                                                      | Extrait, puis traduit les chaînes d’interface (nécessite `features.translateUIStrings`). Interface uniquement — pas de documentation, SVG ou `json[]`. Mêmes options `-l`, `--force`, `--dry-run` et `-j` que `translate-ui`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `proofread-ui [-l <code>] [--chunk <n>] [--dry-run] [--json] [-j <n>]` | Exécute `extract` **en premier** (nécessite `features.translateUIStrings`) pour que `strings.json` corresponde à la source, puis révision LLM des chaînes d'interface utilisateur de la **locale source** (orthographe, grammaire). Les **suggestions terminologiques** proviennent uniquement du fichier CSV `glossary.userGlossary` (même portée que `translate-ui` — pas `strings.json` / `uiGlossary`, donc une mauvaise copie n'est pas renforcée en tant que glossaire). Utilise le fournisseur LLM actif (sa variable d'environnement de clé API). Quitte avec le code **1** en cas d'échec (indicateur de fonctionnalité manquant, échec d'extraction, catalogue manquant/invalide, clé API manquante ou si tous les lots échouent) ; quitte avec le code **0** lorsque l'exécution se termine avec succès (les résultats sont consultatifs). Écrit `proofread-ui-results_<timestamp>.log` sous `cacheDir` comme rapport **lisible par l'homme** (résumé, problèmes et lignes **OK** par chaîne) ; le terminal n'imprime que les totaux récapitulatifs et les problèmes (pas de lignes `[ok]` par chaîne). Imprime le nom du fichier journal sur la dernière ligne. `--json` : rapport JSON complet lisible par machine sur la sortie standard uniquement (le fichier journal reste lisible par l'homme). `--dry-run` : exécute toujours `extract`, puis imprime uniquement le plan de lot (pas d'appels API). `--chunk` : chaînes par lot API (par défaut **50**). `-j` : nombre maximal de lots parallèles (par défaut `concurrency`). Avec `--json`, la sortie de style humain va vers la sortie d'erreur standard. Les liens utilisent `path:line` comme le bouton « lien » des chaînes d'interface utilisateur `dashboard`. |
| `export-ui-xliff [-l <codes>] [-o <dir>] [--untranslated-only] [--dry-run]`              | Exporter `strings.json` vers XLIFF 2.0 (un `.xliff` par langue cible). `-o` / `--output-dir` : répertoire de sortie (par défaut : même dossier que le catalogue). `--untranslated-only` : uniquement les unités manquantes d'une traduction pour cette langue. Lecture seule ; aucune API.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `sync …` | Extraction (si activée), puis traduction de l'interface utilisateur, puis `translate-svg` lorsque `features.translateSVG` et `config.svg` sont définis, puis traduction de la documentation, puis `translate-json` lorsque `features.translateJson` et `json[]` sont définis — sauf si ignoré avec `--no-ui`, `--no-svg`, `--no-docs` ou `--no-json`. Indicateurs partagés : `-l`, `-p` / `-f`, `--dry-run`, `-j`, `-b` (traitement par lots des documents et JSON), `--force` / `--force-update`. `--force` est transmis aux étapes UI et SVG ainsi qu'aux documents/JSON ; `--force-update` s'applique aux documents, JSON et SVG (pas à l'UI). La phase des documents transmet également `--emphasis-placeholders` et `--debug-failed` (même signification que `translate-docs`). `--prompt-format` n'est pas un indicateur `sync` ; les étapes des documents et JSON utilisent la valeur par défaut intégrée (`json-array`). |
| `status [--max-columns <n>]` | Lorsque `features.translateUIStrings` est activé, affiche la couverture de l'interface utilisateur par locale (`Translated` / `Missing` / `Total`). Ensuite, affiche l'état de la traduction Markdown par fichier × locale (pas de filtre `--locale` ; les locales proviennent de la configuration). Lorsque `features.translateJson` est activé et que `json[]` est configuré, affiche également l'état du bundle JSON par bloc. Les grandes listes de locales sont divisées en tableaux répétés de jusqu'à `n` colonnes de locales (par défaut **9**) afin que les lignes restent étroites dans le terminal. |
| `statistics [--max-columns <n>]` | Affiche le cache de la documentation et les statistiques `strings.json` (mêmes agrégats que Tableau de bord de traduction → **Statistiques**). `--max-columns` : nombre maximal de colonnes de paramètres régionaux par modèle × tableau de paramètres régionaux (par défaut : **6**). |
| `cleanup [--dry-run] [--backup <path>]` | Efface l’intégralité du tableau `markdown_source_issues`, puis exécute `sync --force-update` (extraction, interface utilisateur, SVG, documents et `translate-json` si activé) afin que les problèmes de markdown soient de nouveau renseignés pour les documents actuellement configurés ; puis supprime les lignes de segment obsolètes (`last_hit_at` nul/chemin de fichier vide) ; supprime les lignes `file_tracking` dont le chemin source résolu est manquant sur le disque ; supprime les lignes de traduction dont les métadonnées `filepath` pointent vers un fichier manquant ; élague les lignes `translation_failures` orphelines. Enregistre quatre nombres d’élagage après la synchronisation (segments obsolètes, `file_tracking` orphelins, traductions orphelines, échecs orphelins) plus le nombre initial d’effacements des problèmes de markdown. `--backup <path>` écrit une sauvegarde SQLite à ce chemin avant les modifications (pas de sauvegarde si cet indicateur n’est pas défini). |
| `clean-temp [-r\|--root <path>] [-f\|--force] [--dry-run]` | **Aucune configuration.** Parcourt une arborescence de répertoires (par défaut : répertoire de travail actuel) pour `*.log`, `*.tmp` et `cache.db.backup*.sqlite`, affiche les chemins `./…` comme `find -print`. Avec des correspondances : invite `Delete these files? (y/n)` sauf `-f` / `--force` (supprimer sans invite). Sans correspondances : quitte sans invite. `--dry-run` : lister uniquement, pas d’invite ni de suppressions (remplace `--force`). |
| `purge-locale -l <code> [-l <code> …] [--dry-run] [-y\|--yes] [-f\|--force] [--keep-files] [--backup <path>]` | Supprime toutes les lignes mises en cache pour les paramètres régionaux donnés de `translations`, `file_tracking` et `translation_failures`, **et** les artefacts générés pour ces paramètres régionaux : documents traduits (sorties `.md` / `.mdx` / `.astro` résolues à partir de `docs[]`, y compris les sorties orphelines dont la source a été supprimée — trouvées en balayant l'arborescence de sortie de chaque bloc, sauf lorsqu'un `pathTemplate` personnalisé est configuré), le fichier d'interface utilisateur plat par paramètre régional (`<flatOutputDir>/<locale>.json`) et les entrées des paramètres régionaux dans `strings.json`. Les paramètres régionaux sont passés via `-l` / `--locale` répétables (normalisés en BCP-47). Affiche les nombres par paramètre régional (lignes de cache, documents, entrées `strings.json`, fichier plat) ; avertit (ne génère pas d'erreur) pour les paramètres régionaux sans rien à purger. Demande confirmation sauf si `-y` / `--yes` / `-f` / `--force`. `--dry-run` : affiche les nombres et les fichiers qui seraient supprimés, ne supprime rien. `--keep-files` : purge uniquement le cache SQLite, laissant les fichiers générés et `strings.json` intacts. Aucune sauvegarde SQLite n'est effectuée sauf si `--backup <path>` est passé, ce qui écrit une sauvegarde à ce chemin avant la suppression. |
| `dashboard [-p <port>] [--no-open]`                                                                        | Lance le tableau de bord de traduction (interface web locale pour les segments du cache, `strings.json`, le glossaire, les échecs et les statistiques). Port par défaut **8675** (essaie le port suivant si indisponible). Avec `--no-open`, le navigateur par défaut n'est pas ouvert automatiquement. L'alias obsolète `editor` fonctionne encore mais affiche un avertissement.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `glossary-generate [-o <path>]` | Écrit un modèle `glossary-user.csv` vide. `-o` : remplace le chemin de sortie (par défaut : `glossary.userGlossary` de la configuration, ou `glossary-user.csv`). Refuse d’écraser un fichier existant (quitte avec le code **1**). |
| `help [command]`                                                                         | Affiche l'aide pour une sous-commande (sortie identique à `ai-i18n-tools <command> --help`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

<a id="root-and-global-options"></a>
### Options racine et globales

| Option                       | Portée         | Description                                                                               |
|------------------------------|---------------|-------------------------------------------------------------------------------------------|
| `-V` / `--version`           | Programme racine  | Affiche le numéro de version et l'horodatage de compilation (même information que la sous-commande `version`). |
| `-h` / `--help`              | Programme racine  | Affiche l'aide pour le programme racine ou pour une sous-commande lorsqu'utilisé avec un nom de commande.      |
| `-c` / `--config <path>`     | Chaque commande | Chemin du fichier de configuration (par défaut : `ai-i18n-tools.config.json`).                                  |
| `-v` / `--verbose`           | Chaque commande | Journalisation détaillée.                                                                          |
| `-P` / `--provider <name>`   | Chaque commande | Fournisseur LLM actif pour cette exécution ; remplace la clé de configuration `provider`. Doit être configuré sous `providers`. |
| `-L` / `--ui-lang <code>` | Chaque commande | Langue de l’interface utilisateur de l’outil (aide CLI, journaux/résumés, tableau de bord) ; source la plus prioritaire. Voir [Langue de l’interface utilisateur de l’outil](/reference/environment-variables#tool-ui-language). |
| `-w` / `--write-logs [path]` | Commandes sélectionnées | Affiche la sortie de la console dans un fichier `.log` (chemin par défaut : sous la racine `cacheDir`). Câblé uniquement pour `translate-docs`, `translate-json`, `translate-svg`, `translate-ui`, `sync-ui`, `sync` et `cleanup`. |

<a id="target-locales--l----locale"></a>
### Paramètres régionaux cibles (`-l` / `--locale`)

| Commandes | Comportement |
|-----------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------|
| `translate-docs`, `translate-json`, `translate-svg`, `translate-ui`, `sync`, `sync-ui`, `export-ui-xliff` | `-l` / `--locale <codes>` — codes BCP-47 cibles séparés par des virgules (par exemple, `de,fr,pt-BR`). Si omis, les valeurs par défaut proviennent de la configuration (les blocs `json[]` peuvent également définir `targetLocales` par bloc ; les étapes de l’interface utilisateur utilisent `targetLocales` moins `sourceLocale`). |
| `proofread-ui`                                                                           | `-l` / `--locale <code>` — locale source unique à examiner (par défaut : configuration `sourceLocale`).                                                            |
