# CLI-Referenz

| Befehl                                                                                                    | Beschreibung                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
|------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `version`                                                                                                  | Gibt die CLI-Version und den Build-Zeitstempel aus (dieselben Informationen wie `-V` / `--version` im Hauptprogramm).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `init [-t ui-markdown\|ui-docusaurus\|ui-starlight\|ui-vitepress\|ui-nextra\|ui-astro-website\|ui-json-bundles] [-o path] [--with-translate-ignore]` | Schreibt eine Starter-Konfigurationsdatei (enthält `concurrency`, `batchConcurrency`, `batchSize`, `maxBatchChars` und `docs[].addFrontmatter`). `ui-vitepress` erstellt VitePress-Dokumente (`docsOutput.style: "vitepress"`) plus `vitepressThemeCatalog` für Theme-Strings – alles innerhalb von `translate-docs`. `ui-nextra` erstellt Nextra-Dokumente (`docsOutput.style: "nextra"`) plus `nextraDictionaryPath` für das Theme-Wörterbuch (Sidebar `_meta.ts` wird automatisch gesammelt) – ebenfalls innerhalb von `translate-docs`. `ui-json-bundles` erstellt JSON (nur `json[]`). `--with-translate-ignore` erstellt eine Starter-`.translate-ignore`. |
| `check-models`                                                                                             | Überprüfen Sie jede konfigurierte Modell-ID anhand der `GET /models`-Liste des aktiven Anbieters (Mitgliedschaft und `expiration_date`). Erfordert den API-Schlüssel dieses Anbieters (keiner für schlüssellose Anbieter wie Ollama). Beendet sich mit einem Rückgabewert ungleich Null, wenn eine konfigurierte ID fehlt oder abgelaufen ist, und berücksichtigt die `requestTimeoutMs` des Anbieters. Wenn der Anbieter Preise zurückgibt (z. B. OpenRouter), werden auch USD pro 1 Million Tokens für die Eingabe/Ausgabe angezeigt.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `list-models`                                                                                              | Listen Sie jedes Modell auf, das der aktive Anbieter über seine `GET /models`-Liste bewirbt (sortiert nach ID; der aktive Anbieter folgt dem `provider`-Schlüssel der Konfiguration, überschreiben mit `-P` / `--provider`). Erfordert den API-Schlüssel dieses Anbieters (keiner für schlüssellose Anbieter wie Ollama). Wenn der Anbieter Preise zurückgibt (z. B. OpenRouter), werden auch USD pro 1 Million Tokens für die Eingabe/Ausgabe angezeigt und Einträge, die `expiration_date` überschritten haben, markiert.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `bench-models [--model <ids>] [--text <text>\|--file <path>] [--source <locale>] [--target <locale>]` | Jedes konfigurierte Modell wird durch die Übersetzung eines einzelnen Beispiels isoliert bewertet (Client mit einem Modell, keine Fallback-Kette). Es wird eine Tabelle mit Modell-ID, Eingabe-/Ausgabe-Tokens, Übersetzungszeit (Wall-Clock) und USD-Kosten (`—` für Anbieter, die keine Kosten melden) ausgegeben, zusätzlich eine Summenzeile und Fehler pro Modell. Modelle verwenden standardmäßig die Vereinigung der `translationModels`-, `uiModels`- und `localeModels`-IDs des aktiven Anbieters (mit `--model` überschreiben); das Beispiel ist standardmäßig ein integrierter englischer Markdown-Block (mit `--text` / `--file` überschreiben); Quelle/Ziel verwenden standardmäßig die Konfiguration `sourceLocale` und das erste `docs[]`-Zielland, wobei auf die oberste Ebene `targetLocales` zurückgegriffen wird (mit `--source` / `--target` überschreiben). Modelle werden parallel ausgeführt, begrenzt durch die Konfiguration `concurrency` (Standard 4); jedes Modell wird weiterhin einzeln zeitlich erfasst. Erfordert den API-Schlüssel des aktiven Anbieters. |
| `list-languages [search]`                                                                                  | Listen Sie den Katalog der gebündelten UI-Sprachen (`data/ui-languages-complete.json`) als menschenlesbare Tabelle auf (Code, Textrichtung, englischer Name, nativer Name); benötigt keine Konfiguration oder API-Schlüssel. Übergeben Sie einen optionalen `search`-Begriff, um nur Einträge beizubehalten, deren Code, nativer Name, englischer Name oder Richtung ihn enthalten (Groß-/Kleinschreibung wird nicht beachtet), z. B. `list-languages portuguese`, `list-languages rtl`, `list-languages zh`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `extract`                                                                                                  | Aktualisiert `strings.json` aus `t("…")` / `i18n.t("…")`-Literalen, optionaler `package.json`-Beschreibung und optionaler Manifest `englishName`-Einträge (siehe `ui.reactExtractor`). Wenn `.html` / `.htm` in `ui.uiExtractor.extensions` aufgeführt sind, werden auch `data-i18n` / `data-i18n-title` / `data-i18n-placeholder`-Markierungsstrings aus HTML erfasst. Erfordert nicht-leeres `ui.sourceRoots`. Ruft keine LLM auf.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `mark-html [paths...] [--write]`                                                                           | Fügt reine `data-i18n` / `data-i18n-title` / `data-i18n-placeholder`-Marker in HTML ein, sodass der Quelltext einmal geschrieben wird (am Element selbst). Scannt die angegebenen Dateien/Verzeichnisse/Globs (Standard: `.html` / `.htm` unter `ui.sourceRoots`). Standardmäßig Dry-Run (meldet Hinzuzählungen pro Datei und alle gemischten Inhaltselemente, die eine manuelle `<span data-i18n>` benötigen); `--write` wendet Änderungen an. Idempotent, berücksichtigt `data-i18n-ignore` (überspringt das Element und seinen Unterbaum), berührt niemals codeähnliche Elemente (`code`, `pre`, `kbd`, `samp`, `var`) oder leeren/nur numerischen Text und gibt niemals einen wertvollen Marker aus. Ruft keine LLM auf.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `generate-ui-languages [--master <path>] [--dry-run]` | Schreibt `ui-languages.json` in den Pfad in `uiLanguagesPath` (erforderlich) unter Verwendung von `sourceLocale` + `targetLocales` und dem gebündelten `data/ui-languages-complete.json` (oder `--master`). Warnt und gibt `TODO`-Platzhalter für Gebietsschemata aus, die in der Masterdatei fehlen. Wenn Sie ein vorhandenes Manifest mit angepassten `label`- oder `englishName`-Werten haben, werden diese durch die Standardwerte des Masterkatalogs ersetzt – überprüfen und passen Sie die generierte Datei anschließend an. |
| `translate-docs …` | Übersetzt Markdown, MDX, `.astro`, optionalen Docusaurus-Katalog-JSON (`docusaurusCatalogDir`), optionales Nextra `_meta.ts`/Wörterbuch `.ts` und optionalen VitePress-Theme-Katalog für jeden `docs`-Block. `-j`: maximale parallele Locales; `-b`: maximale parallele Batch-API-Aufrufe pro Datei. `--prompt-format`: Batch-Wire-Format (`xml` \| `json-array` \| `json-object`). Siehe [Cache-Verhalten und `translate-docs`-Flags](/guide/documents/cli-options#cache-behaviour-and-translate-docs-flags) und [Batch-Prompt-Format](/guide/documents/cli-options#batch-prompt-format). |
| `write-heading-ids …`                                                                                      | Erfordert mindestens einen `docs[]`-Block. Sammelt `.md` / `.mdx` unter `contentPaths` jedes Blocks (beachtet `.translate-ignore`). Fügt eine HTML-Ankerzeile `<a id="slug"></a>` unmittelbar **vor** jede flache ATX-`#`-Überschrift ein (überspringt Überschriften innerhalb von Codeblöcken mit Rahmen); wenn bereits eine Ankerzeile vorhanden ist, aktualisiert sie `id`, falls diese nicht mehr mit dem aus dem aktuellen Überschriftentext abgeleiteten Slug übereinstimmt. `-p` / `--path` oder `-f` / `--file`: Beschränkung auf eine projektrelative Datei oder ein Verzeichnis. `--slug-style`: `github` (Standard; doctoc / anchor-markdown-header), `bitbucket`, `gitlab`, `pymdown`, `azure-devops`. Mit `pymdown`, optional `--pymdown-case`, `--pymdown-normalize`, `--pymdown-percent-encode` / `--no-pymdown-percent-encode`. `--dry-run`: Zeigt nur Änderungen an.                                                                                                                                                                                                                                                                                                                                    |
| `check-markdown …`                                                                                         | Durchsucht Markdown/MDX unterhalb jedes `docs[]`-Blocks `contentPaths` (gleiche Auffindung wie `translate-docs`, beachtet `.translate-ignore`): Delimiter-Paarung, nicht geschlossener Inline-Code und `STRONG_OUTSIDE_LINK`, wenn `**`/`__` einen `[text](url)`-Link umschließen. `-p` / `--path` oder `-f` / `--file`: optionaler Bereich. Gibt `relativePath:line: [ISSUE_CODE] message`-Zeilen auf **stderr** aus; Exit-Code **1**, falls ein Problem vorliegt. `--json`: JSON-Bericht auf **stdout**. Schreibt `markdown_source_issues` in `cacheDir`, es sei denn `--no-cache`. `-v` fügt Quell-Hashes zu stderr-Zeilen hinzu.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `translate-svg …`                                                                        | Übersetzt SVG-Dateien, die in `config.svg` konfiguriert sind (getrennt von Dokumentation). Erfordert `features.translateSVG`. Gleiche Cache-Überlegungen wie bei Dokumenten; unterstützt `--no-cache`, um SQLite-Lese-/Schreibvorgänge für diese Ausführung zu überspringen. `-j`, `-b`, `--force`, `--force-update`, `-p` / `--path`, `--dry-run`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `translate-ui [-l <codes>] [--force] [--dry-run] [-j <n>]` | Übersetzt nur UI-Strings (`strings.json` → Gebietsschema-JSON). `-l` / `--locale`: durch Kommas getrennte Ziel-Gebietsschemata (Standard: Konfiguration `targetLocales` minus `sourceLocale`). `--force`: alle Einträge pro Gebietsschema neu übersetzen (bestehende Übersetzungen ignorieren). `--dry-run`: keine Schreibvorgänge, keine API-Aufrufe. `-j`: maximale parallele Gebietsschemata. Erfordert `features.translateUIStrings`. |
| `translate-json …` | Übersetzt verschachteltes JSON pro `json[]` (erfordert `features.translateJson`). Gemeinsamer SQLite-Cache; `-l`, `-p` / `--path`, `--dry-run`, `--force`, `--force-update`, `-b`, `--prompt-format`. Siehe [JSON](/guide/json). |
| `sync-ui [-l <codes>] [--force] [--dry-run] [-j <n>]`                                                      | Extrahiert und übersetzt anschließend UI-Texte (erfordert `features.translateUIStrings`). Nur für die Benutzeroberfläche – keine Dokumentation, SVG oder `json[]`. Gleiche `-l`, `--force`, `--dry-run` und `-j` Optionen wie bei `translate-ui`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `proofread-ui [-l <code>] [--chunk <n>] [--dry-run] [--json] [-j <n>]`                                      | Führt `extract` **zuerst** aus (erfordert `features.translateUIStrings`), damit `strings.json` mit der Quelle übereinstimmt, dann LLM-Überprüfung der UI-Strings in der **Quellsprache** (Rechtschreibung, Grammatik). **Terminologiehinweise** stammen nur aus der `glossary.userGlossary`-CSV-Datei (gleicher Umfang wie `translate-ui` – nicht `strings.json` / `uiGlossary`, sodass schlechte Kopien nicht als Glossar verstärkt werden). Verwendet den aktiven LLM-Anbieter (dessen API-Schlüssel-Umgebungsvariable). Beendet mit **1** bei Fehler (fehlendes Feature-Flag, Extraktionsfehler, fehlender/ungültiger Katalog, fehlender API-Schlüssel oder wenn alle Batches fehlschlagen); beendet mit **0**, wenn der Lauf erfolgreich abgeschlossen wird (Ergebnisse sind beratend). Schreibt `proofread-ui-results_<timestamp>.log` unter `cacheDir` als **menschenlesbaren** Bericht (Zusammenfassung, Probleme und pro-String **OK**-Zeilen); das Terminal gibt nur Zusammenfassungszählungen und Probleme aus (keine `[ok]`-Zeilen pro String). Gibt den Protokolldateinamen in der letzten Zeile aus. `--json`: vollständiger maschinenlesbarer JSON-Bericht nur auf stdout (Protokolldatei bleibt menschenlesbar). `--dry-run`: führt weiterhin `extract` aus, druckt dann nur den Batch-Plan (keine API-Aufrufe). `--chunk`: Strings pro API-Batch (Standard **50**). `-j`: maximale parallele Batches (Standard `concurrency`). Mit `--json` geht die menschenlesbare Ausgabe an stderr. Links verwenden `path:line` wie die Schaltfläche „Link“ der `dashboard`-UI-Strings. |
| `export-ui-xliff [-l <codes>] [-o <dir>] [--untranslated-only] [--dry-run]`              | Exportiert `strings.json` nach XLIFF 2.0 (eine `.xliff` pro Zielgebietsschema). `-o` / `--output-dir`: Ausgabeverzeichnis (Standard: derselbe Ordner wie der Katalog). `--untranslated-only`: nur Einheiten ohne Übersetzung für dieses Gebietsschema. Nur-Lesen; keine API.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `sync …`                                                                                                   | Extraktion (falls aktiviert), dann UI-Übersetzung, dann `translate-svg`, wenn `features.translateSVG` und `config.svg` gesetzt sind, dann Dokumentationsübersetzung, dann `translate-json`, wenn `features.translateJson` und `json[]` gesetzt sind – es sei denn, sie wird mit `--no-ui`, `--no-svg`, `--no-docs` oder `--no-json` übersprungen. Gemeinsame Flags: `-l`, `-p` / `-f`, `--dry-run`, `-j`, `-b` (Dokumente und JSON-Batching), `--force` / `--force-update`. `--force` wird an die UI- und SVG-Schritte sowie an Dokumente/JSON weitergeleitet; `--force-update` gilt für Dokumente, JSON und SVG (nicht UI). Die Dokumentationsphase leitet auch `--emphasis-placeholders` und `--debug-failed` weiter (gleiche Bedeutung wie `translate-docs`). `--prompt-format` ist kein `sync`-Flag; die Dokumentations- und JSON-Schritte verwenden den integrierten Standard (`json-array`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `status [--max-columns <n>]`                                                                               | Wenn `features.translateUIStrings` aktiviert ist, wird die UI-Abdeckung pro Gebietsschema (`Translated` / `Missing` / `Total`) ausgegeben. Anschließend wird der Markdown-Übersetzungsstatus pro Datei × Gebietsschema ausgegeben (kein `--locale`-Filter; Gebietsschemas stammen aus der Konfiguration). Wenn `features.translateJson` aktiviert und `json[]` konfiguriert ist, wird auch der JSON-Bundle-Status pro Block ausgegeben. Große Gebietsschemalisten werden in wiederholte Tabellen mit bis zu `n` Gebietsschema-Spalten (Standard **9**) aufgeteilt, damit die Zeilen im Terminal schmal bleiben.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `statistics [--max-columns <n>]` | Druckt den Dokumentations-Cache und `strings.json`-Statistiken (dieselben Aggregationen wie Übersetzungs-Dashboard → **Statistiken**). `--max-columns`: maximale Gebietsschema-Spalten pro Modell × Gebietsschema-Tabelle (Standard **6**). |
| `cleanup [--dry-run] [--backup <path>]` | Löscht die gesamte `markdown_source_issues`-Tabelle und führt dann `sync --force-update` aus (Extraktion, UI, SVG, Dokumente und `translate-json`, falls aktiviert), sodass Markdown-Probleme für die aktuell konfigurierten Dokumente neu gefüllt werden; entfernt dann veraltete Segmentzeilen (Null `last_hit_at` / leerer Dateipfad); löscht `file_tracking`-Zeilen, deren aufgelöster Quellpfad auf der Festplatte fehlt; entfernt Übersetzungszeilen, deren `filepath`-Metadaten auf eine fehlende Datei verweisen; bereinigt verwaiste `translation_failures`-Zeilen. Protokolliert vier Bereinigungszählungen nach der Synchronisierung (veraltete Segmente, verwaiste `file_tracking`, verwaiste Übersetzungen, verwaiste Fehler) plus die anfängliche Markdown-Probleme-Löschzählungen. `--backup <path>` schreibt vor Änderungen ein SQLite-Backup in diesen Pfad (kein Backup, es sei denn, dieses Flag ist gesetzt). |
| `clean-temp [-r\|--root <path>] [-f\|--force] [--dry-run]` | **Keine Konfiguration.** Durchläuft einen Verzeichnisbaum (Standard: aktuelles Verzeichnis) nach `*.log`, `*.tmp` und `cache.db.backup*.sqlite`, druckt `./…`-Pfade wie `find -print`. Bei Übereinstimmungen: fordert `Delete these files? (y/n)` auf, es sei denn, `-f` / `--force` (Löschen ohne Aufforderung). Bei keinen Übereinstimmungen: Beendet ohne Aufforderung. `--dry-run`: nur auflisten, keine Aufforderung oder Löschungen (überschreibt `--force`). |
| `purge-locale -l <code> [-l <code> …] [--dry-run] [-y\|--yes] [-f\|--force] [--keep-files] [--backup <path>]` | Löscht alle zwischengespeicherten Zeilen für die angegebenen Locales aus `translations`, `file_tracking` und `translation_failures`, **und** die generierten Artefakte für dieses Locale: übersetzte Dokumente (`.md` / `.mdx` / `.astro`-Ausgaben, die aus `docs[]` aufgelöst wurden, einschließlich verwaister Ausgaben, deren Quelle entfernt wurde – gefunden durch Durchsuchen des Ausgabebaums jedes Blocks, außer wenn ein benutzerdefiniertes `pathTemplate` konfiguriert ist), die Flat-UI-Datei pro Locale (`<flatOutputDir>/<locale>.json`) und die Einträge des Locales in `strings.json`. Locales werden über wiederholbare `-l` / `--locale` übergeben (normalisiert auf BCP-47). Zeigt Zählungen pro Locale an (Cache-Zeilen, Dokumente, `strings.json`-Einträge, Flat-Datei); warnt (kein Fehler) für Locales, für die nichts zu bereinigen ist. Fordert zur Bestätigung auf, es sei denn, `-y` / `--yes` / `-f` / `--force`. `--dry-run`: Zählungen und die zu entfernenden Dateien melden, nichts löschen. `--keep-files`: Nur den SQLite-Cache bereinigen, generierte Dateien und `strings.json` unberührt lassen. Es wird kein SQLite-Backup erstellt, es sei denn, `--backup <path>` wird übergeben, was ein Backup in diesen Pfad schreibt, bevor gelöscht wird. |
| `dashboard [-p <port>] [--no-open]`                                                                        | Startet das Übersetzungs-Dashboard (lokale Web-Benutzeroberfläche für Cache-Segmente, `strings.json`, Glossar, Fehler und Statistiken). Standardport **8675** (bei Belegung wird der nächste Port versucht). Mit `--no-open` wird der Standardbrowser nicht automatisch geöffnet. Der veraltete Alias `editor` funktioniert weiterhin, gibt aber eine Warnung aus.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `glossary-generate [-o <path>]` | Erstellt eine leere `glossary-user.csv`-Vorlage. `-o`: Überschreibt den Ausgabepfad (Standard: `glossary.userGlossary` aus der Konfiguration oder `glossary-user.csv`). Verweigert das Überschreiben einer vorhandenen Datei (Beenden **1**). |
| `help [command]`                                                                         | Zeigt die Hilfe für einen Unterbefehl an (gleiche Ausgabe wie `ai-i18n-tools <command> --help`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

<a id="root-and-global-options"></a>
### Stamm- und globale Optionen

| Option                       | Bereich         | Beschreibung                                                                               |
|------------------------------|---------------|-------------------------------------------------------------------------------------------|
| `-V` / `--version`           | Stammprogramm  | Gibt die Versionsnummer und den Build-Zeitstempel aus (gleiche Informationen wie der Unterbefehl `version`). |
| `-h` / `--help`              | Stammprogramm  | Zeigt die Hilfe für das Stammprogramm oder für einen Unterbefehl an, wenn zusammen mit einem Befehlsnamen verwendet.      |
| `-c` / `--config <path>`     | Jeder Befehl | Pfad zur Konfigurationsdatei (Standard: `ai-i18n-tools.config.json`).                                  |
| `-v` / `--verbose`           | Jeder Befehl | Ausführliche Protokollierung.                                                                          |
| `-P` / `--provider <name>`   | Jeder Befehl | Aktiver LLM-Anbieter für diesen Lauf; überschreibt den Konfigurationsschlüssel `provider`. Muss unter `providers` konfiguriert werden. |
| `-L` / `--ui-lang <code>` | Jeder Befehl | Sprache für die Benutzeroberfläche des Tools (CLI-Hilfe, Protokolle/Zusammenfassungen, Dashboard); Quelle mit höchster Priorität. Siehe [Sprache der Tool-Benutzeroberfläche](/reference/environment-variables#tool-ui-language). |
| `-w` / `--write-logs [path]` | Ausgewählte Befehle | Konsolenausgabe in eine `.log`-Datei umleiten (Standardpfad: unter dem Stammverzeichnis `cacheDir`). Nur für `translate-docs`, `translate-json`, `translate-svg`, `translate-ui`, `sync-ui`, `sync` und `cleanup` verdrahtet. |

<a id="target-locales--l----locale"></a>
### Zielsprachen (`-l` / `--locale`)

| Befehle | Verhalten |
|-----------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------|
| `translate-docs`, `translate-json`, `translate-svg`, `translate-ui`, `sync`, `sync-ui`, `export-ui-xliff` | `-l` / `--locale <codes>` – durch Kommas getrennte BCP-47-Zielcodes (z. B. `de,fr,pt-BR`). Wenn weggelassen, stammen die Standardwerte aus der Konfiguration (`json[]`-Blöcke können auch pro Block `targetLocales` festlegen; UI-Schritte verwenden `targetLocales` minus `sourceLocale`). |
| `proofread-ui`                                                                           | `-l` / `--locale <code>` — einzelnes Quellgebietsschema zur Überprüfung (Standard: Konfiguration `sourceLocale`).                                                            |
