- **Added**: cli — new `bench-models` command (`src/cli/bench-models.ts`, registered in `src/cli/index.ts`) that benchmarks each configured translation model in isolation by translating one sample through a single-model `LlmClient` (no fallback chain). It prints a table of model id, input/output tokens, wall-clock translation time (`MM:SS.mmm`), and USD cost (`—` for providers that do not report cost, e.g. non-OpenRouter), plus a totals row and per-model failure details. Models default to the active provider's `translationModels` (override with `--models <ids>`); the sample defaults to a built-in English markdown block (override with `--text` / `--file`); source/target locales default to config `sourceLocale` and the first documentation target locale, falling back to the top-level `targetLocales` when no `docs[]` blocks are configured (override with `--source` / `--target`). Uses the document/markdown translate path (`translateDocumentSegment`).
- **Added**: cli — new `purge-locale` command (`src/cli/purge-locale.ts`, registered in `src/cli/index.ts`) that deletes all cached rows for one or more locales from the `translations`, `file_tracking`, and `translation_failures` tables, and (unless `--keep-files`) the locale's generated artifacts: translated documents (`.md` / `.mdx` / `.astro` outputs resolved from `docs[]` via `resolveTranslatedOutputPath`, unioned with an on-disk sweep of each block's output tree so orphaned outputs whose source was removed are also deleted — the sweep matches the `flat` filename suffix or the per-locale output directory, and is skipped for blocks with a custom `pathTemplate`), the per-locale flat UI file (`<ui.flatOutputDir>/<locale>.json`), and the locale's entries in `strings.json` (`translated`/`models` maps). Locales are passed via a repeatable `-l` / `--locale <code>` flag (normalized with `normalizeLocale`); it prints per-locale counts (cache rows, documents, `strings.json` entries, flat file), warns (does not error) for locales with nothing to purge, and prompts for confirmation unless `-y` / `--yes` / `-f` / `--force`. `--dry-run` reports counts and the files that would be removed without deleting; `--keep-files` purges only the SQLite cache; `--backup <path>` writes a SQLite backup before deletion (no backup unless set). Backed by a new `TranslationCache.countLocaleRows(locale)` helper (`src/core/cache.ts`) reusing the existing `clear(locale)` for deletion.
- **Fixed**: cli/docs — `sync` and the `translate-*` document/JSON commands now recreate a translated file when the destination is missing or older than its source, even when the source content hash is unchanged. Previously an unchanged (cache-hit) source was skipped as long as the output existed, so a translated file that had been deleted-then-restored stale, or whose source was touched/edited-and-reverted to identical bytes, would not be regenerated. A new `translatedOutputIsCurrent(outPath, sourceMtimeIso)` helper (`src/cli/helpers.ts`) replaces the prior `fs.existsSync(outPath)` skip guard in the markdown, Astro, JSON-doc, and SVG paths of `src/cli/doc-translate.ts` and in the nested-JSON path of `src/cli/translate-json-run.ts`; re-translation reuses the segment cache, so unchanged content costs no extra LLM calls.

This is a breaking change with no backward-compatible alias — the old `lint-source` name is removed. The implementation moved from `src/cli/lint-source.ts` to `src/cli/proofread-ui.ts` and its symbols/prompt identifiers were renamed accordingly (`runProofreadUI`, `ProofreadUIReport`, `buildProofreadUIPromptMessages`, `parseProofreadUIBatchResponse`, `LlmClient.proofreadUISourceBatch`, `PROMPTS.proofreadUI`, …). The results log is now `proofread-ui-results_<timestamp>.log`, console prefixes read `[proofread-ui]`, and `README.md` / `docs/GETTING_STARTED.md` / `docs/ai-i18n-tools-context.md` were updated. Source-text-keyed catalog entries change, so the affected UI strings re-translate on the next `pnpm i18n:self` run.
- **Fixed**: build — removed dead duplicate `src/api/openrouter.ts` and `src/cli/lint-source.ts`, which were still referencing renamed symbols (`LintSource*` → `ProofreadUI*`) and the obsolete top-level `config.openrouter` block removed in the multi-provider refactor; their orphaned test files (`tests/unit/openrouter.test.ts`, `tests/unit/lint-source.test.ts`) were also removed. The live implementations are `src/api/llm-client.ts` (re-exported as `OpenRouterClient`) and `src/cli/proofread-ui.ts`.

- **Fixed**: lint — added `references/**` to ESLint `ignores` so temporary external-reference snapshots (which may have missing dependencies) no longer break `pnpm run lint`. A new bracketed-title branch in `src/processors/admonition-placeholders.ts` masks only the directive prefix (`:::note[`) as `{{ADM_OPEN_n}}` and the trailing `]` / `{.attr}` remainder as `{{ADM_TCLOSE_n}}`, leaving the inner title text inline so it reaches the model (its own `**`/`_`/`` ` `` markup is handled by the downstream emphasis/inline-code protectors). The new `titleCloseMap` is threaded through `PlaceholderHandler.protectForTranslation`/`restoreAfterTranslation` (`src/processors/placeholder-handler.ts`), the empty-state shell in `src/cli/doc-translate.ts`, and the `ADM_(?:OPEN|END|TCLOSE)_\d+` leak guard in `src/processors/translation-placeholder-leaks.ts`. The legacy space form `:::note Title` continues to translate as before.
- **Added**: extractors/processors — nested admonitions (4+ colon fences, e.g. `:::::info[Parent]` wrapping `::::danger[Child]` wrapping `:::tip[Deep Child]`) are now supported. Openers are generalized from exactly `:::` to `:{3,}`, and the line scanner in `src/extractors/markdown-extractor.ts` tracks a colon-count depth stack so a whole nested block is captured as one translatable segment and round-trips exactly (exact colon counts preserved). A new whole-file scanner (`collectMalformedAdmonitionIssues` in `src/processors/markdown-source-diagnostics.ts`) reports `ADMONITION_UNCLOSED` (opener with no closing fence), `ADMONITION_UNEXPECTED_CLOSE` (stray `:::`), and `ADMONITION_UNTERMINATED_TITLE` (`:::note[Title` with no `]`), skipping fenced code and YAML front matter. ## [1.7.2] - 2026-06-22

- **Added**: cli/i18n — when the tool's UI language is explicitly requested via `-L, --ui-lang`, the `AI_I18N_LANG` environment variable, or config `uiLanguage` but no shipped bundle matches (the resolver falls back to the source locale), the CLI now prints a one-time yellow warning that the default locale will be used (`initUiI18nFromEnvironment` in `src/i18n/index.ts`). The warning is intentionally not routed through `t()` (it always renders in the default/source language, since the requested locale is unavailable). A locale inferred only from the host OS never triggers a warning, and the warning is de-duplicated per requested value so the startup + post-config resolution passes do not warn twice.
- **Added**: extractors — HTML `data-i18n*` marker extraction. A new `src/extractors/html-i18n-marks.ts` scanner lets `extract` capture UI strings from `.html` / `.htm` sources (when listed in `ui.uiExtractor.extensions`) via `data-i18n` (element `textContent`), `data-i18n-title`, and `data-i18n-placeholder` attributes. Bare markers take the source text from the element itself (no duplication); valued markers (`data-i18n="Key"`) set an explicit key for mixed content. `data-i18n-ignore` skips an element and its subtree. The shared `normalizeI18nText` helper keeps build-time keys identical to the browser runtime. Exposed from the public API (`collectHtmlI18nStrings`, `collectHtmlI18nLocations`, `markHtmlContent`, `normalizeI18nText`, …).
- **Added**: cli — new `mark-html [paths...]` command that auto-inserts bare `data-i18n` / `data-i18n-title` / `data-i18n-placeholder` markers into HTML (`src/cli/mark-html.ts`). Dry run by default (reports per-file add counts and mixed-content elements needing a manual `<span data-i18n>`); `--write` applies changes via atomic writes. Idempotent, honours `data-i18n-ignore`, never marks code-like elements (`code`, `pre`, `kbd`, `samp`, `var`) or empty / numeric-only text, and never emits a valued marker. Does not call an LLM.
- **Added**: config — optional `ui.uiExtractor.htmlI18nAttributes` (`src/core/types.ts`) to customize the scanned HTML marker attributes (defaults to `["data-i18n", "data-i18n-title", "data-i18n-placeholder"]`; `data-i18n-<attr>` maps to that attribute's value).

- **Fixed**: cli/docs — interrupting a document-translation run (`Ctrl-C`) no longer reports `Total tokens used: 0` / `Total cost: $0.0000 (all segments from cache)` after batches had already succeeded. - **Fixed**: api/llm-client — tokens and cost spent on billed-but-discarded LLM responses are no longer dropped from run totals.
